# One-click hosted sandbox Nodes

Console exposes the action on Settings / Devices / Add device. Authenticated
GET and POST requests to `/api/v1/sandbox` are forwarded by the browser ingress.
The endpoint returns 404 outside the pilot, a null sandbox before creation, and
the sandbox status and exact Node ID when available. POST has no caller-supplied
parameters. It queues one environment per user and retries or resumes the same
environment when appropriate.

The Node queue stores its lease and status in `sandbox_node_state` through
`db/hosting.sql`. The dedicated row and transaction keep Starter accounting
independent and persist the first-boot registration token atomically with its
allocation. The existing worker claim, heartbeat, and completion routes select
the Node queue only for the `node_only` job kind and a dedicated bearer. A
completion must report an owned Node ID. The Node image starts paxd and
registers through the existing Node API. Agent selection happens after pairing.

## Pilot configuration

Set all of these on the intended regional Manager:

| Variable | Value |
| --- | --- |
| `HOSTING_SANDBOX_HOST_ID` | One exact AWS worker ID |
| `HOSTING_SANDBOX_HOST_KEY` | Distinct private random worker bearer |
| `HOSTING_SANDBOX_CLOUD_URL` | The HTTPS origin used by paxd registration and control |
| `HOSTING_SANDBOX_OWNERS` | Comma-separated canonical user IDs admitted to the pilot |

Apply the additive schema using the standard Manager deployment sequence
before enabling the pilot. Deploy the browser ingress and Manager before the
Console action is enabled for the pilot account. Set the AWS worker's
`kind` to `node_only`, pin the Manager and paxd origins, and store the dedicated
bearer in its protected host credential file. The existing sandbox image
supports `--quick-connect` without a model credential. The current AWS pilot
is configured for one running sandbox.

The Starter flow and the existing free model quota remain separate from
Node creation. A known Node is reused when the environment resumes. Recover
an uncertain registration on the original disk before issuing a new identity.

## Checks

API declarations live in `api/pax_manager.thrift`. Regenerate Hertz and OpenAPI
artifacts with `GOWORK=off make generate` from this worktree with Go 1.26.

The Manager tests cover user and host admission, idempotent queueing, registration
token consumption, ownership, and lease expiry. The region-directory tests cover
the exact browser allowlist and security boundaries. The Console and pax-host
changes have separate test suites. A live pilot also needs a signed-in account,
the regional Manager ingress and the AWS worker enabled with matching settings.
