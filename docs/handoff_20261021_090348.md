# Notification reply previews and Console click recovery

## Result

The owner confirmed that automatic standard-turn notifications arrive, then
requested reply previews and a working session link. Manager now snapshots a
bounded preview of the latest visible assistant reply in the completed turn.
The companion Console displays that body and recovers failed window reuse.

## Boundaries and flow

- `storage/notification_preview.go` selects only the same owner, node, agent,
  canonical session, business turn, ACP source and assistant direction. It
  accepts `agent_message_chunk` and `message_delta`, excludes thought/tool/user
  text, and fences rows before the terminal session sequence.
- PostgreSQL reads at most 1024 characters from part zero of the latest reply.
  Memory storage applies the equivalent projection. The ACP terminal projection
  already flushes pending text before the atomic terminal/outbox transaction.
- `notifications.BuildTurnNotification` normalizes whitespace/control characters
  and limits the body to 200 Unicode code points, including a truncation marker.
  Empty reply text retains the generic body. Identity, TTL, deduplication,
  receiver authorization, leases and retries retain their existing contracts.
- The snapshot remains in the existing delivery payload. No schema, Thrift,
  generated API, regional gateway, VAPID or Android package change is needed.
  Administrator subscription metadata does not expose reply payloads.
- Console keeps the constant app title and validates destinations. Clicks prefer
  an exact top-level session window, focus before navigation, and fall back to
  opening the validated URL if lookup/focus/navigation fails or returns no client.
  Links use the canonical Home route `/?session_id={encoded_id}`. Home resolves
  node/agent context and applies ordinary session auth. The worker converts old
  `/sessions/{id}` links to the same Home route, including clicks on previously
  displayed notifications after the worker updates.
