# Hosted domain migration

## Change

The four repositories now use these company-hosted defaults:

- Console and browser verification: `https://paxworkspace.net`.
- Browser API, direct browser WebSocket, public downloads and release publication:
  `https://api.paxworkspace.net` / `wss://api.paxworkspace.net`.
- paxd machine connection: `https://wsapi.paxworkspace.net`.

paxl login and artifact resolver defaults, paxd configuration and update resolver,
Console proxy/tunnel/connect/auth helper defaults, and Manager pairing verification
URLs were updated in their existing modules. Environment and command-line
endpoint overrides remain supported. The hosted wsapi-to-api download resolver
mapping now recognizes the new hostname while preserving custom ports and paths.

Install/release scripts, configuration examples, tests and operating documentation
were updated together. No generated Manager artifacts changed; regeneration is
not required. Android package IDs and launchd service identifiers are unchanged.

The Access review checklist now records the company PAX Machine API application
and policy, with machine scopes only on wsapi. This repository edit does not
apply Cloudflare changes or alter old-account resources. Historical audit records
are explicitly distinguished from new-domain verification.

## Validation

- Console: six affected Vitest files, 57 tests passed using installed Node 24.
- paxl: facade tests and hosted-domain shell checks passed.
- paxd: config, updater, cmd/paxd and cmd/paxctl tests passed, including the
  final wsapi machine default. Release-script checks also passed.
- Manager: `make fmt-check`, both `make lint` passes (including integration
  build tags), `go test -count=1 ./...` and the cmd/manager build passed.
  HTTP tests were run outside the sandbox because local listeners are blocked
  inside it.
- Shell syntax and Git whitespace checks passed.

## Deployment

Rebuild and deploy Console and Manager, and publish updated paxl/paxd releases
and installers through the existing release workflow. Existing saved remote URLs
and deployed environment overrides are not rewritten by changing source defaults.
Keep Node Keys, remote authentication and Cloudflare credentials unchanged.
Public download paths require their own existing non-interactive delivery setup;
the machine Access scopes do not grant access to public artifact paths.

No production deployment, credential rotation or Cloudflare policy change was
performed by this source migration. No tracked issue status changed.
