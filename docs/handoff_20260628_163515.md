# Handoff 20260628 163515: Team Agent Identity Profiles

## Summary

Team agents now carry optional team-scoped profile fields for future task routing:

- `identity`
- `role`
- `display_name`
- `description`
- `metadata`

The change is backward compatible. Existing `POST /api/v1/user/:user_id/teams/:team_id/agents`
requests that only send `agent_id` still work. When no identity or role is
provided, responses default to `identity = agent_id` and `role = general`.

`identity` is intentionally not unique. Multiple active team agents may share
the same identity. Future routing should treat identity as a label and either
apply a selection policy or introduce a separate unique routing key if a single
target is required.

## Module Boundaries

- `internal/manager/domain/team.go` owns the team agent profile fields and
  request shape.
- `internal/manager/userapi/team.go` validates and normalizes user-provided
  profile fields.
- `internal/manager/storage/team.go` and
  `internal/manager/storage/memory_team.go` persist and return profile fields.
- `db/init.sql` owns the schema additions and non-unique lookup indexes.
- Generated mocks were refreshed with `make mocks`.

## Data Flow

1. Owner or operator calls `POST /api/v1/user/:user_id/teams/:team_id/agents`.
2. The request must include `agent_id`; profile fields are optional.
3. User API normalizes:
   - blank `identity` to the agent id
   - blank `role` to `general`
   - `identity` and `role` to lowercase token values
4. Storage verifies the requester can add only their own agent.
5. Storage inserts or reactivates the `team_agents` row with the profile fields.
6. `GET /api/v1/user/:user_id/teams/:team_id/agents` returns the profile fields.

## Schema

`team_agents` now has:

- `identity TEXT NOT NULL DEFAULT ''`
- `role TEXT NOT NULL DEFAULT 'general'`
- `display_name TEXT NOT NULL DEFAULT ''`
- `description TEXT NOT NULL DEFAULT ''`
- `metadata JSONB NOT NULL DEFAULT '{}'::jsonb`

Indexes:

- `idx_team_agents_identity_active` on `(team_id, identity)` where active
- `idx_team_agents_role_active` on `(team_id, role)` where active

Both indexes are non-unique.

## Known Risks

- Team endpoints are custom manager routes, not generated Thrift routes. No
  `make generate` update is expected for this change.
- Identity is a non-unique label. Do not route assuming a single agent match.
- Existing clients can ignore the new response fields.
