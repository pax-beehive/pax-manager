# Team Memex Read Surface Handoff

## Summary

This change starts the LLM Wiki / team memex module with a read-only surface.
Team members can read the active memex index, list active documents, and fetch an
active document by path. Archived documents are stored but hidden from ordinary
read paths. There is no LLM run path, write path, scheduler, or paxl/user-agent
retrieval path in this slice.

## Module Boundaries

- `internal/manager/domain` owns the `TeamMemexDocument` domain shape and store
  interface methods.
- `internal/manager/storage` owns SQL and in-memory persistence for active
  document reads.
- `internal/manager/userapi` owns request authorization, path normalization, and
  markdown index rendering.
- `internal/manager` owns the hand-written Hertz route bindings.
- `db/init.sql` owns the initial `team_memex_documents` table shape.

## Request Flow

1. A user calls a team memex endpoint under `/api/v1/user/:user_id/teams/:team_id`.
2. `userapi.Service` resolves the authenticated principal.
3. The storage layer confirms the principal is an active member of an active
   team.
4. The storage layer returns only documents with `status = active`.
5. User-facing document responses include `path`, `title`, `summary`, `tags`,
   `body_md`, and `updated_at` only. Session/message source references and
   internal document metadata are not exposed by these read APIs.

## Endpoints

- `GET /api/v1/user/:user_id/teams/:team_id/memex/index`
  - Response: `{ "index": "<markdown>" }`
- `GET /api/v1/user/:user_id/teams/:team_id/memex/documents`
  - Response: `{ "documents": [...] }`
- `GET /api/v1/user/:user_id/teams/:team_id/memex/documents/*document_path`
  - Response: `{ "document": {...} }`

## Storage

`team_memex_documents` stores:

- `document_id`
- `team_id`
- `path`
- `title`
- `summary`
- `tags_json`
- `body_md`
- `status`
- `created_at`
- `updated_at`
- `archived_at`

The `(team_id, path)` key remains unique, including archived documents, so an
archived path stays reserved.

## Risks And Notes

- These routes are hand-written and not yet represented in the generated
  OpenAPI/Thrift surface.
- There is no migration runner beyond `db/init.sql` in this change.
- Search/query semantics are intentionally not implemented yet.
