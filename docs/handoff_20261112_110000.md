# Node-scoped ordinary workspace search

## Change and boundaries

Issue 083 is resolved in the current node API. Ordinary agents can search their
owner's sessions across agents on the calling node during an active
Manager-registered turn. Cross-node scope requires a matching expansion grant.
Secretary's capability and user-facing owner search permissions are unchanged.

`domain/workspace_access.go` normalizes node/agent/session dimensions and tests
grant containment. `workspace_access.go` resolves caller aliases, validates
owned identifiers, selects the default or approved path, and rechecks access
before returning results. Request lifecycle remains in the existing workspace
request/lifecycle modules. Queue JSONB carries the added node_ids dimension.

Search domain types, ES queries and group cursors carry node IDs. Storage
derives source node attribution; userapi checks current source records before
releasing hits. Session/message attribution follows historical source metadata,
never the agent's current node. Summary attribution requires unanimous leaves
and compatible live primary-session metadata. Unknown, conflicting or mixed-node
sources have no node attribution and cannot match a narrow node filter.

## API flow

Default ordinary MCP request:

```json
{"query":"cicd","scope":{"node_ids":["self"],"agent_ids":["*"],"session_ids":["*"]}}
```

node_ids.self resolves to the authenticated calling node; agent_ids.self still
means the calling agent. Concrete nodes must belong to the same owner. Explicit
session IDs must fit both declared dimensions. Agent and node filters intersect,
allowing moved agents' historical sessions on their original source node.

workspace_request_access and prompt search_access accept optional node_ids.
Missing node_ids in legacy requests/grants means ["*"], preserving all-node
semantics. Legacy ordinary searches therefore need approval until helpers are
upgraded to explicitly send the self-node filter. New MCP schemas require all
three search dimensions. No layer silently narrows an all-node request.

Request deadlines, nonblocking status polling, cancellation, auto approve and
turn-end expiry are unchanged. A narrow expansion grant does not reduce the
same-node default permission.

## Schema and rollout

No Thrift or generated HTTP transport artifacts changed; workspace tool and
search_access data use the existing JSON envelopes. The standard regeneration
command remains `make generate` if the IDL changes later.

EnsureSchema runs db/search.sql, adds search_sync_state.projection_version and
sets new rows to version 2. Legacy rows begin at version 1. Backfill upgrades
their projection marker and desired revision to force an ES rewrite despite
external-version indexing. Active leases remain intact.

ES index setup adds the node_id keyword mapping to both new and existing
indices. Stop all old search workers before starting the first upgraded Manager
worker and its backfill. Complete backfill before relying on complete narrow-node results. Old workers cannot populate
node_id and can overwrite projections if retained during rollout. Unknown or
stale attribution cannot widen access because fresh source checks apply, but
results may be incomplete until indexing finishes. Then deploy paxd and Console;
existing MCP helpers need their usual reload/restart to expose the new schema.

If old and upgraded workers were mixed, retire old workers and force another
revision refresh with the existing bounded tool:

```bash
python3 tools/backfill_search_groups.py --batch-size 500 --max-pages 10000
```

Use the normal libpq connection configuration. Continue from the reported
after-kind/after-source-id cursor if the page limit is reached; completion
reports `queued: 0`. This tool increases revisions independently of the
projection marker and preserves leases. Clearing indexed_revision alone cannot
rebuild documents because ES rejects equal external revisions.

Use the existing machine route allowlist and Manager affinity from
turn_search_access.md. No live deployment or merge was performed for this task.
