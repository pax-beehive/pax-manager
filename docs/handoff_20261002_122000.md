# KEV-75: Worker-owned regional provisioning

## Delivered code

Branch: `feat/kev-75-regional-directory`, based on `565b3a8`.
Local issue 034 is partial; production activation remains outstanding.

- `workers/region-directory`: Access JWT verification, immutable D1 assignments,
  Sessions/bookmarks, primary confirmation of replica misses, 10-second signed
  bootstrap state, regional provisioning orchestration and private import tooling.
- `internal/manager/auth`: verifies short-lived, region-specific HMAC assertions;
  regional authentication and static registration-owner lookup cannot create users.
- `internal/manager/storage`: memory and SQL idempotent provisioning preserve the
  global ID; mismatched identity/ID pairs return conflict without mutation.
- `internal/manager/regional_user.go`: HTTP adapter delegates authentication and
  storage, applying the Manager's own admin policy. No role comes from the Worker.
- `config`: opt-in `PAX_REGION` plus `REGION_PROVISIONING_SECRET`; partial
  configuration fails startup. Legacy mode is unchanged by default.

D1 commits the winner first. The Worker then calls the chosen Manager's
`POST /internal/users/ensure`. Provision failure preserves the D1 assignment;
retry cannot switch regions. Only a successful provision enables the 10-second
cookie shortcut. Subsequent D1 reads carry a signed bookmark rather than relying
on time alone for replica freshness. There is no distributed transaction,
automatic migration, global PostgreSQL replication or regional credential redesign.

The public API is `POST /api/v1/region/bootstrap`. Full request/response, HMAC
byte-level contract, import commands and coordinated rollout are documented in
`workers/region-directory/README.md`.
