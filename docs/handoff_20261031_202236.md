# Rolling Secretary summaries and optional source lookup

## Scope

Automatic Secretary now maintains one current rolling summary per owned source
session, with immutable revisions in the existing summary tables. Manager
supplies the current summary, raw message delta and existing session metadata.
The selected agent decides whether to search for related sessions and which
original sources to read. Board maintenance, topic/project/direction inference,
embedding and model calls during search remain outside this change.

No Console change is required: the existing Secretary selection, enable switch,
Run/Retry and progress page drive this worker. The local experimental pipeline
remains stopped. No production service was deployed during implementation.

## Boundaries and flow

1. Source/message-part writes mark durable source jobs. Canonical message IDs and
   full visible-text hashes detect older edits and late parts.
2. Storage loads a bounded delta and the stable rolling head. Existing raw
   metadata includes title, primary project ID, cwd and workspace roots. No
   semantic related-session query runs in PG.
3. The prompt contains current title/body/claims, new or changed raw messages and
   removed IDs. Unchanged coverage is carried server-side rather than replaying
   all historical text or refs to the model.
4. The normal ACP execution injects the existing paxd conversation MCP child with
   an ephemeral capability. Updated paxd exposes only four read-only tools:
   workspace_search, workspace_read, workspace_expand and workspace_history.
5. The new node route authenticates both the stored node key and the execution
   capability, rechecking current owner, selected agent, settings and job lease
   before and after reads. History reuses the frontend history service, trims
   its complete-turn expansion back to the bounded base page, and canonically
   reads visible messages with signed receipts.
6. The agent returns strict replacement-summary JSON. It can explicitly select
   original-message refs plus read receipts in related_sources. Manager verifies
   the exact exposed text, including during completed-turn recovery. Snippets
   and other summaries do not count as new factual evidence.
7. Publication composes unchanged coverage plus mandatory delta and selected
   related refs, validates quotes and source visibility, freezes source bodies,
   writes a new revision, and advances only the original source's checkpoint in
   one transaction. Related-session reads never advance other checkpoints.

The execution reader selects the last visible assistant message in the target
turn, preserving its ordered parts. Commentary before tool calls is excluded
from the final JSON. Completed execution recovery does not submit another prompt.

## Source/version behavior

The stable ID is derived from owner plus source ID and is independent of retry
generation. Edits replace that message's old coverage ref; unchanged refs keep
their exact versions. A previous rolling revision is not chained as another
factual dependency. Summary versions and referenced bodies remain immutable.

Unreadable baselines, deleted source membership and migration from old fragments
can start a durable reset. The old summary is withheld; safe current messages
are rebuilt in bounded batches. Empty reset work publishes a neutral summary
without a model call. Historical refs continue to enforce current access and
deletion checks. Old fragment identities are retained rather than destructively
rewritten; default generic search can still find their individual latest
versions. The automatic worker uses only the canonical rolling head.

## Limits and operation

- Delta: at most 64 complete messages and 128 KiB raw text; separately at most
  64 removed IDs. No source truncation.
- Prompt state: 64 KiB summary and 16 KiB metadata. Oversize input/output fails
  explicitly without advancing the checkpoint.
- Optional output selections: at most 50 exact original-message refs.
- Read history: default 20, maximum 50 base-page messages, using existing seq
  cursors. Search and read cursors never become processing checkpoints.
- Trusted rolling coverage can exceed the public 512-ref publication limit;
  the existing 4,096-entry dependency budget remains enforced atomically.
- Tool grants are revoked on execution exit or fencing. Normal runtime tool
  approval policy remains unchanged. A paused run cannot reuse an old grant.
- A fresh native session refreshes capability-bearing MCP configuration when
  retrying before a turn started. Started turns are not duplicated.

Deploy Manager with its complete db directory and deploy the matching updated
paxd for automatic workspace tools. No standalone daemon, Python process, model
API key or per-user MCP registration is needed for this execution path. The
manual Python adapter remains available independently. OpenClaw retains its
existing lack of per-session MCP injection; unavailable optional tools fall back
to the supplied summary/delta. ES is needed for search, not source reads or
summary publication.

Keep SEARCH_READ_RECEIPT_SECRET stable across Manager restarts. Old receipts fail
closed after a key change; explicit Retry regenerates reads/output. Changed or
deleted related sources do not proactively schedule the consuming session.
Current access checks still hide unsafe reads; a later own-source update or
explicit Run/Retry can rebuild an unreadable baseline.

Current execution routing assumes one Manager with its local agent connections.
Multiple instances require agent-aware routing separately from database leases.

## Generated artifacts and verification

The new route is declared in api/pax_manager.thrift and the node route manifest.
Use make generate to regenerate handlers, routers, OpenAPI and mocks. The machine
gateway consumes the manifest; it does not need a parallel hand-written route.

The verification commands were:

```bash
GOWORK=off go mod tidy
GOWORK=off make fmt-check
GOWORK=off make lint
GOWORK=off GOCACHE=/tmp/pax-manager-go-cache go test -count=1 ./...
GOWORK=off GOCACHE=/tmp/pax-manager-go-cache go build -o /tmp/pax-manager-build-check ./cmd/manager
PAX_SECRETARY_TEST_PAXD_BINARY=/absolute/path/paxd GOWORK=off make secretary-acceptance
GOWORK=off make search-acceptance
```

The cross-binary Secretary gate uses actual paxd stdio, stored SQLite node
credentials, HTTP node auth, ACP execution, exact related-source publication and
revocation. Its matching paxd binary is explicit; default CI does not download a
sibling repository. The gate rejects skipped required scenarios. Deterministic
fixture responses test protocol and persistence, not production model quality.
