# Whole-turn encrypted replay

## Change and boundaries

Issue 033 is partial: new indexed E2EE turns use bounded whole-turn replay;
unindexed legacy ciphertext remains readable but cannot be divided into turns
by Manager. Ordinary conversation history is unchanged.

`internal/manager/e2ee_transport.go` accepts opaque reliable metadata `turn_ref`.
The storage layer persists it on `agent_events`, with turn/cursor and partial
indexed-event indexes. The domain replay interface is part of E2EETransportStore
so Store wrappers retain the capability. Manager never parses encrypted ACP.
Paxd supplies a reference matching the encrypted batch's turn ID and journals
the original prompt before dispatch. Canonical history projection stays separate.

## HTTP and persistence contract

The existing authorized encrypted-events GET endpoint accepts `view=replay`:

- Initial request: `limit` (default 100, max 500), optional `before_turn`
  (exclusive start cursor of a newer turn).
- Continuation: `turn_ref`, `through_cursor`, `after_cursor`, and `limit`.
  Empty `turn_ref` selects the legacy unindexed bucket.
- Response data: `events` (cursor, created_at, envelope), `turn_ref`,
  `turn_start_cursor`, `head_cursor`, `next_after_cursor`, `has_more`, `has_older`.

The initial request chooses the latest indexed turn before the boundary, or
legacy events if none exists. The head cursor covers the entire committed
session snapshot. The client reads all pages of that turn using the same head,
then starts existing SSE after the head. New frames arriving during replay are
therefore delivered by SSE. Scrolling backwards requests earlier whole turns.
Non-JSON requests keep the existing SSE behavior.

PostgreSQL uses repeatable-read snapshots for selection and paging. Event writes
take a per-session transaction advisory lock before sequence allocation: a later
commit cannot cause a client to skip a lower still-uncommitted session cursor.
Duplicate event IDs must retain their original turn reference and ciphertext.

`db/init.sql` adds the column/indexes idempotently at service startup. Existing
rows default to an empty reference. No ciphertext or old rows are rewritten.
Deploy Manager before paxd and Console. Mixed old/new Manager writers cannot
provide the new per-session commit-order guarantee until all writers upgrade.
Index creation may block event writes briefly on a large existing table; plan
schema rollout accordingly.

## Generated code and development

This is a query variant of the existing manually registered E2EE route, which
has no generated Thrift definition. No generated artifacts change. Existing
generated APIs continue to use `api/pax_manager.thrift` and `make generate`.
Build with `GOWORK=off go build ./cmd/manager`; normal deployment/startup applies
the schema. No deployment or local daemon restart is part of this change.
