# Unlimited monthly token caps

## Behavior and boundaries

Monthly token cap zero means unlimited tokens. Positive caps remain optional.
The default HOSTING_GRANT_TOKENS is now zero. Per-user money grants still default
to USD5/month; the platform pool still defaults to zero/paused. This fixes issue
092 without changing service authentication, execution leases or model policies.

The hosting package applies the sentinel consistently at wake, reservation and
the post-moderation generation check. Accounting still records actual and held
tokens. Neither cancellation nor an operator cap edit resets spent money.
The configuration loader validates the monetary grant as strictly positive and
tokens/pool as nonnegative, distinguishing invalid explicit values from an
unconfigured zero-value Config.

## API and persistence

There are no new fields, schema migrations or generated artifacts. No generator
was run. In Quota, granted_tokens=0 means unlimited and remaining_tokens=0 is a
sentinel, not exhaustion. Clients should inspect granted_tokens. Preserve actual
spent_tokens and reserved_tokens in both modes.

Stored zero token grants take the new meaning after this binary is deployed;
balances and audit history need no rewrite. Existing positive grants remain
limited. Default changes affect new environments and future monthly grants;
apply a per-user zero override to remove an existing current-month token cap
immediately. AccessPaused remains the explicit per-user suspension control.

## Companion UI and rollout

in both token editors while continuing to show dollar balances and usage.
