# Artifact publication turn placement

New artifact cards store the originating tool's sequence in
`raw_json.source_session_seq`, in addition to existing parent message and turn
IDs. Display keys and replacement lists are scoped to that turn. Repeat
registration uses the same deterministic key.

`artifact_publication_reconcile.go` contains the write-path change.
`domain/message_display.go` uses source positions for transcript display without
changing stored sequences or cursor values. Existing invocation anchoring is
preserved. The companion Console branch `fix/artifact-turn-association` uses the
same position when sorting merged pages, so it does not undo backend ordering.

The change applies to new artifact writes and display ordering. Historical-data
migration is outside its scope. Existing publication reconciliation remains in
place; the change adds no history-read repair hooks, storage interfaces, schema
changes or paxd updates.

Deploy Manager before Console through the normal release workflows. Neither
has been deployed during this task.

Validation: backend full Go tests, format/lint checks and manager build;
Console resource/runtime regression tests, TypeScript, ESLint and changed-file
Prettier checks. Remaining changed production statement coverage is 30/30 (100.0%),
with duplicate cross-package coverage blocks merged before counting. The profile
is `/tmp/artifact-turn-manager-simplified-coverage.out`.
Tests retain late registration, tagged replay/idempotence, reused tool IDs,
source-outside-page placement and final artifact/reply/Done ordering. Issue 045
is resolved in source; rollout is pending.
