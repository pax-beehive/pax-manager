# Team Memex Run Harness Handoff

## Summary

This change adds the first manual team memex run harness. It does not call
DeepSeek, select session messages, publish document changes, or run a scheduler.
It creates and returns a dry-run maintenance record with the generated active
document index and the explicit constraints that future hosted LLM executors
must follow.

## Module Boundaries

- `internal/manager/domain` owns run statuses, executor type, constraints, and
  validation report shapes.
- `internal/manager/storage` owns PostgreSQL and in-memory run persistence.
- `internal/manager/userapi` owns manual run creation, run lookup, index
  rendering, and response DTOs.
- `internal/manager` owns the hand-written Hertz route bindings.
- `db/init.sql` owns the `team_memex_runs` table shape.

## Request Flow

1. Owner or operator calls `POST /api/v1/user/:user_id/teams/:team_id/memex/runs`.
2. `userapi.Service` resolves the principal and reads active memex documents.
3. The service creates a dry-run record with:
   - executor type `dry_run`
   - status `succeeded`
   - generated `index_md`
   - default run constraints
   - no session or message references
4. The storage layer enforces owner/operator authorization before persisting.
5. Team members can call `GET /api/v1/user/:user_id/teams/:team_id/memex/runs/:run_id`
   to read the run status and constraints.

## Endpoints

- `POST /api/v1/user/:user_id/teams/:team_id/memex/runs`
  - Creates a dry-run harness record.
- `GET /api/v1/user/:user_id/teams/:team_id/memex/runs/:run_id`
  - Reads a run record for active team members.

## Constraints

Default constraints are returned as structured JSON and persisted with each run:

- max input messages: 200
- max input message chars: 120000
- max docs read per run: 20
- max doc chars read per run: 160000
- max output docs: 20
- max output doc chars each: 64000
- allowed operations: `create_doc`, `update_doc`, `archive_doc`, `no_op`
- index is read-only
- embeddings disabled
- max repair attempts: 2
- initial executor enabled: false

## Validation Report Shape

The run model includes a typed validation report:

```text
retryable
errors[]
constraints
```

This prepares the failure feedback path for the future DeepSeek repair loop,
but this slice does not yet run manifest validation or repair attempts.
