# Team Memex DeepSeek Executor Handoff

## Summary

This change wires the team memex maintenance loop to a hosted DeepSeek executor.
The existing dry-run executor remains the local fallback. Production VM deploys
now read the DeepSeek API key from Google Secret Manager secret
`deepseek_api_key`, inject it as `DEEPSEEK_API_KEY`, and set
`TEAM_MEMEX_EXECUTOR=deepseek`.

## Module Boundaries

- `internal/manager/config` owns DeepSeek and memex executor configuration.
- `internal/manager/userapi/team_memex_deepseek.go` owns the DeepSeek
  OpenAI-compatible chat completion client and prompt assembly.
- `internal/manager/userapi/team_memex.go` owns executor type detection and the
  run/attempt lifecycle.
- `internal/manager/server.go` wires the configured executor into the user API.
- `deploy/vm/deploy.sh` owns runtime Secret Manager access for VM deployment.

## Runtime Configuration

Defaults:

```text
TEAM_MEMEX_EXECUTOR=dry_run
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_TIMEOUT_SECONDS=120
DEEPSEEK_MAX_TOKENS=384000
DEEPSEEK_TEMPERATURE=0.2
```

When `TEAM_MEMEX_EXECUTOR=deepseek`, `DEEPSEEK_API_KEY` is required to build the
executor. If the key is missing or invalid at startup, manager logs a warning
and keeps the dry-run executor so the service remains available.

The VM deployment script runs:

```bash
gcloud secrets versions access latest --secret=deepseek_api_key
```

and injects the result into the container as `DEEPSEEK_API_KEY`.

## DeepSeek Request Flow

1. `CreateTeamMemexRun` resolves the configured executor type.
2. The DeepSeek executor receives `TeamMemexExecutorInput`, including the
   generated index, constraints, attempt number, previous invalid manifest, and
   validation report when repairing.
3. The executor sends a chat completion request to:

```text
POST https://api.deepseek.com/chat/completions
```

4. The request uses JSON mode:

```json
{"type":"json_object"}
```

5. The response content is decoded as `domain.TeamMemexManifest`.
6. Existing validation, repair attempts, run attempt persistence, and document
   publishing remain unchanged.

## Known Risks

- The hosted executor currently gets the generated index and validation repair
  context. Session selection and incremental session summarization are still
  not implemented.
- DeepSeek tool calling is not wired yet, so this slice does not expose
  `SearchDocs` or `ReadDoc` as live model tools.
- Deployment assumes the VM service account can access Secret Manager secret
  `deepseek_api_key`.
