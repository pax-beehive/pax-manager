# Handoff: Durable E2EE Command and Event Transport

## Summary

This change adds the Manager portion of a staged Browser-to-paxd end-to-end
encrypted transport. The existing paxd WebSocket and reliable sequence/ACK
journal remain the real-time hop. PostgreSQL is the durable source of truth for
encrypted commands, encrypted events, event cursors, and agent connection
fencing. LISTEN/NOTIFY is only a low-latency wake-up mechanism.

The Manager never receives an E2EE root key and never decrypts ACP payloads. It
stores and routes a small authenticated metadata envelope plus opaque nonce and
ciphertext bytes.

## Module boundaries

- `internal/manager/domain/e2ee_transport.go` defines opaque command/event
  records and the storage contract.
- `internal/manager/storage/e2ee_transport.go` owns in-memory and PostgreSQL
  persistence, idempotency checks, notification transactions, cursor reads, and
  connection-epoch fencing.
- `internal/manager/e2ee_transport.go` owns authenticated browser HTTP/SSE
  endpoints and the encrypted frame bridge on the existing agent tunnel.
- `internal/manager/e2ee_listener.go` owns the two fixed PostgreSQL LISTEN
  channels and reconnect behavior.
- `internal/manager/acp_tunnel.go` remains the owner of live WebSocket and
  reliable transport state. It now registers a database connection epoch and
  starts a periodic/wake-driven encrypted command drain.

Do not move cryptographic key handling or payload decryption into this
repository.

## Browser API

Authenticated user routes:

```text
POST /api/v1/user/{userID}/agents/{agentID}/sessions/{sessionID}/encrypted-commands
GET  /api/v1/user/{userID}/agents/{agentID}/sessions/{sessionID}/encrypted-events
```

The POST accepts one version-1 opaque envelope and returns `202 Accepted` with
the command ID, idempotent creation result, and delivery status. Reusing a
command ID with different metadata or ciphertext returns a conflict.

The GET is an SSE stream. It resumes from `Last-Event-ID` or `after_cursor`,
queries in ascending batches of 100, immediately continues when a batch is
full, and rechecks PostgreSQL on every wake-up and 15-second heartbeat.

## PostgreSQL data model

`db/init.sql` adds:

- `agent_connection_epochs`: one monotonically increasing fencing token per
  agent.
- `agent_commands`: globally unique business command ID, opaque envelope,
  delivery/acknowledgement state, and the epoch used for both state changes.
- `agent_events`: monotonic cursor, paxd-generated local ID, opaque envelope,
  and `UNIQUE(agent_id, local_id)` for upload deduplication.

The command insert and `pg_notify('pax_agent_commands', agent_id)` run in one
transaction. The event insert and `pg_notify('pax_agent_events', session_id)`
also run in one transaction, and duplicates do not notify.

All Manager instances LISTEN on the fixed `pax_agent_commands` and
`pax_agent_events` channels. A listener reconnect wakes all local agent senders
and SSE waiters because notifications may have been missed while disconnected.
Periodic database drains preserve correctness if NOTIFY is unavailable.

## WebSocket behavior

Connection establishment atomically increments the agent connection epoch.
Encrypted command frames include the epoch and stable command ID in reliable
transport metadata. A command is acknowledged in PostgreSQL only after paxd
returns an explicit business ACK for the current epoch. An unacknowledged
command is resent on a new connection epoch even if a previous Manager marked
it delivered.

paxd encrypted events retain their stable local ID across reliable transport
replay. The Manager inserts an event only from the current fenced connection.
Old connection ACKs and events are ignored and cannot update current state.

Reliable transport sequence numbers remain transport identifiers. They are not
used as command IDs, event local IDs, or SSE cursors.

## Envelope limits

The Manager validates protocol/cipher version 1, positive key epoch, a 12-byte
nonce, ciphertext including at least a GCM tag, ciphertext up to 1 MiB, and
bounded non-empty routing identifiers. The Manager does not verify the GCM tag;
the Browser and paxd authenticate route metadata as AES-GCM AAD.

## Staged rollout boundary

This change does not replace the existing Manager-owned `/conversation`
runtime. That path still projects plaintext history, approvals, runtime state,
and native session identity. The encrypted transport is the durable foundation
for a later workbench cutover after those orchestration responsibilities move
to paxd. Both paths can coexist during migration, but a single session must not
mix their ownership models.

## Verification

Focused unit tests cover:

- command lifecycle, current-epoch fencing, and conflicting idempotency keys;
- event local-ID deduplication and cursor ordering;
- authenticated opaque command creation;
- `Last-Event-ID` SSE replay;
- nonblocking coalesced wake-ups.

Run the repository checks before merge:

```bash
make fmt-check
make lint
GOCACHE=/private/tmp/pax-manager-go-cache go test -count=1 ./...
GOCACHE=/private/tmp/pax-manager-go-cache go build -o /private/tmp/pax-manager-build-check ./cmd/manager
```

At handoff time, the E2EE Manager/storage tests and manager build pass. The new
files pass gofmt, goimports, golines, errcheck, and gocyclo. Repository-wide
`make fmt-check` / `make lint` remain red on pre-existing unrelated files:

- `internal/manager/storage/message_history_test.go` needs goimports.
- Existing runtime snapshot and daemon lifecycle functions exceed the current
  gocyclo limit.

The sandboxed full test command also cannot run old `httptest.NewServer` cases
because local port binding is denied. No E2EE-focused test requires a listener,
and all focused tests pass in the sandbox.
