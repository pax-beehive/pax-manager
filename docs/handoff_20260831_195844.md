# Empty ACP Session Initialization Handoff

## Summary

KEV-47 extends the existing user conversation endpoint with an optional
`initialize_only` request flag. It creates and durably binds a native ACP
session without sending an initial prompt or creating a turn.

## Module Boundaries

- `internal/manager/conversation.go` owns request validation and the
  initialize-only branch.
- The existing ACP frame pipeline continues to observe permission options from
  the successful `session/new` response.
- The existing conversation session creation path owns native ID binding,
  permission choice validation/application, durable persistence, and rollback.
- No generated HTTP model or Thrift API changes are required because the
  conversation endpoint uses its local JSON request type.

## Request and Response

```http
POST /api/v1/user/{user_id}/nodes/{node_id}/agents/{agent_id}/conversation
Accept: text/event-stream
Content-Type: application/json
```

```json
{
  "initialize_only": true,
  "cwd": "~/project",
  "approval_mode": "manual",
  "permission_choice_id": "agent:legacy-mode:default",
  "primary_project_id": "proj_x",
  "project_target_id": "target_x"
}
```

The request must not include `session_id`, prompt input/content, or resume. On
success the endpoint emits the existing `session` envelope followed by `done`
without a turn ID. It does not call `session/prompt`.

## Core Flow

```text
authorize and validate
  -> resolve workspace and Project context
  -> allocate Manager session ID
  -> claim ACP tunnel
  -> session/new
  -> observe live permission catalog
  -> optionally apply session/set_config_option or session/set_mode
  -> persist native-backed session
  -> SSE session
  -> SSE done
```

Failures before durable completion retain the existing provisional session
rollback, including best-effort `session/close`.

## Risks and Follow-up

- E2EE empty initialization is intentionally out of scope.
- Available commands can arrive asynchronously after `session/new`; durable
  session capability projection and command UI remain follow-up work.
- Native permission editing after session creation remains separate scope.
- The Console must keep this as a secondary Advanced action and preserve an
  unsent draft across the New-session to assigned-session key transition.
