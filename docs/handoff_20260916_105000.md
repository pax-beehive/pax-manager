# Turn-scoped observer contract

## Summary and boundaries

Issue 023 is resolved in local code. The user observer now streams a durable
turn projection rather than mixing session history with raw ACP deltas.

- session_observer.go owns HTTP validation and SSE framing.
- domain.TurnTranscriptStore is a narrow read interface, forwarded through
  canonicalSessionStore. MemoryStore and PostgresStore scope by agent, canonical
  session/native aliases, and business turn ID before reading message parts.
- Tool rows use the concurrent issue 022 summary implementation; heavy tool
  input/output remains behind the detail API. These changes already existed in the workspace and are included in this
  combined merge with user authorization.
- Console session-observer.ts stages versions by message_id; head commits a
  complete replacement of the target turn in reconcile-session-timeline.ts.

## Wire contract

GET events optionally accepts turn_id. Without it, select the active turn;
otherwise return no_running_turn without replay. Explicit turns must belong to
the authorized session. Reconnect always supplies the pinned turn_id.

after_seq (or Last-Event-ID if the query is absent) is a nonnegative committed
head watermark. Nonzero unscoped cursors are invalid. A cursor beyond the target
turn head is a conflict. after_message_id is explicitly unsupported.

Each connection sends turn_start, the complete turn as history_item messages,
and head. Existing messages can grow without changing SessionSeq, so the cursor
does not skip the mutable prefix. Live history_item replaces message versions;
history_remove removes superseded display rows. Only head carries an SSE id.
turn_done is emitted after the durable completion marker is included in a batch.
resync reconnects to the same turn; it never widens to session replay.

## Operations and limitations

No schema change, production deployment, restart, or data repair was performed.
Deploy Console and Manager together. Old Console sends a rejected parameter;
old Manager does not implement snapshot boundaries. Existing history rows with
incorrect turn IDs remain a separate data/projection issue.

The server checks the target durable turn every 500 ms, hashes message versions,
and sends changed items. Cost grows with the current turn and observer count;
this has not been production load-tested. Delivery includes persistence latency
plus up to one check interval. There is no browser history recovery poll. The
implementation depends on durable turn_done, does not infer completion from an
idle status, and reconnects after the existing idle timeout if the marker is
missing. Future write notifications can replace the periodic reads without
changing the wire contract. Encrypted transport remains separate.
