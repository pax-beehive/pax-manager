# Secretary connection retry backoff

## Change and boundaries

Secretary retries a confirmed pre-dispatch tunnel failure with durable exponential
backoff. The Manager classifies only structured missing/busy tunnel errors returned
while claiming the runner, before session creation or ACP prompt dispatch. Other
transport failures retain the existing unknown-execution recovery behavior.

Nominal delays are 5, 10, 20, 40, 80, 160, 300, and 300 seconds. Each delay has stable
attempt-derived jitter of up to 20 percent, capped at 300 seconds. Eight automatic
retries follow the first failure; the ninth failure pauses the source. Manual
Retry run creates a fresh retry epoch. Restarting, adding turns, or replacing an
invalidated fixed input does not reset the connection budget.

## Persistence and execution flow

- Domain owns the retry policy and the not-dispatched/deferred error markers.
- The ACP service marks only failures before obtaining a runner as not dispatched.
- Storage atomically marks the attempt failed/not-dispatched, increments the batch
  connection counter, stores its retry deadline, updates the job deadline, and
  releases the lease. No worker sleeps while retaining a lease.
- Claim, Prepare, and Begin enforce the durable deadline and exhausted budget.
  Source triggers cannot make a connection retry immediately eligible.
- Three output-validation attempts remain available independently of connection
  failures. Persisted output and uncertain executions cannot become fresh retries.
- Source invalidation carries the connection budget to the next automatic epoch;
  explicit manual retry leaves an epoch gap and resets the budget.
- User API and Console distinguish connection backoff from retry exhaustion using
  fixed safe reasons. They never display raw transport errors.

The schema adds `secretary_batches.connection_failures`,
`secretary_batches.retry_after`, and `secretary_attempts.not_dispatched` through the
existing idempotent bootstrap. No Thrift, generated code, paxd protocol, summary
format, checkpoint, or search-index change is required.

## Existing stuck attempts

Backfill narrowly repairs legacy unknown attempts only when their exact stored
error is the known missing-tunnel failure, output is empty, settings/owner/agent
and retry epoch remain current, there is no active lease, and neither a native
session nor any message exists for the derived execution session. The attempt is
then recorded as the first connection failure and scheduled through the same retry
policy. This is idempotent; any ambiguous or already-dispatched execution stays
unknown. Existing summaries, revisions, coverage, and checkpoints are retained.

This change does not change source completion proofs, restart agent providers, or
re-run all summaries. It does not recover other source-incomplete jobs by guessing
that an idle session has finished.

## Deployment

Deploy Manager first, then the companion Console change. Existing Manager startup
applies the additive schema and the narrow legacy repair automatically. No ES
rebuild or model backfill is required. Operators may explicitly use Retry run
after connection retries are exhausted.

## Verification

Tests use isolated local PostgreSQL and local ACP/HTTP fixtures; production state
is not mutated during verification. Final verification results are recorded in
the pull request.

The full PostgreSQL acceptance package exceeded its previous 180-second test
budget after adding the retry/repair scenarios. The acceptance script now allows
300 seconds per test package. This changes only the test harness limit, not any
production task timeout or retry delay.

```sh
GOWORK=off make fmt-check
GOWORK=off make lint
GOWORK=off GOCACHE=/tmp/pax-manager-go-cache go test -count=1 ./...
GOWORK=off GOCACHE=/tmp/pax-manager-go-cache go build -o /tmp/pax-manager-build-check ./cmd/manager
PAX_SECRETARY_TEST_PAXD_BINARY=/tmp/pax-summary-nodes-daemon GOWORK=off make secretary-acceptance
```

Regression tests cover durable deadlines, lease release, restart and new-input
gates, exhaustion, explicit retry, automatic input replacement, separate validation
budgets, saved output, ambiguous dispatch, rollback, legacy repair exclusions, and
safe API/UI states. The previously documented obsolete Hermes integration fixture
remains tracked separately in issue 068.
