## Integration boundaries

The new `internal/manager/hosting` package owns monthly user allowances and the
operator pool, host leases, model policies, reservations, settlement, and
sanitized administrator audit data. Manager handlers resolve the existing
user/admin principal or the distinct host/gateway capability before delegating.
Model execution remains in the independent gateway. The retired Manager model
proxy returns 410.

Conflict resolution preserved all existing search, notification, runtime-config,
and Secretary setup. `EnsureSchema` retains every existing schema source and
appends the additive `db/hosting.sql`. The existing Dockerfile copies the
entire `db` directory, so the table DDL is included without a packaging change.
PostgreSQL serializes hosting transactions through the singleton JSONB row;
memory storage uses a separate hosting mutex.

The IDL adds ten methods across eight paths. Regeneration uses the current
image source's existing Hertz template and generator configuration. Existing
93 OpenAPI paths, 228 schemas, and 565 generated Go structs remain unchanged.
Worker source is unchanged. The new administrator route already falls under
its existing user route allowance; the trusted accounting route is not
browser-allowlisted. A later free-Starter rollout must separately expose its
status and wake paths through the browser Worker.

## Portal-only operation

`GET` and `PATCH /api/v1/user/self/hosting-admin` use the server-resolved
administrator principal and the persistent hosting store. They work without
hosting credentials, a Lambda deployment, model-provider keys, or an enabled
model. The default monthly pool remains zero. Missing hosting credentials keep
free execution disabled even if an administrator edits allowance defaults.

The regression
`TestHostingAdminDisabledConfigurationCoexistsWithRuntimeConfig` covers the
disabled snapshot, allowance update, restart over the same store, independent
config-center update/read, ordinary-user rejection on both admin APIs, and
disabled Starter wake. Production authentication defaults are unchanged.

## Release limits

The Console page, sandbox host, and gateway images are separate release units.
This portal-only candidate does not require or publish a Worker release. Before a
production rollout, verify the exact immutable source, preserve the existing
deployment configuration, back up the actual database, and commission the
additive table. Then verify real administrator reads/writes, persistence,
ordinary-user 403 responses, and audit records with the shared pool still zero.
Paid model activation requires its own gateway and provider configuration.
