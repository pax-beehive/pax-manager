# Persistent administrator model registration

## Source and contract

This isolated change starts from current Manager main
`5d533099ea1930175f2feec5e73a5eeddfb3ae2d` (PR 257). The worktree is
`work/model-gateway-model-create-manager-20261116`, branch
`feat/model-gateway-model-create-20261116`. Existing worktrees and production
state are untouched.

The existing administrator endpoint accepts a new action:

```json
{
  "revision": 0,
  "action": "model_create",
  "target_id": "trial/frontier",
  "provider": "openrouter",
  "upstream_model": "vendor/frontier-model",
  "moderation": "openai",
  "max_output_tokens": 4096,
  "input_microusd_per_million": 1000000,
  "output_microusd_per_million": 5000000,
  "enabled": false
}
```

The provider must be exactly `openrouter`, `openai`, or `anthropic`. Alias and
upstream identifiers retain the model-policy ASCII format and limits (128 and
256 characters); URL scheme strings are rejected. The concrete
`provider/upstream_model` route is limited to 256 characters and cannot contain
empty, dot, or parent-directory path segments. Moderation, output cap, and
both integer prices are required. Output cap is 1 through 8192, prices are 0
through 1000000000000 microusd per million tokens. The server assigns the
policy version. Creation always disables the new model; `enabled: true` is
rejected. Credentials, URLs, routes, and caller policy versions are not input
fields. The existing authenticated administrator principal and strict JSON
decoder are retained.

Duplicate aliases or provider/upstream identities return HTTP 409
`hosting_model_conflict`; stale global
revisions retain HTTP 409 `hosting_admin_revision_conflict`. Invalid input
returns HTTP 400 `invalid_hosting_admin_update`. Creation preserves all pool,
user allowance, spending, reservation, and runtime-enable settings.

## Storage and runtime flow

New identities are serialized under `admin.created_models` in the existing
`hosting_state` JSONB document. No DDL or additional credential store is needed.
Missing maps initialize empty for older documents. Existing seeded policy
overrides stay in `admin.models` with their original base-policy fencing.
The combined configured and created catalog is bounded to 128 at creation.

Administrator snapshots include created models and their `model_bases`. The
existing `action: model` controls enablement, moderation, cap and prices after
creation, while identity remains immutable. RuntimePolicies and reservation
admission resolve the same merged catalog; billing still uses the shared
ledger. A future file-configured identity colliding with a persisted identity
is disabled with `model_id_conflict`; an edit cannot bypass that collision.

Adding a future seed under a different alias with a provider/upstream identity
already registered in the database is an invalid deployment combination. The
gateway rejects duplicate concrete routes. Current API creation prevents that
combination. The recommended managed-provider bootstrap selects the existing
database default and does not add a `HOSTING_MODELS_FILE` containing overlapping
seeds.

A model can be registered while runtime configuration is disabled. If a later
deployment selects that existing identity via `HOSTING_MODEL` without seeded
models, admission selects the registered policy ahead of implicit legacy
fallback. The host job uses its effective output cap. Legacy default IDs
already configured before registration are reserved against creation. Runtime
configuration readiness requirements are unchanged, including existing
credential, endpoint, grant, legacy price, and rate validations.

The gateway separately owns trusted provider profiles and derives the actual
route from provider plus upstream model. Persisted catalog registration alone
does not establish a provider connection or activate model execution. The
Console's provider catalog picker/BFF and gateway managed-provider integration
are separate coordinated changes.

## Rollback

Before rolling back to a Manager version that predates `created_models`, take
and verify a snapshot of the current `hosting_state` document. Older writers
ignore the new field and can discard it when serializing the document again,
including during an administrator read that refreshes state. Preserve the
snapshot for restoration before returning to the new version. This matters
once any models have been registered after this release; no new SQL migration
protects the JSON field from an older writer.
