# Refreshed browser session preservation

## Change and boundaries

Issue [060](../issues/060-refreshed-session-cookie-loss.md) covers replacement
WorkOS cookies lost after token refresh succeeds but a later dependency fails.
The implementation stays in `workers/region-directory`; Manager's Go auth and
permission checks, generated APIs, and browser cookie format are unchanged.

`authenticateSession` now carries replacement cookies in a retryable
`SessionFailure` when identity lookup fails. Auth routes and the Worker wrapper
retain cookies after later failures. The opt-in regional Node gateway retains
them on directory failures and HTTP or WebSocket proxy connection failures.
Authentication
failures retain their existing 401 and cookie-clearing behavior.

## Request flow

1. The SDK validates the sealed browser session and refreshes an expired token.
2. The SDK returns replacement sealed session data; the previous refresh token
   has already been rotated.
3. Directory or upstream errors still return 503 or 502, respectively, together
   with the replacement cookies. A later request can use the new token.

The configured public Worker routes in `wrangler.browser.jsonc` handle
`paxworkspace.net/auth/*`, `/api/pax/*`, and browser `/api/v1/user/*` requests.
Its normal caught origin-fetch 503 already retained refresh cookies. The
regional Node HTTP proxy is a separate opt-in deployment; do not infer that it is
running because its implementation is present in this repository.

## Verification and deployment

From `workers/region-directory`, run:

```sh
npm run typecheck
DIRECTORY_TEST_DATABASE_URL=postgresql://postgres:password@127.0.0.1:5432/directory_test npm test
npm run build:regional
```

The focused regression suite first reproduced five cookie-loss failures on the
unchanged implementation. The final full suite passes all 264 tests with real
PostgreSQL, including rejected WebSocket handshakes. Coverage is 94.67% lines,
94.27% statements, 92.95% branches and 96.89% functions, above every 80% gate.
Type checking, Worker dry-run build, regional build, Worker formatting and the
repository `make fmt-check` also pass. No Go implementation changed.

The Worker is deployed separately using `npm run deploy`, which selects
`wrangler.browser.jsonc --keep-vars`. This change does not require a database
migration or generated API updates. No production deployment was performed as
part of this fix.

## Operational limits

WorkOS documents a 30-second replay grace period for rotated refresh tokens:
<https://workos.com/docs/authkit/session-resilience>.

The fix covers error responses that can reach the browser. It cannot deliver a
cookie after a client disconnects or a response has already been sent. It does
not add a cache that bypasses session validation or change refresh-token
revocation rules. Do not report this demonstrated failure mode as the proven
cause of a production incident without matching observations.
