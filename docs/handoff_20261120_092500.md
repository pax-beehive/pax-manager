# Model access for AWS sandbox Agents

`GET /api/v1/starter` describes the owner's live AWS sandbox and the Agent types
the sandbox worker currently supports. An authenticated owner requests model
access for a specific Agent with the existing `POST /api/v1/starter/wake` route.
The same handler still supports the separately enrolled legacy Pi Node.

The sandbox worker reports supported harnesses and polls the existing
`/api/v1/hosting/jobs/claim` route with `kind: sandbox_model`. Only the bearer
configured for managed sandbox Nodes can use this job kind. The job identifies
the owner, Node, Agent, harness, sandbox environment, and sandbox generation.
Its signed model token permits catalog reads while provisioning. Model admission
requires the worker to report the exact assigned Node and Agent as ready.

Manager stores an independent model grant per Agent in the hosting document.
All grants and the legacy Starter share one monthly account quota and pool.
Managed admission holds the hosting and sandbox rows in that order while
verifying the sandbox lease and generation. Successful renewal never extends a
grant past the sandbox's current lease. Revocation blocks new authorizations
and preserves settlement of existing reservations.

The API contract is in `api/pax_manager.thrift`. Run `make generate` to refresh
the Thrift transport and OpenAPI output. Run the sandbox lifecycle and hosting
accounting tests with `go test ./internal/manager/hosting ./internal/manager`.

The matching sandbox worker and guest adapters advertise compatible harnesses.
Manager uses the existing provider catalog and state document schema.
