# Compact session history and on-demand message details

## Summary

Issue 022 is partially addressed in pax-manager and pax-console. Console
requests summary history rather than loading all collapsed tool outputs and
their duplicate ACP payloads. No paxd changes, data migration, commit, merge,
or deployment are included in this work.

## Modules and flow

- domain/message_summary.go defines the narrow storage interface, tool summary,
  and revision-pinned detail page.
- storage/message_summary.go projects tool metadata inside PostgreSQL. Summary
  reads never select tool message_parts payloads. Other parts suppress payloads
  identical to message raw_json while preserving independent structured content.
  The existing seq pagination implementation accepts an internal SQL projection;
  full-history callers retain the previous projection.
- userapi/message_summary.go authenticates session access, returns canonical
  session IDs even for legacy native-session rows, keeps user prompt frames once
  (including attachments), and applies existing artifact/invocation display rules.
- The hand-written history handler supports view=summary; limit defaults to 100,
  max 200, and before_id is rejected for this mode. Missing view and view=full
  preserve compatibility. Agent-scoped legacy history is unchanged.
- GET /api/v1/user/{user_id}/sessions/{session_id}/messages/{message_id} verifies
  both session authorization and message ownership, including session aliases.
  section=input|output chooses stored input or output. Output falls back to the
  ordered text parts (including terminal output); otherwise it uses tool content.
- Detail pages contain format (text/json), text, revision, next_offset, has_more,
  message_id and section. Limit is at most 16384 Unicode code points. JSON must be
  concatenated before decoding. Nonzero offsets require the first page revision;
  a changed message/part update timestamp returns 409. The SQL slices before
  returning the value to Go, so legacy oversized single-part outputs are bounded
  on the wire too.
- Summary reads bypass the old session-wide artifact repair callback. Existing
  ACP and publication write paths still reconcile those display projections.

## Console

The history normalizer consumes tool summaries directly. Event merging retains
all durable message references when tool and terminal rows share a tool ID,
preserves terminal tool completion, and keeps turn identity. Only opening an
individual tool or selecting its evidence panel mounts the detail queries.
TanStack Query keys include user/session/message/section/update time/completion.
Completed output is cached; running single-page details refresh every two seconds
while mounted. Multi-page reads stay pinned and expose explicit Load more and
Reload details. Completion requests a fresh final snapshot. Selected evidence
resolves against the latest timeline. Ordinary text/thoughts and E2EE remain on
their existing paths. Compact history details display text/JSON; they do not
preload patches for rich turn-footer diff aggregation.

## API generation and rollout

These routes extend the existing hand-written history route/OpenAPI mechanism
(route_paths.go, node_idl_handlers.go, message_detail_handler.go, openapi.go and
openapi_message_detail.go). No Thrift-generated handler was edited. The userapi
Store mock was regenerated with:

    go run github.com/vektra/mockery/v2@v2.53.5 --config .mockery.yaml

Use the existing repository make generate workflow for future IDL/generated
changes. Deploy Manager before Console to enable the reduced query/response
path. No paxd release or database migration is required. Existing full-history
clients continue to work. Local Manager build: make build. Local Console uses
the documented same-origin proxy and Node 24.

## Limits and operational notes

No production timing/EXPLAIN or real PostgreSQL run was performed in this task.
Docker is stopped locally; it was left stopped on the user's older laptop.
Storage tests include the existing scripted PostgreSQL driver, not a real
PostgreSQL server. PostgreSQL may still detoast large raw_json values to extract
summary fields, and terminal detail reads aggregate parts before slicing.
Ordinary reply/thought part 0 persistence, large inline user attachments, total
inline text byte budgets and full-history GET repair cost remain open under
issue 022. Stored duplicate raw frames are retained; only reading/transport is
changed. Existing artifact projections are served without a backfill-on-GET.

Pre-existing uncommitted Console permission/UI changes were preserved, including
session-event-cards, merge-session-events, reconcile-session-timeline, permission-
decisions helpers/tests, fleet-overview, and both architecture docs. Review/stage
this task's hunks separately if those other changes must remain uncommitted.
