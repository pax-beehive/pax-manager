# Approval fingerprint index overflow repair

## Change and flow

Issue 043 is resolved in source. ACP tool permission fingerprints can include full command text. The old composite grant lookup index stored that unbounded text and rejected some approval writes with SQLSTATE 54000.

`db/init.sql` creates `idx_agent_approvals_grant_lookup_digest` over the existing scope fields and `md5(action_fingerprint)`, then drops the old index. `PostgresStore.FindReusableApprovalGrant` adds the matching digest predicate while retaining exact full-fingerprint equality. The digest is only an index locator, never an authorization decision. Existing fingerprints, grants, payloads, wildcard scope matching, expiry, and revocation semantics are unchanged.

No API, transport, generated model, or column definitions changed. No regeneration is required. Generated model index annotations still describe the previous introspected index; runtime schema is owned by init.sql, and this change does not invoke GORM AutoMigrate.

## Deployment

Production has not been modified. Deploy manager code and the updated db/init.sql together through the existing production workflow. EnsureSchema applies the migration at startup. The regular CREATE INDEX and DROP INDEX can wait on locks and block writes while applied; schedule accordingly. The replacement is created before removing the old index. Old manager binaries retain correct matching semantics against the new schema but will not use the digest index for fingerprint filtering.

Do not restore the old index while long fingerprints exist: rebuilding it can reproduce the same failure. No approval content needs rewriting.
