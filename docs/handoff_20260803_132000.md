# Session Runtime Snapshot Reconciliation Handoff

## Outcome

Session runtime status now has one durable authority path:

```text
ACP router lease
  -> paxd active-turn projector
  -> complete session_runtime.snapshot report
  -> pax-manager fenced atomic reconciliation
  -> AgentSession.runtime_status
  -> pax-console session status surfaces
```

ACP frames remain authoritative for conversation output and history, but no
longer write current runtime status after an agent's first valid snapshot
commits. Snapshot authority is persisted per agent and remains sticky across
manager restarts and node-control reconnects.

## Runtime Contract

Each active turn reports:

- native session ID;
- globally unique turn instance ID;
- the original string or numeric JSON-RPC prompt request ID;
- `running` or `waiting_approval` status; and
- optional approval, slot, and process-epoch diagnostics.

Absence from the next valid complete snapshot means `idle`. A connection-scoped
manager fence and monotonically increasing report sequence reject late,
duplicate, and out-of-order snapshots. Connection replacement and snapshot
commit share the durable fence/head transaction boundary.

Snapshot validation rejects malformed IDs, duplicate session/turn keys,
invalid statuses, more than 1,024 active turns, identifiers over 512 bytes, and
prompt request IDs over 512 bytes. Invalid reports are never partially applied.

## Storage and API

`db/init.sql` adds:

- `agent_sessions.runtime_status`;
- `agent_sessions.runtime_turn_instance_id`;
- `node_runtime_fences`;
- `agent_runtime_snapshot_heads`, including durable authority; and
- `agent_native_session_bindings`, with unique `(agent_id, native_session_id)`
  ownership.

Inventory writes structurally exclude runtime projection columns. Legacy frame
projection checks the durable authority marker inside storage and becomes a
no-op after snapshot cutover. Session API responses and generated OpenAPI now
include canonical runtime fields.

The user reset endpoint is:

```text
POST /api/v1/user/{user_id}/agents/{agent_id}/sessions/{session_id}/runtime/reset
{"expected_turn_instance_id":"turn_..."}
```

Manager authorizes and resolves the canonical session to its native identity,
then forwards `session_runtime.reset` to the bound paxd connection. The response
is explicitly `accepted_pending`; paxd immediately triggers a new complete
snapshot. The operation suppresses display projection only and does not cancel
the ACP task, release the prompt lease, or delete slot lifecycle state.

## Console Ownership

Session lists, details, Home work items, mobile activity indicators, and the
workbench badge read only `runtime_status`. They do not fall back to `status`,
`run_status`, ACP frames, observer state, or agent connectivity. Live state
still controls current-window interaction behavior such as stop, queue, and
stream following.

The workbench overflow menu exposes **Reset stale status** only when an active
turn instance exists. Confirmation warns that the action does not cancel the
underlying task. Acceptance invalidates detail, agent-session, and global
session-list queries. Thirty-second polling remains as a disconnected-client
fallback.

## Rollout

1. Apply the manager database schema before deploying the new manager binary.
2. Deploy manager first; older paxd agents remain on frame authority.
3. Deploy paxd. Each agent switches atomically and permanently to snapshot
   authority when its first valid snapshot commits.
4. Deploy console after manager session responses expose `runtime_status`.
5. Observe fenced/stale/duplicate/invalid report rates and reset conflicts.

Do not roll an agent back to frame authority implicitly. Any downgrade requires
an explicit audited migration because replayed ACP frames are not a safe current
status source after snapshot cutover.
