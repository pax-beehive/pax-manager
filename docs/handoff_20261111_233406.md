# Voice Input Relay Handoff

## Summary

Manager now relays browser dictation audio to a streaming speech recognition
provider and streams transcript snapshots back. Each manager instance selects
its own provider, because OpenAI does not serve Hong Kong:

- US instance: OpenAI `gpt-live-transcribe`
- HK instance: Alibaba Cloud Model Studio `qwen3-asr-flash-realtime` on the
  international (Singapore) endpoint
- Also available: ByteDance Seed ASR 2.0 via Volcengine (mainland China
  endpoint) or BytePlus (international endpoint)

Voice input is off unless `VOICE_PROVIDER` is set. It is limited to admins
until `VOICE_ADMIN_ONLY=false`, which matches the admin-only Mic button in
pax-console. No frontend code is part of this change.

## Module Boundaries

- `internal/manager/voice` owns everything provider-specific:
  - `voice.go`: `Provider` and `Stream` interfaces, `Snapshot`, settings,
    hint normalization, and provider selection.
  - `openai.go`: OpenAI Realtime transcription client (JSON frames).
  - `qwen.go`: Qwen realtime ASR client (OpenAI-style JSON frames, server
    VAD).
  - `transcript.go`: per-item transcript tracking shared by the OpenAI and
    Qwen clients.
  - `seedasr.go`, `seedasr_frame.go`: Seed ASR client and its binary framing
    (4-byte header, sequence, size, gzip payload).
  - `session.go`: `Serve`, the browser-facing protocol bridge.
- `internal/manager/voice_handlers.go` authenticates, enforces admin-only,
  upgrades the WebSocket, and delegates to `voice.Serve`.
- `internal/manager/config` owns the environment variables below.
- `internal/manager/openapi_voice.go` documents both endpoints.

## Endpoints

```text
GET /api/v1/user/{user_id}/voice/config   JSON availability for the caller
GET /api/v1/user/{user_id}/voice/stream   WebSocket dictation session
```

Both use the authenticated principal; `user_id` is not trusted.

`voice/config` returns `{enabled, provider, sample_rate, encoding,
max_duration_seconds}` in `data`. `enabled` is false when no provider is
configured or the caller is not allowed.

## Stream Protocol

Client to server:

1. Text `{"type":"start","keywords":["..."],"context":["..."]}`. `keywords`
   are hotwords (max 100, 64 runes each). `context` is recent conversation
   text, oldest first, bounded to 20 items and 800 runes total.
2. Binary frames of mono `pcm_s16le` at the advertised `sample_rate` (OpenAI
   24000, Qwen and Seed ASR 16000). Send 100-200 ms chunks; frames over 64 KiB close
   the connection.
3. Text `{"type":"stop"}` to finalize, or `{"type":"cancel"}` to abort.

Server to client:

- `{"type":"ready","provider","sample_rate","encoding"}` after the provider
  session opens.
- `{"type":"transcript","final","partial"}` snapshots. Each one carries the
  whole transcript: `final` never changes, `partial` may be rewritten. Clients
  replace their rendered text rather than appending.
- `{"type":"done","final"}` with the full text, or
  `{"type":"error","code","message"}` with code `bad_request`,
  `provider_unavailable`, `provider_failed`, or `timeout`. The server then
  closes the connection.

Audio past `VOICE_MAX_SESSION_SECONDS` stops the session as if the client had
sent stop. Providers get 15 seconds after stop to return a final result.

## Provider Mapping

OpenAI (`wss://api.openai.com/v1/realtime?intent=transcription`):

- `Authorization: Bearer`, plus `OpenAI-Safety-Identifier` set to a hash of
  the user id.
- `session.update` with `type: transcription`, `audio/pcm` at 24 kHz,
  `turn_detection: null` (the model has no server VAD), `delay`, `languages`,
  `keywords`, and context folded into `prompt`.
- Audio goes out as `input_audio_buffer.append` (base64). Stop sends one
  `input_audio_buffer.commit`. Sessions under 100 ms of audio skip the commit.
- Deltas accumulate per `item_id` into `partial`; `completed` replaces the
  item with the final transcript.

Qwen (`wss://dashscope-intl.aliyuncs.com/api-ws/v1/realtime?model=...`):

- `Authorization: Bearer` with a Model Studio key, plus
  `OpenAI-Beta: realtime=v1` as in the vendor samples. Keys are regional: the
  default endpoint needs a Singapore key.
- `session.update` with `pcm` at 16 kHz and the balanced server VAD preset
  (`threshold` 0.2, `silence_duration_ms` 800), so each pause finalizes an
  utterance. Keywords and context go into
  `input_audio_transcription.corpus.text`. `language` is omitted unless
  `VOICE_QWEN_LANGUAGE` is set, which keeps auto detection for mixed speech.
- Every client event carries a unique `event_id`. Audio goes out as
  `input_audio_buffer.append`. Stop sends `session.finish`; the service
  returns the last transcription and then `session.finished`.
- `...transcription.text` events carry `text` (settled prefix) and `stash`
  (draft tail); the item shows both as partial until `...completed` replaces
  it with the final transcript.

Seed ASR (`/api/v3/sauc/bigmodel_async`):

- Headers `X-Api-Key` (new console) or `X-Api-App-Key` + `X-Api-Access-Key`
  (legacy console), `X-Api-Resource-Id`, and the same UUID in both
  `X-Api-Request-Id` and `X-Api-Connect-Id`.
- The full client request enables two-pass recognition (`enable_nonstream`),
  ITN, punctuation, utterances, and `result_type: full`. Hotwords and dialog
  context (newest first) go in `corpus.context`.
- The leading run of `definite` utterances becomes `final`; the rest is
  `partial`. A trailing 100 ms of silence is sent as the negative-sequence
  last packet.

## Runtime Configuration

```text
VOICE_PROVIDER=                  # openai | qwen | volcengine | byteplus; empty disables
VOICE_ADMIN_ONLY=true
VOICE_MAX_SESSION_SECONDS=300
VOICE_LANGUAGES=zh-cn,en         # OpenAI language hints

OPENAI_API_KEY=
VOICE_OPENAI_URL=                # default wss://api.openai.com/v1/realtime?intent=transcription
VOICE_OPENAI_MODEL=              # default gpt-live-transcribe
VOICE_OPENAI_DELAY=              # default low; minimal|low|medium|high|xhigh

DASHSCOPE_API_KEY=               # Model Studio key for the endpoint's region
VOICE_QWEN_URL=                  # default wss://dashscope-intl.aliyuncs.com/api-ws/v1/realtime
VOICE_QWEN_MODEL=                # default qwen3-asr-flash-realtime
VOICE_QWEN_LANGUAGE=             # default empty (auto detect); e.g. zh, en

VOICE_SEEDASR_API_KEY=           # or VOICE_SEEDASR_APP_KEY + VOICE_SEEDASR_ACCESS_KEY
VOICE_SEEDASR_APP_KEY=
VOICE_SEEDASR_ACCESS_KEY=
VOICE_SEEDASR_RESOURCE_ID=       # default volc.seedasr.sauc.duration
VOICE_SEEDASR_URL=               # default by provider, see below
```

Seed ASR default URLs:

```text
volcengine  wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async
byteplus    wss://voice.ap-southeast-1.bytepluses.com/api/v3/sauc/bigmodel_async
```

A provider with missing credentials logs `voice input disabled` at startup and
leaves the instance running without voice.

## Known Risks and Assumptions

- Nothing has run against the live providers yet. On the first real session,
  check:
  - whether `gpt-live-transcribe` deltas only append or also revise earlier
    text (the guide mentions revisions without specifying them);
  - that Qwen accepts the session update as sent (`modalities`, the VAD
    preset, `corpus.text`) and that `session.finish` flushes the last
    utterance;
  - that Seed ASR acknowledges the session request before any audio arrives
    (`Open` waits up to 10 seconds for that frame);
  - the Volcengine endpoint and resource id for the account.
- The browser must reach this WebSocket. pax-console now streams over SSE
  through same-origin `/api/pax`. Next route handlers cannot upgrade
  WebSockets, so whatever fronts the manager must forward the upgrade.
- The shared upgrader accepts any Origin, as the ACP tunnel does. A cross-site
  page with a valid session could spend provider minutes. Admin-only mode
  limits that exposure.
- There is no per-user cap on concurrent voice sessions.
- With OpenAI, the whole dictation is one committed item, so final text
  arrives only after stop. Long sessions are bounded by
  `VOICE_MAX_SESSION_SECONDS`.
