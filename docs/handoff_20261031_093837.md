# Automatic Secretary end-to-end handoff

## Result and scope

Automatic session summaries now use one user-selected owned agent. Console
`/settings/secretary` provides selection, an explicit Save settings action, an
enable switch, runtime status and Run now / Retry run. The default is disabled.
Offline owned agents can be selected; execution waits for their ACP connection.

This completes the automatic fragment-summary layer on top of the search and
immutable-summary implementation. It does not migrate the separate local JSON
topic/project/direction board or restart its stopped watch process. The feature
operates on currently owner-visible Manager plaintext messages. Local native
logs, ciphertext, reasoning and tool output are outside this source contract.

Authoritative interfaces and operational limits are in
[secretary_automation.md](secretary_automation.md). Earlier storage details are
in [handoff_20261031_022926.md](handoff_20261031_022926.md); search and source
version contracts are in [search_contract.md](search_contract.md).

## Module boundaries and data flow

- `userapi/secretary.go` owns authenticated settings, owned-agent validation,
  settings CAS and public runtime status. `secretary_handlers.go` binds the
  three HTTP routes. Raw provider/source errors are not returned to the UI.
- `storage/secretary*.go` and `db/secretary.sql` own settings, coalesced durable
  jobs, leases, retry generations, internal-session registration and per-message
  canonical-hash checkpoints. Changes to message parts also enqueue work.
- `secretary/worker.go` reads bounded complete source batches, builds the prompt,
  validates model JSON and evidence, monitors cancellation and requests atomic
  publication. It never delegates source identity or ownership to model output.
- `secretary_agent.go` executes the selected actual agent through the existing
  ACP tunnel and conversation runner, using stable isolated session/turn IDs.
  Completed responses can be recovered without repeating a transient failed
  publication. Tool permission handling remains manual.
- `secretary_publish_postgres.go` validates source versions and settings/lease
  fences, freezes every coverage body, saves an immutable summary revision and
  advances message checkpoints in one transaction. Failure advances none of
  these. Existing summary publication queues the current version for ES.
- `app.go` starts the worker under the Manager lifecycle and stops it before
  transport storage closes. Schema initialization now includes all four DDL
  files in order: init, summaries, search and secretary.

The worker polls every five seconds and normally waits until the source session
is idle and quiet for 30 seconds. A batch is bounded to 64 complete visible
messages and 128 KiB; no source message is silently truncated. Unchanged blocks
are reused, new messages form new blocks, and an edited covered message creates
a new revision of its existing block. Multipart boundaries do not become new
message identities. Previous fragments provide bounded context without silently
becoming additional coverage.

Disable or selection changes cancel active work when possible and fence final
publication independently. Internal execution sessions are registered before
prompting and marked with `secretary_internal`; ordinary search also excludes
the reserved `sess_secretary_` prefix. This prevents recursive summarization and
duplicated raw source bundles in search. Direct owner diagnostics remain possible.

The HTTP source of truth is `api/pax_manager.thrift`. GET/PATCH
`/api/v1/user/self/secretary` read/save configuration; POST
`/api/v1/user/self/secretary/run` queues work and retries failures, returning 202.
Regenerate router, models and OpenAPI using `make generate`. No generated
artifacts were manually changed.
