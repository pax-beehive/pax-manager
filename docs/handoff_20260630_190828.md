# Agent Audit Events Handoff

## Summary

Implemented a user-facing audit event surface for agent and session activity.
The new audit stream standardizes tool calls, tool results, file changes,
message completions, approval requests, approval decisions, and approval grant
revocations.

The user API now exposes:

```text
GET /api/v1/user/:user_id/audit-events
```

Supported filters are `q`, `event_type`, `agent_id`, `session_id`,
`approval_id`, `decision`, and `limit`.

## Module Boundaries

- `api/pax_manager.thrift` is the IDL source of truth for the new response
  models and endpoint.
- `internal/manager/domain` owns the audit event model, constants, and store
  interface contract.
- `internal/manager/storage` owns extraction, persistence, upsert, and query
  behavior for Postgres and memory stores.
- `internal/manager/node_idl_handlers.go` binds the user endpoint and delegates
  to storage.
- Generated transport, OpenAPI, and mocks were refreshed with `make generate`.

## Core Flow

1. Approval writes create audit events at the same point the approval state is
   stored:
   - `approval_requested`
   - `approval_decided`
   - `approval_grant_revoked`
2. Mailbox result writes extract audit events from paxd-reported payloads:
   - `events` with `entity_type=tool` and `event_type=call` becomes
     `tool_call_requested`
   - `events` with `entity_type=tool` and `event_type=result` becomes
     `tool_call_completed`
   - `file_changes` becomes `file_changed`
   - completed or failed messages become `message_completed`
3. Audit writes use stable source keys so repeated result reporting updates the
   same logical audit record instead of duplicating it.
4. The user endpoint lists owner-scoped audit events ordered by occurrence time
   descending.

## Schema

Added `agent_audit_events` to `db/init.sql`.

The table stores normalized fields for filtering and display, plus raw JSON for
later parser improvements:

- identity fields: owner, node, agent, session, turn, message, approval
- event fields: type, source, stable key, title, summary
- tool fields: tool name and tool input
- approval fields: reason, risk, status, decision, scope, approver, decision time
- raw payload and timestamps

## Risks And Follow-Ups

- The first parser supports the current paxd/Hermes tool event shape
  (`entity_type=tool`, `event_type=call|result`). If paxd sends additional
  shapes, add parser cases in `internal/manager/storage/audit_events.go`.
- Audit writes happen after the primary approval or mailbox write. A failed audit
  upsert currently makes the operation fail, but the primary write is not wrapped
  in a shared transaction.
- The list endpoint is owner-scoped. If team/shared-agent audit visibility is
  required, add explicit access rules before broadening the query.
- Some stored session IDs come from manager-side canonical IDs. If the UI needs
  native session ID filtering everywhere, add a translation pass before audit
  persistence.
