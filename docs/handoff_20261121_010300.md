# Hosted sandbox recovery and turn results

The owner can start a saved sandbox with `POST /api/v1/sandbox/resume`, or
request a restart with `POST /api/v1/sandbox/restart`. Both require the saved
Node ID. Restart also requires the generation from `GET /api/v1/sandbox`.
Manager queues the next generation, and the worker fences and replaces the
old run on the original disk. Replaying the old generation returns the current
status and cannot restart it again. The existing creation request remains
compatible with older Consoles.

The region directory must publish the two browser allowlist entries when the
Manager endpoints are published. Console can issue these actions after they
are available in its active region. The worker keeps its existing job and
lease contract, so no new host command or service key is needed for restart.

Conversation errors use the existing message field to identify agent
connection, session startup, delivery or agent response failures. A closed
agent response stream without a terminal reply returns an interruption. If a
terminal reply has already arrived, it is kept. Permission interruptions and
their resume flow continue to use their existing events.
