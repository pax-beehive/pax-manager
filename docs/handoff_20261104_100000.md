## 模块和数据路径

- `db/summaries.sql`：`knowledge_nodes` 身份和 current 指针、来源目录与失效；
  继续复用 `summary_versions`、`summary_sources` 和 `message_snapshots`。
- `db/secretary.sql`：来源队列 `secretary_jobs`、固定输入 `secretary_batches`、
  实际调用 `secretary_attempts`、处理账本和内部 session 注册。
- `internal/manager/storage/secretary_nodes*.go`、`secretary_node_invalidations*.go`：
  多输出原子发布、固定来源、来源变更与权限变化的反向失效。
- `internal/manager/storage/secretary_lifecycle*.go`：prepare/begin/save/fail、恢复授权、
  attempt/lease/settings fence、prompt 失败阻塞；`secretary_completed_sources.go` 校验完成证明。
- `internal/manager/secretary/nodes_{prompt,output,publication,worker}.go`：
  有界提示词、create/revise/outcome、来源绑定、执行恢复与发布。
- `internal/manager/secretary_agent_nodes.go` 和 `secretary_tools*.go`：
  真实 ACP 关联、只读 capability 工具、读取账本和 summaries 目录投影。
- `api/pax_manager.thrift` 是路由源；需要重新生成时执行 `make generate`，不能手改生成物。

完整请求/数据链路、全部 API、预算和运行默认值见[运行说明](secretary_automation.md)。
新增历史接口为 `GET /api/v1/user/self/secretary/summaries/:summary_id/revisions`；
列表和历史返回 `items/next_cursor`，正文仍用 search/read 的确切 ref。
Node 展示元数据包括 summary type、active/empty/stale 和独立授权的 origin source 信息。
origin 用于成果与 session 搜索归组，附加证据来源不复制同一张摘要卡片。

## 必须保持的生命周期边界

1. 只处理有可靠完成证明、且 source idle/静默期已过的消息；idle 不证明完成。
   稳定 message ID 来自采集，parts 在完成前组装，不建 message revision 或逐 chunk 历史。
   用户全文、assistant 每消息 last 为默认；full 只展开可见正文，tools/thought 全程排除。
2. Prepare 优先恢复同一 owner/source/settings/epoch 的 open batch，新 turn 不扩大旧 checkpoint。
   恢复缓存输入先校验范围并逐项重新授权，源删除/撤权后旧混合 body 不能再次交给模型。
   不可用输入原子 superseded，并返回 SourceVersionUnavailable；空新 delta 不绕过旧批次。
3. Begin attempt 持久化后才调用模型。输出和可信 reads 先保存，重启恢复 output_received 不调用模型。
   运行中/未知 attempt 只能检查原执行确定终态，ACK、idle、lease 过期均不足以自动重发。
4. 三次真正失败后停止；未尝试的完成等待不计数，prompt/schema 预算失败在无 attempt 时直接 blocked。
   active manual run 不轮换 epoch 或创建第二次调用。关闭设置、租约/attempt 失配和迟到输出不能提交。
5. 多份新版本、确切来源、快照、全部 outcome、checkpoint、commit manifest 和 ES outbox 同事务。
   同请求/hash 重放返回同组 ID/revision，不同 hash 冲突；ES 失败只重试索引。

current coverage 是当前保留内容，不累积全部历史；处理账本和历史来源目录各司其职。
来源失效必须修订所有受影响目标；没有内容时仅允许既有失效 Node 发布明确 empty。
stale 是当前版需更新，不是 empty；撤权直接拒绝标题、片段、正文和历史，不能只隐藏来源按钮。

## 超大历史成果与 MCP

capability 模式只暴露 search/read/expand/history/summaries 五个只读工具，没有 publish/board 工具。
workspace_summaries 参数 session_id 必须匹配当前整理来源；默认 20、最大 50，0 用默认。
响应页限制 64 KiB，正常返回完整当前 SummaryVersion；单大项仅返回
`{summary_id,revision,title,requires_read:true}`，不能把它当已读正文或来源。
用 `workspace_read({ref:{kind:"summary",id:"...",revision:N}})` 获取整版后才允许修订。
摘要读取不分页，整版 JSON 与其他工具读取共享每任务累计 4 MiB 预算，超限在响应和账本写入前拒绝。
prompt 的 summaries_has_more 为 true 且 cursor 为空时，从 summaries 第一页列举。
新发布结构仍整批 64 KiB，不能用目录头绕过输出或事实来源预算。

## 迁移与发布

`PostgresStore.EnsureSchema` 顺序执行 init/summaries/search/secretary 四份 SQL。
Node 身份/来源目录幂等补齐，复用旧 summary ID 与历史；不清 checkpoint、不改旧引用、不创建 topic。
worker 启动只补齐缺失队列，没有全面重算、拆分历史或启动模型迁移；
已启用且确实 pending 的工作依然按正常调度处理，不能宣称重启绝不调用模型。

先备份 PG、在副本验证 schema 和旧成果，再部署新 Manager；随后 Console 与所选 agent 主机的 paxd。
同一个队列不要混跑新旧 worker。旧版本缺少 summaries 工具时显式失败，不当作空页。
本版不自动压缩超过 4 MiB 读取预算的旧单份摘要，不自动重建全部历史 session。
原始 ACP 上游 runtime 真实性仍受[问题 064](../issues/064-secretary-stale-upstream-background-state.md)约束；
多 Manager 水平扩容仍需 agent 连接路由，PG lease 不是完整的路由实现。
