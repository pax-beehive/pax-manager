# Region Directory Worker release integration

## Problem and resulting behavior

Worker deployments were outside PAX Release and the default deploy command used
the obsolete bootstrap-only configuration. The deploy command now uses the
browser production configuration, while a separate CI workflow uploads immutable
versions without routing traffic. PAX Release selects/activates those exact
versions and records global progress plus US/HK verification.

This repository adds the version-upload/registration workflow, full commit
annotation, configuration fingerprint, Manager capability health fields and a
credential-protected read-only Worker diagnostic. The companion pax-release
branch is `feat/worker-release`. Its `docs/worker-release.md` contains API schemas,
controller configuration, recovery semantics and the rollout checklist.

## Validation

- BDD tests first failed on missing regional capabilities/diagnostic endpoints.
- Manager fmt-check, lint, complete Go tests and build passed after regeneration.
- New Manager health handler: 100% statement coverage.
- Worker unit/Miniflare suite passed; release-health.ts has 95% statement coverage.
- CI upload/registration tests: 95% branch-inclusive coverage.
- No production deployment, secret mutation, route change or D1 migration used
  as a test. The new workflow stays disabled until explicitly configured.

## Rollout prerequisites

Deploy the Manager contract to both regions before any Worker activation. Add a
dedicated RELEASE_PROBE_TOKEN to the Worker/controller, verify regional Access
service credentials, add PAX_WORKER_CF_API_TOKEN, and enable the repo variable
PAX_WORKER_RELEASE_ENABLED after upgrading/configuring the Release controller.
The CI workflow only uploads/registers; Release activation is operator-only.
Cloudflare Workers Scripts Write also permits activation, so keep these tokens
private; the permission cannot enforce an upload-only credential boundary.
See workers/region-directory/README.md for complete setup and limitations.

## Remaining work

First live CI upload and operator-triggered US/HK production verification require
the credentials/configuration above. No production activation is claimed by this
handoff. Staging, machine routing rollout and issue 034's remaining recovery
scope stay open. Rollback means republishing a compatible registered old version;
there is no automatic rollback, database restore or bypass of CF secret guards.
