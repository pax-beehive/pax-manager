# Secretary durable automation storage handoff

## Scope and ownership

This change adds the domain contract and PostgreSQL/in-memory persistence for
opt-in Secretary automation. It consumes canonical Manager messages. It does not
read local paxl exports, modify the adjacent Secretary demo, migrate its boards,
or restart the stopped prototype pipeline.

The worker/ACP adapter, HTTP/app wiring and Console settings are separate changes
by other agents. This handoff describes the storage boundary they use.

## Files

- `internal/manager/domain/secretary.go`: settings, status, jobs, bounds and store
  interface. The default is disabled, revision zero, with no selected agent.
- `db/secretary.sql`: settings, durable jobs, coalesced per-message state and an
  explicit registry of internal runner sessions. Message/part triggers record
  changes atomically with source writes; owner transfer invalidates leases.
- `storage/secretary_postgres.go`: owner settings/CAS, status, backfill and retry.
- `storage/secretary_jobs_postgres.go`: bounded claims, canonical reads, lease
  checks, internal-session registration and failure backoff.
- `storage/secretary_publish_postgres.go`: fenced summary publication and
  checkpoint completion in one PostgreSQL transaction.
- `storage/secretary.go`: source bounds, stable generation/request IDs and trusted
  publication contract validation.
- `storage/secretary_memory*.go`: memory parity and immutable summary/snapshot
  support. `MemoryStore` gains one private state pointer; existing source
  visibility and canonical text rules are reused.
- `storage/secretary*_test.go`: BDD unit/driver and isolated PostgreSQL tests.

No generated artifacts were edited by this storage work. Root wiring adds the
fourth DDL file to `EnsureSchema`; startup applies it after `search.sql`.

## Source and job data flow

1. The owner selects an owned active agent and explicitly enables Secretary.
   Settings updates require `expected_revision`. An existing unavailable agent ID
   may be preserved while disabling, so removal cannot prevent turning it off.
2. Initial backfill and message/part writes coalesce durable work by canonical
   `agent_sessions.id`. Message state keeps a change revision and the hash/owner
   of the version last successfully summarized. Sequence numbers are not the
   processing checkpoint.
3. Claims require an active owned source, an idle runtime and a quiet interval.
   The worker defaults to 30 seconds. Claims return at most 64 complete canonical
   visible messages totaling 128 KiB. Individual messages are never silently
   truncated. Oversized work remains pending with a bounded visible error.
4. A new batch gets a stable fragment summary ID. An edit to an existing fragment
   regenerates that fragment with its complete currently visible coverage; other
   blocks remain reusable. New messages and another old block are not folded into
   the same replacement. At most ten accessible previous fragments are returned
   as context, without automatically declaring them to be sources.
5. The runner registers its internal agent/session before sending the first
   prompt. Scheduling excludes both explicit registrations and
   `source=secretary_internal`, preventing feedback into its own summaries.
   Registration also stamps an existing session row with that source marker;
   a pre-create registration remains in the registry until the row exists.
   Ordinary search excludes the marker and reserved execution-session prefix.
6. `PublishSecretaryJob` validates exact coverage and the fixed run/summary IDs,
   locks settings and the lease, rechecks ownership/current visibility, freezes
   exact source versions, inserts the immutable summary and source links, then
   advances message hashes and only the claimed queue revision in one commit.
   The summary insert also enters the existing durable ES indexing queue.

Parts arriving during generation leave a newer revision pending. A failed
generation, source-version mismatch or rolled-back publication does not advance
content checkpoints. No-op/hidden dirty events can be acknowledged without a
model call and without inventing a new processed body hash. Source deletion
invalidates dependent summaries through the existing current-visibility policy.

## Cancellation, retries and identity

Settings changes clear old leases and increment the configuration revision.
`SecretaryJobActive` checks that revision, selected agent, current source access,
internal-session exclusion and the live lease. Publication holds the settings
lock for its transaction, so a disable that wins the lock fences publication.
Lease expiration uses `clock_timestamp()` even while a transaction waits on a
lock. The worker's active monitor owns prompt cancellation; storage provides the
final publication fence.

Automatic transient retries preserve `RunID`, allowing reuse of already completed
ACP output. Explicit retry increments a separate durable `RetryGeneration` for
inactive pending work, without changing settings CAS. This permits a fresh model
execution after invalid/canceled output while keeping its target fragment ID.
The fingerprint also includes `ExpectedRevision`: a source reverting A to B to A
must create fragment v3, not collide with the original v1 request/cache entry.

Checkpoint ownership is tracked separately. A transferred source cannot reuse
the previous owner's processed hashes or lease. Existing historical snapshot
ownership checks remain unchanged; this feature does not expand authorization.
