# Optional harness upgrade version

The existing harness upgrade API accepts an omitted, blank, or explicit latest
version. Manager normalizes blank input to latest before forwarding the durable
command. Explicit semantic versions remain supported; ranges and other tags are
rejected. Authentication, ownership and connection selection are unchanged.

paxd resolves latest once using paxl upgrade --dry-run before draining, then passes
that exact version to installation and runtime verification. Console defaults a
blank input to latest and reads the installed version from command results,
including after reload. The existing paxl installer already supports this flow.

api/pax_manager.thrift remains the schema source. Regenerated with make generate;
the OpenAPI description changed and no endpoint or field was added.

The browser fixture provides npm view responses and records each query. E2E
leaves all six CLI/ACP target versions blank, checks successful concrete version
reporting after reload, and asserts exactly one latest lookup per package. Existing
explicit-version Codex/Pi rollback cases remain covered. No real packages or
provider accounts are changed.

Verification: make generate, make fmt-check, make lint, go test -count=1 ./...,
go build ./cmd/manager, and TestHarnessBrowserUpgrade with the updated Console,
paxd test node and paxl binary. Use gvm Go 1.26, GOWORK=off, and Node 24 on PATH.
No local issue statuses changed. Deployment requires the updated Manager and
paxd alongside Console; older daemons reject latest explicitly.

All checks above passed. Browser E2E completed in 70.59s with six blank-version
upgrades, reload recovery of exact installed versions, exactly six npm latest
