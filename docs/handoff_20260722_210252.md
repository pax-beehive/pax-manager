# Inbound Consumer ACK Watermark Handoff

## Summary

The ReliableMQ consumer ACK path now persists a monotonic
`inbound_acked_through` watermark in `transport_queue_state`.
`ConsumerAckedThrough` reads that queue-state value directly instead of scanning
the complete inbound `transport_journal` history for every frame.

The change keeps consumer ACK and dispatcher progress independent:

- `inbound_acked_through` records the highest contiguous inbound sequence that
  has been durably journaled.
- `inbound_applied_through` records dispatcher progress.
- Advancing dispatcher progress does not advance the consumer ACK watermark.

No tracked issue under `issues/` described this performance problem, so no issue
status changed.

## Module Boundaries

- `db/init.sql`
  - Adds and backfills `transport_queue_state.inbound_acked_through`.
  - Creates queue-state rows for legacy journal queues.
  - Adds a partial inbound ACK index.
- `internal/manager/storage/transport_journal.go`
  - Keeps the PostgreSQL implementation and transaction ownership in
    pax-manager.
  - Locks the queue-state row while saving an inbound frame.
  - Advances only from the previous watermark through the newly contiguous
    journal tail.
- `internal/manager/storage/memory_transport_journal.go`
  - Implements the same monotonic and gap-aware behavior for the memory store.
- `paxkit/reliablemq`
  - The sibling paxkit branch adds the same queue-state field and behavior to
    paxkit's reference SQL and memory stores.

pax-manager does not delegate its transport storage to paxkit. Its journal has
manager-specific foreign keys, compatibility columns, lifecycle operations,
and transaction boundaries.

## Core Flow

For an inbound frame:

1. Begin the journal transaction.
2. Ensure the queue-state row exists.
3. Lock the queue-state row with `FOR UPDATE`.
4. Read the existing consumer ACK and dispatcher-applied watermarks.
5. Insert the inbound frame if it is not already present.
6. If the frame fills the next ACK gap, query only rows with
   `seq > inbound_acked_through` and find the newly contiguous tail.
7. Update `inbound_acked_through` with `GREATEST` in the same transaction.
8. Commit.
9. `ConsumerAckedThrough` subsequently reads one queue-state row.

Out-of-order frames above a gap do not trigger a historical scan and do not move
the watermark. When the missing frame arrives, the watermark advances across
the contiguous buffered tail once.

## Schema Migration

`db/init.sql` performs an idempotent migration:

- add `inbound_acked_through BIGINT NOT NULL DEFAULT 0`
- insert missing queue-state rows for legacy journal queues
- backfill the contiguous inbound watermark with `ROW_NUMBER() OVER`
- derive the backfill only from contiguous durable journal rows; do not use
  `inbound_applied_through` as a consumer ACK lower bound
- rebuild ACK progress conservatively from ordered peer retries if applied
  journal rows were already swept before this migration
- create `idx_transport_journal_inbound_ack` on `(queue_id, stream, seq)` for
  durable inbound statuses

The runtime watermark is monotonic and derived only from durably stored inbound
rows. The applied cursor is not used as the ongoing consumer ACK algorithm.

## Risks and Follow-up

- The paxkit and pax-manager branches are currently tested together through the
  workspace `go.work`. Publish the paxkit change first, then update
  pax-manager's `go.mod` to that paxkit pseudo-version before publishing the
  pax-manager branch.
- A Docker-backed PostgreSQL schema validation was attempted, but the isolated
  build could not pull `postgres:16-alpine` because the registry request timed
  out. The temporary Compose project was removed.
- `make fmt-check` and the repository-wide lint command still report the
  pre-existing goimports ordering in
  `internal/manager/storage/message_history_test.go`, which is unchanged from
  `origin/main`. The changed storage files have no remaining lint findings.
- No transport GC worker was added in this change. paxd's current 72-hour plus
  latest-100 policy prunes ACKed outbound rows through paxkit. pax-manager's
  `DeleteCompletedTransportFrames` is not scheduled and does not implement the
  same keep-tail policy. Add consumer-side completed-frame GC as a separate
  follow-up after the ACK semantics land.
