# WorkOS browser authentication

## Changes and boundaries

The region-directory Worker owns `/auth/login`, `/auth/callback`, `/auth/session`
and POST `/auth/logout`. WorkOS SDK 11 uses PKCE and sealed sessions; the callback
transaction is an expiring encrypted JWE tied to a host-only HttpOnly cookie.
Session cookies are Secure, SameSite=Lax, split into at most four chunks. Refresh
replaces all chunks; transient errors retain cookies and return 503. Access token
verification uses the environment's WorkOS JWKS and explicit issuer allowlist.
No provider tokens or API keys are returned to the browser.

D1 migration 0002 creates `workos_identities`. Initial binding requires verified
email. Unique subject and canonical email constraints prevent conflicting claims.
Subsequent requests resolve only the immutable WorkOS subject, even when the
provider email changes. Existing `user_regions` rows, IDs and US/HK assignments
are untouched. New users select a region through the existing bootstrap flow.
The synthetic local account cannot bind. Deleting/recreating a WorkOS user does
not automatically transfer an existing binding; recovery requires an explicit
administrative review. No bulk import or email notifications are performed.

The Worker signs `pax-browser-identity-v1` proofs with the destination region's
existing provisioning secret. Proofs bind canonical account, WorkOS subject,
region, method, path and a 30-second window. Transport code supplies actual method
and path, never user-provided metadata. Manager resolves the already-provisioned
account and checks its ID; foreign-region principals must already be admins and
can only reach analytics or explicit CLI login approval. Existing PAX API key
and Cloudflare authentication remain available. No generated API changes.

## Deployment order

1. Apply the additive D1 migration and set WorkOS API/cookie secrets.
2. Deploy Worker with WORKOS_ENABLED=true, WORKOS_BROWSER_ENABLED=false.
3. Deploy both Managers; configure regional origin Service Auth credentials and
   narrowly scoped Access policies. Preserve existing human and machine policies.
4. Verify a real callback and the exact existing PAX user/region. Verify Manager
   reads, cross-region admin denial, API key compatibility, refresh and logout.
5. Publish Console login/POST logout changes and switch canonical browser Access
   protection to the WorkOS gateway. Enable WORKOS_BROWSER_ENABLED only when
   both regional signed-identity paths work. Never bypass regional origin auth.

`npm run deploy` uses wrangler.browser.jsonc with keep-vars. Secret values stay
in Worker Secrets. Never commit or print them. The initial source configuration
intentionally leaves the browser cutover disabled. Update it when cutover is
actually completed. Other Worker deployment configurations still default off.
