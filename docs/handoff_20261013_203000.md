# Native user authentication correction

## Scope and boundaries

Issue 038 replaces the Android client's paxl enrollment model. Issue 037 remains
a historical transport resolution. Local client work is in sibling pax-clients;
this isolated worktree is codex/android-native-gateway. No Git push is authorized.

- native-client.ts verifies client-specific WorkOS RS256 JWTs, checks identity
  claims and provides bootstrap, logout and the existing narrow REST/SSE allowlist.
- WorkOS identity binding and directory assignment are reused from Web.
- Manager receives the existing signed user assertion plus server-only regional
  Cloudflare Access credentials. User-provided identity/cookies/tokens are not
  forwarded. No regional Access policy is relaxed.
- The existing registered /auth/callback relays native.android-prefixed states
  and single-use codes to one fixed app scheme. Android owns/verifies state and
  PKCE verifier; no token is placed in a redirect URL. Web cookie flow is unchanged.
- The native dispatcher rejects legacy paxl start/poll with 410. Legacy key
  resource routes remain for the installed client's own-key revocation.
- No generated Go artifacts changed; regeneration is not needed.

159 tests passed. The standard npm test command (including build and coverage)
also passed: 96.47 percent line coverage overall. Deployment preflight passed. Previous active version was
`e91fd9c2-53ca-40ec-b52e-4abe52ab526a`; deployed version is
`59e2dd0e-1ff9-4c61-b20b-50cac28a92a9`. The user had authorized native gateway
publication and continued integration. No new secrets or Access policies were
required. Rollback with wrangler rollback to the previous version restores the
old node-login semantics, so it also requires matching client rollback.

Live checks using the Android okhttp/4.12.0 User-Agent returned 401 for anonymous
native reads/bootstrap, 410 for both old regional login starts and 401 for
anonymous Web auth/session. Python's default UA receives edge WAF 1010 instead;
this does not describe the Android path. Existing authenticated Web account and
Claude test-session history loaded after deployment.

## Remaining acceptance

Pixel real-user PKCE callback, token refresh and physical fold/unfold need live
acceptance. JVM/Worker fixtures do not prove provider configuration or physical
layout. Android revokes its legacy key on upgrade but does not delete historical
offline node records by display-name matching. End-to-end encryption approval
is separate from login and is not bypassed by this change.

Android checks: 25 JVM tests, lint, three fixture UI flows and the real-network
anonymous/invalid-token/legacy-410 smoke test pass. Width transitions and keyboard
layout were visually inspected. AOSP Pixel Fold posture testing hit an emulator
invalid-display-mode fault; physical fold acceptance is still pending.
