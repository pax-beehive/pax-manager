# Bounded recovery from rejected Secretary output

## Scope and evidence

Issue [063](../issues/063-secretary-invalid-output-retry-loop.md) is fixed in the
current Manager scheduler and Secretary implementation. A metadata-only production
audit confirmed repeated validation of completed cached output without a fresh
run. A manually advanced single generation then published successfully. The
common errors were unsupported source references and missing literal quotes;
stale baseline evidence and independent-page receipts are additional code-proven
contract problems, not established causes of that production sample.

No production data, settings, jobs, or model calls were changed by this branch.
No Console, ES, public API, MCP schema, or board behavior changes are required.

## Boundaries and flow

1. Secretary validates input and baseline without classifying those errors as
   generated-output failures. Decoder, generated evidence, and requested-proof
   boundaries return a typed domain schema/evidence error. Wording can change
   without disabling recovery.
2. Manager maps only the exact typed HTTP 400 invalid-receipt error to a distinct
   domain proof-rejection marker. Other HTTP statuses, ownership/fence failures,
   and plain strings are preserved. Signatures, current access, exact content
   versions, pages, views, and literal quotes remain fully validated.
3. A matching leased job failure updates its error, backoff, and persisted retry
   budget atomically. It may increment retry_generation at most twice per
   fingerprint of canonical messages/removals, baseline revision, metadata,
   settings revision, source/owner, and input policy. Retry generation itself is
   excluded from that fingerprint. Stale or expired workers cannot spend retry budget or clear a current lease.
4. The next claim has a new deterministic execution ID and the safe enum feedback
   schema/evidence. It creates a fresh internal execution, rather than reading
   the rejected cached reply. Successful publication clears the budget alongside
   existing immutable summary/checkpoint commit. New canonical input has a new
   budget; explicit retry resets only inactive jobs.
5. After two failed fresh attempts, existing backoff continues to recover the
   last cached response and retain the error. Further automatic model calls stop
   for that unchanged fingerprint. Manual retry is an explicit new budget.

Memory storage mirrors PG. Incomplete/approval/no-output, source/baseline,
permission, transport, cancellation, and storage errors are not classified.
Only a persisted completed response over the output-size bound is classified;
an incomplete oversized stream remains ineligible for fresh generation.

## Prompt and independent receipts

The prompt keeps the baseline body and claims but omits evidence from changed or
removed messages. It asks the agent to copy actual source IDs and literal quotes,
correct rejected evidence, and keep valid JSON within the existing size limits.
Stored baseline facts and frozen source versions are not changed by this prompt
projection. Supplied user text remains full visible text; assistant text remains
the final paragraph with explicit tools for expansion.

A selected related source may be read using one receipt and quoted from another
page/view receipt. Recovery now reconstructs the second receipt only for a
selected exact version; ambiguous multiple versions require an exact version
reference or an existing selected receipt. The trusted read layer still checks
the receipt and actual exposed quote. Unselected sources remain rejected.

## Separate open runtime issue

Issue [064](../issues/064-secretary-stale-upstream-background-state.md) remains
open: three pending sources have old message activity but fresh upstream running
background snapshots. Two have a last visible completed event and none has a
queued turn. That is not authoritative native-idle evidence. This change retains
the idle gate and does not reset or automatically retry active background work.

## Schema and rollout

`db/secretary.sql` adds three non-null metadata columns with constant defaults:
`auto_retry_key`, `auto_retry_count`, and `last_validation_failure`. Existing
idempotent schema initialization applies the additive migration before workers
start. It does not scan/requeue historical sources or modify desired revisions.
There are no generated artifacts or interface signature changes; `make generate`
is unnecessary.

A deployment lets already eligible failed sources take their next ordinary claim
and fresh generation, subject to existing backoff (up to five minutes). No global
input-policy bump is used, so unaffected sources do not rerun. Existing invalid
cached receipts are first rejected by the typed verifier and then regenerated.
A later signing-key change can reject old receipts; no time-based expiry is
assumed by this fix.

The selected agent still has real model cost. The two-generation budget is per
unchanged input, not a global daily quota; source edits and explicit retry can
permit additional work. No automatic retry of incomplete or approval-pending
turns is introduced.

Full Go tests, build, formatting, normal and integration-tag lint all passed.
The final complete Secretary acceptance passed 421 checks with real HTTP/ACP/PG
and zero skipped tests, including the expired-lease regressions. New retry-classification/fingerprint/
failure and prompt-filter helpers have 100% unit coverage; independent receipt
selection is 91.7%, and the full Secretary package is 95.6%. Existing unrelated
package coverage is not claimed as coverage for the new code. Local verification
uses `GOWORK=off` and an isolated disposable PG schema/container, never production.
Required commands:

```sh
GOWORK=off make fmt-check
GOWORK=off make lint
GOWORK=off GOCACHE=/tmp/pax-manager-go-cache go test -count=1 ./...
GOWORK=off GOCACHE=/tmp/pax-manager-go-cache go build -o /tmp/pax-manager-secretary-retry ./cmd/manager
GOWORK=off make secretary-acceptance
```

Additional PG tests are selected by `^TestSecretaryValidationRetryPostgres` with
`PAX_MANAGER_SECRETARY_TEST_DATABASE_URL` pointing to an isolated test database.
They verify restart durability, capped generation increments, new input, manual
reset, successful reset, stale leases, settings disablement, and transient errors.
The real ACP regression uses fake model responses over the actual WebSocket
protocol; it does not call an external model.
