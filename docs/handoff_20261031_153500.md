# Manager search and Secretary integration

## Base and scope

This integrates feature commit `2cc6cd9` onto Manager `origin/main` at `ea14d96`.
The isolated integration worktree is `work/search-secretary-manager-pr`, branch
`codex/workspace-search-secretary`. Earlier feature contracts are documented in
`search_contract.md`, `secretary_automation.md`, and
`handoff_20261031_095037.md`.

The implementation retains the current main branch's WorkOS/regional identity,
notification delivery, transport journal retention, artifact display and native
session behavior. Search remains opt-in through `SEARCH_URL`; automatic
Secretary execution remains disabled until the owner saves enabled settings.
Canonical messages and their parts remain the source of truth. Summary versions,
source snapshots and per-message checkpoints retain their original contracts.

## Compatibility changes

- Application startup preserves notification and journal cleanup workers. Search
  and Secretary workers stop before the transport store closes. Search starts
  only after notification worker startup has succeeded.
- Configuration and memory storage combine the new search/Secretary fields with
  main's existing notification and journal fields. Schema initialization applies
  `init.sql`, `summaries.sql`, `search.sql` and `secretary.sql` in that order.
- The Thrift merge retains main's existing declarations and adds twelve feature
  structs and seven service methods. `make generate` uses main's
  `api/hz-package.yaml` template. New Hertz wrappers delegate to `HandleGenerated`
  and all seven names are present in the business handler bridge. A regression
  invokes the actual generated wrappers and verifies authenticated dispatch.
- Ordinary turn-completion push notifications exclude internal Secretary
  sessions by source marker or reserved session prefix, both during enqueue and
  final delivery authorization. Memory uses a completion-specific predicate;
  the shared predicate used by tool approval notifications is unchanged.
  Actionable manual tool approvals still notify the owner. Reduced notification
  test fixtures now include the existing production `agent_sessions.source`
  column.
- Secretary acceptance supplies its guarded disposable PostgreSQL URL to the
  notification fixtures as well. The gate explicitly requires suppression,
  queued-delivery authorization and manual-approval preservation scenarios.

There are no related local issue status changes. The original feature worktree,
retained preview and user data are not modified by integration verification.

## Verification

The generated-wrapper regression first returned 404 for all seven missing
bridges and passed after the bridge entries were added. Existing feature HTTP
and notification route regressions passed alongside it. Internal completion
notification regressions first reproduced unwanted delivery for both source
marker and reserved prefix, then passed after the completion-only exclusion.

Generation, formatting checks, the Manager binary build and all seventeen
Python adapter/runner guard tests passed. Formal Docker integration built the
actual Manager image and passed the integration suite in 2.475 seconds. Its
unique project and volumes were removed; the temporary override bound Manager

Repeat the backend checks from this worktree with:

```bash
export GOWORK=off GOCACHE=/tmp/pax-manager-go-cache
make generate
make fmt-check
make lint
go test -count=1 -coverprofile=/tmp/pax-manager-pr-unit.cover ./...
go build -o /tmp/pax-manager-pr-build-check ./cmd/manager
make secretary-acceptance
make search-acceptance
```

Both acceptance targets create isolated local databases and clean up their own
containers and volumes. Search acceptance also exercises a real deployed local
Manager, Elasticsearch and the stdio MCP adapter. Secretary acceptance exercises
HTTP, a synthetic agent over the actual ACP transport, PostgreSQL publication
and exact progress checkpoints. Neither target calls an actual user agent,
deploys remotely or starts the stopped local Secretary prototype.

For formal Docker integration, choose an isolated `INTEGRATION_PROJECT` and
unused Manager/MinIO ports, run `make integration-test`, then always run
`make integration-down` with the same values. The PR integration workflow also
runs both feature acceptance targets after cleaning the formal test stack.
