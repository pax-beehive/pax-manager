# Pi SDK upgrade integration

Pi CLI upgrades now restart managed Pi ACP connections through paxd's existing
harness.upgrade coordinator. Manager's request schema and forwarding are unchanged.
The browser fixture requires PI_ACP_SDK_ROOT and reports the selected Pi package's
version, so a CLI/SDK mismatch exercises automatic rollback. The Console script
covers both Pi CLI and ACP mismatches as well as successful upgrades and reload
recovery. All packages are isolated fixtures; no provider account is contacted.

Production requires @ccgv2/pi-acp >=0.7.0 and Node >=24. paxd binds the SDK package
behind the connection's pi launcher at every start. Explicit SDK roots remain
independent of global CLI updates. See paxd docs/harness-upgrade.md for details.

No generated files, API schemas, or issue statuses changed.

Validation commands (run with gvm Go 1.26 and Node 24):

- make fmt-check
- make lint
- GOWORK=off go test -count=1 ./...
- GOWORK=off go build -o /tmp/pi-sdk-manager ./cmd/manager
- PAXL_E2E_BROWSER_CHANNEL=chrome PAXL_E2E_CONSOLE_DIR=<console> PAXL_E2E_NODE_BINARY=<paxd-test-binary> HARNESS_E2E_PAXL_BINARY=<paxl> GOWORK=off go test ./internal/manager -run '^TestHarnessBrowserUpgrade$' -count=1 -timeout=6m -v

Build the node fixture with `go test -c -o <paxd-test-binary> ./internal/daemon`
in paxd, and build paxl with `go build -o <paxl> ./cmd/paxl` in paxl.

All listed checks passed on 2026-10-08. Browser E2E completed in 214.59s:
six successful CLI/ACP upgrades with reload recovery, plus Codex and Pi CLI/ACP
mismatches with confirmed restoration. paxd runtime/daemon/control/controlws
regression tests passed. The published @ccgv2/pi-acp@0.7.0 also passed the optional
paxd process-runner test across SDK switch and restore. Console component tests,
TypeScript, and scoped ESLint passed. Published-adapter validation uses fixture SDKs;
no model-provider calls were made.
