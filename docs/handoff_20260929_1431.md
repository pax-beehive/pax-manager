# KEV-66: latest generated E2EE pairing wins

## Behavior

For one `(agent_id, device_id, key_epoch)`, successfully creating B immediately
supersedes all earlier pairing requests, including completed A. A cannot be
completed or reactivated by retrying creation. Generating B preserves A's
published key package until B completes. Completing B atomically replaces that
package. Retrying the latest completed request returns the original saved
package, even when paxd supplies freshly randomized wrapping material or the
completion deadline has passed. This read-only retry does not renew expiry or
replace ciphertext. Expired incomplete requests cannot complete, and expiry
never reactivates an older request.

Different device IDs, agents, and key epochs remain independent. Root keys are
not rotated. The Manager continues to store only opaque wrapped key material.

## Implementation and request flow

- `domain/e2ee_keys.go` holds the internal supersession timestamp and distinct
  expired/superseded errors.
- `storage/e2ee_keys.go` owns the state transitions. The memory store uses its
  existing mutex. PostgreSQL creation and completion acquire the same
  transaction-scoped advisory lock for the agent/device/epoch before reading
  mutable state. Transaction lock order defines generation order, independently
  of client clocks or timestamp ties.
- Creation inserts a request and supersedes its predecessors in one transaction.
  Retrying an existing creation only returns its existing state; it does not
  supersede any other request or extend its deadline.
- Completion rechecks supersession under the lock, returns saved results for
  completed requests, or checks expiry and upserts the package before marking
  the request completed in the same transaction.
- Superseded requests are omitted from pending lists. Fetching a superseded
  request returns HTTP 409 with an actionable message. Expired incomplete
  completion returns HTTP 410 with a regenerate instruction.
- Both current user and node v1 completion endpoints use this storage path.
  No legacy agent API behavior is claimed. Existing paxd forwards the Manager
  error message, although its local outer error code remains `invalid_argument`.

## Schema and rollout

`db/init.sql`, applied by `EnsureSchema`, adds nullable `superseded_at` and a
device-scope index. Existing requests are reconciled by server `created_at`
(pairing ID breaks historical ties); all but the latest unsuperseded request
per scope are marked superseded. The migration is repeatable and retains
published key packages. Do not delete old pairing rows: package foreign keys
use `ON DELETE CASCADE`.

Ship the updated schema and Manager binary together. Drain older Manager
instances before relying on the new rule: older binaries do not observe the
supersession marker or participate in the advisory lock. Existing browser and
paxd request formats remain compatible. No Thrift or generated-code change is
required. The change has not been deployed by this task.

Coverage includes superseding completed and pending requests, preservation and
replacement of old packages, randomized completion retries, expiry boundaries,
creation retries, independent scopes, concurrent creation, both orderings of
creation versus completion, and repeated schema migration with existing data.

retries. The complete unit suite and Manager build passed. The real PostgreSQL
suite passed with the race detector, using a disposable PostgreSQL 17 container;
the container was stopped after testing. Formatting and both normal/integration
lint checks passed. The full suite was run outside the filesystem/network sandbox
because existing httptest servers require local listening sockets.
