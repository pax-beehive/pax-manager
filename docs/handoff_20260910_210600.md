# KEV-36 trusted proxy implementation

Historical implementation record. Production rollout completed on 2026-09-11;
see [the production handoff](handoff_20260911_002500.md).

## Change and boundaries

Client IP selection now checks the immediate TCP peer against
`TRUSTED_CLOUDFLARE_PROXY_CIDRS`. Configuration loads and validates explicit
CIDRs; an empty list trusts nobody. Security middleware uses the resulting
address for both general and registration rate limiting. Registration previews
use the same address and only read CF location headers from trusted peers.
X-Forwarded-For no longer selects client identity. User authentication and
Node Key authorization are unchanged; there are no schema or generated changes.

The HTTP test adaptor has no connection peer, so its registration preview test
now expects empty network metadata. Dedicated Hertz connection tests cover
trusted IPv4/IPv6 peers, mapped addresses, malformed headers, default denial,
separate trusted-client buckets and resistance to spoofing for both limiters.

## Deployment and rollback

This is a source change, not a production deployment. See
[trusted_proxy.md](trusted_proxy.md) for migration constraints. The current
shared Docker network must not be trusted wholesale; stabilize and isolate
connector addressing before enabling header trust. Keep loopback bindings and
existing Access validation. Preserve the old binary and environment for rollback.
An empty trust list is secure but aggregates proxied clients into one bucket.

## Audit context

Read-only host inspection found loopback-only application/database bindings.
Host-side tests rejected those ports through the host LAN address. Public
hostnames responded and the user API retained Access redirects. No independent
external-origin rejection test was completed. Privileged firewall and router
forwarding inspection remain outstanding. Local issue 017 is partial and
KEV-36 remains in progress.

## Verification

Go 1.26 was selected through gvm. Full `go test -count=1 ./...` passed
with local test-server sockets enabled. The first sandboxed run was blocked
from binding an IPv6 loopback test socket. Native and Linux static builds passed.
Changed production files and new tests pass gofmt, goimports and golines.
`make fmt-check` still reports existing files, including server_test.go where
only the legacy header-trust expectation changed. `make lint` reports the same
nine pre-existing findings (one errcheck, eight gocyclo), outside this change.
`git diff --check` passed.

The isolated PostgreSQL/object-storage integration suite passed using project
`pax-kev36-isolated`, Manager port 29879 and object-storage port 29000.
The legacy paxd-container case was skipped because no sibling checkout exists
in this isolated worktree layout. This does not verify production deployment.

Targeted security tests passed with `go test -race`. The isolated integration
containers, network and volumes were removed after verification.
