## Client changes

The actual SQLite producer wrapper now supplies the inbound cursor to replay.
Dispatch failures stop the batch, later frames cannot overtake missing input,
and a reopened database can retry the failed prefix in order. Inconsistent
received history or checkpoints fail closed without deleting records, changing
cursors, ACKing new input, or rotating the transport queue.

The forwarder drains worker stdout/stderr while replay writes stdin, reaps
workers on recovery failure, supports multiple process completion waiters, and
closes the websocket on cancellation to interrupt a silent reconcile. A real
worker descendant holding stdout open reproduced the cancellation hang before
the final three-line fix.

The ACP pool retains session creation correlation across websocket reconnects.
Only responses can consume it; failed durable binding does not consume the
correlation. Existing output callbacks can still lose a worker event if routing
or journaling fails before acceptance. The paxd recovery document records this
older limitation; boundary unit tests do not claim automatic callback retry.

  binding.
- Initialize, session creation and prompt were each dispatched exactly once.

The recorded acceptance run completed in 14.61 seconds. The helper README
documents reproduction. JSON relay assertions normalize whitespace, local API
commands use stdin to avoid Docker Desktop bind-file cache reuse, and the test
overrides any cached image DB-path setting. No installed daemon state is mounted.
