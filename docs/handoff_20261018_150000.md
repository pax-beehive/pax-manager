# Console-initiated harness authentication

## Behavior and boundaries

The new GET/POST node `harness/auth` routes check node access, derive actor_id
from the verified principal, and forward ephemeral commands/queries through the
existing node-control hub. Manager never starts vendor authentication or stores
codes, credentials or challenge history. Responses are no-store. The source IDL
is `api/pax_manager.thrift`; generated Hertz models/routes, handler service mocks
and OpenAPI were regenerated with `make generate`.

Console -> same-origin Next proxy -> Manager userapi -> authenticated node control
WebSocket -> paxd's attempt owner -> `paxl harness auth --protocol jsonl` -> selected
native CLI/SDK. Actor/source ownership and current prompt IDs scope attempt input.
Secrets are POST bodies, never URLs or durable command-journal entries. An ACK
acknowledges a start/input; final result plus process exit determines completion.

The GET route accepts a session_id or original start command_id to recover an
existing attempt without restarting it. A control disconnect or browser reload
leaves the owned child running. Daemon restart loses ephemeral attempts; callers
must explicitly start again after a not-found result. Provider methods/status
use the same paxl native boundary and retain configured/unknown semantics.

## Deployment and operations

Deploy the new paxl JSONL protocol first, then paxd delegation, Manager and Console.
Manager requires a successful version-1 capabilities probe before dispatching a
start; old executors are rejected without starting a legacy login.
Paxd resolves PAXD_PAXL_COMMAND through its existing executable resolver. A missing
protocol fails explicitly; there is no vendor-executor fallback. The scope is the
node's default OS/credential environment. Custom per-connection credential contexts
and automatic ACP restarts are not part of this change. TTY-only flows remain
local until the separately tracked PTY work; no slash command is sent as a model
prompt and no subscription flow silently changes to API billing.

## Validation

- Manager `go test -count=1 ./...` passed with temporary test state/listeners.
- Userapi tests cover node permission before dispatch and verified actor binding.
- Browser E2E uses real Console/Manager/paxd/paxl with fixture vendor CLI/SDKs.
  It checks native code input, SDK provider/method/secret prompts, reload and
  control reconnect, cancellation, no repeated native login, and absence of
  inputs from browser storage and daemon SQLite.
- See the PR validation for final format/lint/race results and any baseline
  findings. No real provider login/logout or installation was performed.

Build the node test helper with `go test -c -o /tmp/paxd-auth-e2e-node ./internal/daemon`
in the paired paxd worktree, and paxl with `go build -o /tmp/paxl-console-auth ./cmd/paxl`.
Run `TestHarnessBrowserAuthentication` with PAXL_E2E_CONSOLE_DIR,
PAXL_E2E_NODE_BINARY and HARNESS_E2E_PAXL_BINARY pointing to paired builds/worktrees.
Use PAXL_E2E_BROWSER_CHANNEL=chrome for an installed Chrome browser. All test
servers, fixtures and databases are isolated; production services are untouched.

KEV-92 remains partial for richer credential contexts/account pools. KEV-104
continues to track PTY fallback. This change does not mark either fully resolved.
