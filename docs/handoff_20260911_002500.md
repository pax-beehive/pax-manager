gateway `172.30.36.1`, dynamic pool `172.30.36.4/30`. cloudflared uses only
this network at static `172.30.36.2`, outside the dynamic allocation pool.
Manager is attached at `172.30.36.3` and retains `pax-manager_default` for
PostgreSQL. Console is attached at `172.30.36.4` and retains its original
network. Existing Tunnel destination names resolve on the dedicated network.

The protected Manager environment contains
`TRUSTED_CLOUDFLARE_PROXY_CIDRS=172.30.36.2/32`; both auth bypass flags remain
false. Manager, Console and PostgreSQL host bindings remain loopback-only.
Cloudflare routes and Access policies are unchanged. Manager was replaced and
cloudflared restarted; Console, PostgreSQL and paxd were not restarted.

The initial network attempt reverted automatically because the urllib health
probe received HTTP 403, including on the healthy original network. Curl got
HTTP 200. Correcting the probe completed the migration successfully.
