# Handoff 20260613 115532

## Summary

This change makes message delivery fully session-scoped while keeping explicit
agent-level routes for bootstrap and aggregate views.

The canonical user-facing route for an existing conversation is now:

```text
GET /api/user/agents/{agentId}/sessions/{sessionId}
POST /api/user/agents/{agentId}/sessions/{sessionId}/messages
GET /api/user/agents/{agentId}/sessions/{sessionId}/messages
```

The paxd-facing mailbox pull for a session-bound connection is now:

```text
GET /api/agent/sessions/{sessionId}/mailbox
```

The older agent-level mailbox pull and agent message routes remain available:

```text
GET /api/agent/mailbox
GET /api/user/agents/{agentId}/messages
POST /api/user/agents/{agentId}/messages
```

Use these for agent-wide polling, aggregate mailbox views, or bootstrap messages
before a session is known.

## Model

The operational hierarchy is:

```text
user -> agent -> session -> mailbox message
```

An agent belongs to one platform user. A session belongs to one agent. A user
message sent after a session exists must identify both the agent and session.
The service validates that the session belongs to the requested agent before
creating or listing messages.

## Module Boundaries

- `api/pax_manager.thrift` remains the transport contract source of truth.
- `internal/manager/userapi` owns user-visible agent, session, and mailbox
  authorization behavior.
- `internal/manager/paxd` owns paxd-facing mailbox pull behavior.
- `internal/manager/storage` owns SQL and memory persistence filtering.
- `internal/manager/idl_handlers.go` maps hz request models to service calls.
- `internal/transport/http/handler` and `internal/transport/http/router` are
  hz-generated transport glue with minimal manual path fallback and middleware
  hook code.

## Key Flows

User sends a message to a known session:

1. Cloudflare-authenticated user calls
   `POST /api/user/agents/{agentId}/sessions/{sessionId}/messages`.
2. The hz handler binds body fields and path params.
3. `internal/manager/userapi.Service.CreateSessionMessage` resolves the user,
   checks the target session belongs to the requested agent, and persists the
   mailbox message.
4. Persistence stores `agent_id` and `session_id` on the mailbox row.

paxd pulls messages for a session:

1. paxd calls `GET /api/agent/sessions/{sessionId}/mailbox` with its pax key.
2. `AgentAuth` authenticates the key and injects the agent into the Hertz
   context.
3. `internal/manager/paxd.Service.PullSessionMailbox` validates the session id
   and calls storage with both `agent_id` and `session_id`.
4. Storage returns only pending rows for that agent and session.

Websocket session-bound pull:

1. paxd connects with `session_id` during websocket bootstrap.
2. `pull_mailbox` websocket frames route through `pullWSMailbox`.
3. If the connection has a session id, the service uses the session-scoped
   mailbox pull. Otherwise it keeps the agent-wide fallback.


agent is injected into the context.

## Notes

- `GET /api/user/agents/{agentId}/messages` is an aggregate view.
- `POST /api/user/agents/{agentId}/messages` is for bootstrap or agent-level
  messages only.
- Flat user endpoints such as `/api/user/sessions/{sessionId}`,
  `/api/user/sessions/{sessionId}/messages`, `/api/user/message`, and
  `/api/user/mailbox` should not be exposed. User-facing APIs must stay under
  the `user -> agent -> session` resource hierarchy.
