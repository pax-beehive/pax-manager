# Secretary acceptance fixture runtime

## Diagnosis

Main CI run 42913861251 for commit 8c314eb passed normal Docker integration
and search acceptance, then hit the storage package's 300-second limit during
`make secretary-acceptance`. Image publication was skipped by its required
integration dependency. No Docker image compilation error was reported.

The storage package completed 205 top-level tests with 299.88 seconds of
aggregate elapsed time. Its final terminal-wake PostgreSQL subtest had run for
about 85 milliseconds when the package alarm fired. The stack was executing
schema creation in `secretaryPostgresFixture`, not waiting on a business lock.
The completed 131 PostgreSQL leaves had median duration 1.46 seconds.

Each fixture rebuilds the schema from init.sql, summaries.sql, search.sql and
secretary.sql. Additional regression cases pushed the cumulative fixture cost
over the fixed budget. Previous local verification did not run the exact full
Secretary acceptance command under the CI storage configuration.

## Change and boundaries

`tools/verify_secretary.sh` mounts `/var/lib/postgresql/data` on a 4 GiB tmpfs
for its uniquely named, disposable postgres:16-alpine container. That directory
is the image's PGDATA. The memory ceiling is allocated on demand. An observed
mid-run sample used approximately 588 MiB; this was not a peak measurement.

PostgreSQL fsync, full_page_writes and synchronous_commit remain enabled.
Tests, the 300-second package timeout, required test names and the no-skips
gate remain unchanged. The existing EXIT/INT/TERM cleanup removes only this
script's container and releases its memory-backed data directory. A stopped
container's data is not retained, as appropriate for this isolated fixture.

No application, API, SQL, schema, generated artifact, production deployment
or image-publishing workflow changes are included. Publication still requires
all CI gates. No merge or production deployment was performed.

## Verification

A controlled comparison of the same 18 terminal-proof scenarios passed with
both backends: the default container storage took 24.287 seconds, while tmpfs
with unchanged PostgreSQL durability defaults took 19.009 seconds. All 36
Memory/PostgreSQL leaves passed in each run. This is a local runtime comparison,
not a CI performance guarantee.

The exact full acceptance passed with:

```bash
GOWORK=off GOCACHE=/tmp/pax-manager-go-cache make secretary-acceptance
```

It reported 1342 named checks, including subtests, with no skips. Storage
completed all 233 top-level tests in 225.234 seconds; Manager and userapi took
12.679 and 1.206 seconds, and the separate worker package took 0.599 seconds.
These local timings are not a same-runner comparison with the failed CI run.
The script successfully removed its isolated PostgreSQL container.

Additional checks passed:

- `bash -n tools/verify_secretary.sh` and `git diff --check`.
- `make fmt-check`.
- `GOWORK=off make lint`, including integration-tag lint.
- `GOWORK=off GOCACHE=/tmp/pax-manager-go-cache go test -count=1 ./...`.
- `GOWORK=off GOCACHE=/tmp/pax-manager-go-cache go build -o /tmp/pax-manager-ci-fixture-build-check ./cmd/manager`.

The initial lint command without `GOWORK=off` rejected this isolated worktree
because the parent go.work lists other module directories. The corrected
module-scoped command passed. No backend implementation changed, so there is
no new backend coverage denominator.

GitHub CI still needs to validate the change on its runner. Issue 078 remains
partial pending that verification and main image publication. Existing issues
074-077 are outside this harness correction.

## Operational notes

The runner must have spare memory for the temporary PostgreSQL data and other
test processes. The CI workflow already stops the shared integration stack
before feature acceptance; search acceptance cleans up its own containers.
This change reduces fixture data disk I/O but does not eliminate the full
schema creation cost. Continued suite growth can require a separately reviewed
fixture lifecycle improvement. Do not hide a future regression by skipping
tests, disabling durability or bypassing image publication gates.
