# User-requested local file fetch (manager side)

## Summary

The console can ask the session node to share a local absolute-path file. The
manager relays a policy check and a fetch command over the existing node-control
tunnel. Accepted fetches go through the existing artifact publication pipeline,
and paxd's worker registers, prepares, uploads, and completes or fails them as
usual. Agent publish behavior is unchanged. The behavior scenarios are in
`docs/artifact_fetch_bdd.md`.

## Routes (manual Hertz routes, not thrift/hz)

```text
GET  /api/v1/user/:user_id/sessions/:session_id/artifact-fetches/check?path=<abs>
POST /api/v1/user/:user_id/sessions/:session_id/artifact-fetches   {"path":"<abs>"}
```

- Check, HTTP 200:
  `data:{allowed,path,filename,size_bytes?,denial?{code,rule,message}}`.
  When `allowed` is true, `size_bytes` is present and `denial` is absent. When
  it is false, `denial` is present and `size_bytes` is absent.
- Fetch accepted, HTTP 202: `data:{accepted:true,publication:<ArtifactPublication>}`.
  This is the same struct that `GET .../artifact-publications/:pid` returns.
- Fetch denied by paxd, HTTP 200: `data:{accepted:false,denial:{code,rule,message}}`.
  `rule` is the ack's `error.target`. No row is created.
- HTTP errors:
  - 400: bad path or body. The path is empty, not starting with `/`, longer
    than 8192 bytes, not valid UTF-8, or contains NUL/CR/LF.
  - 404: the session or agent is not owned by the user. A `:user_id` that is
    neither `self` nor the user also gets 404.
  - 409: the session is E2EE.
  - 503: the tunnel is missing, or the session has no node.
  - 504: timeout.
  - 502: invalid or inconsistent paxd payload, or a paxd error frame.

## Module boundaries

- `internal/manager/artifact_fetch_handlers.go`: handlers, target resolution,
  node-control call wrapper (`artifactFetchControlTimeout` = 10s), and strict
  decoding of the check result and the ack.
- `internal/manager/openapi_artifact_fetches.go`: OpenAPI entries for the
  manual routes, in the same style as `openapi_artifact_publications.go`.
- `internal/manager/domain`: `ArtifactPublication.Origin` (JSON `origin`),
  `RequestedByUserID` (not serialized), `RequestedPath` (JSON
  `requested_path,omitempty`), the `ArtifactPublicationOrigin*` constants, and
  `Store.MarkArtifactPublicationUserFetch`.
- `internal/manager/storage`: Postgres and memory implementations.
  `PutArtifactPublication` defaults an empty origin to `agent`.
- `db/init.sql`: three `ALTER TABLE artifact_publications ADD COLUMN IF NOT
  EXISTS` lines: `origin` default `'agent'`, `requested_by_user_id` default
  `''`, and `requested_path` default `''`.
- `artifact_publication_reconcile.go`: skips `user_fetch` publications, so they
  are never projected into the chat transcript.
- `validArtifactFilename` was extracted from the PUT normalizer and is shared
  with the ack validation.

## Flow

1. The handler authenticates with `userPrincipal`, checks `:user_id`,
   validates the path, and then calls `GetSession(principal, session_id)`.
2. `GetAgent(principal, session.AgentID)` must return an agent with
   `OwnerUserID == principal`. Team or admin access is not enough.
3. If `session.Transport == "e2ee"`, the handler returns 409. The manager sets
   this transport when the first encrypted agent command is stored (storage
   `markSessionE2EE*`). It is the same check that turn queue and session
   config already use.
4. The node is `session.NodeID`, or the agent's `NodeID` if the session has
   none.
5. Check sends query `{"type":"artifact_fetch.check","check_artifact_fetch":{"path"}}`.
6. Fetch generates `apub_<32 hex>` from crypto/rand and sends command
   `{"command_id":pid,"type":"artifact.fetch","fetch_artifact":{publication_id,agent_id,session_id,path}}`.
   - A rejected ack returns HTTP 200 with the denial.
   - An applied ack is accepted only if `result.artifact_fetch.publication_id`
     and `target_id` equal the pid and the filename is a basename. Otherwise
     the handler returns 502.
7. On an applied ack, the handler calls `PutArtifactPublication` with owner,
   node, agent, session, the ack's filename (trimmed, the same way the PUT
   handler trims), title `""`, status queued, and origin `user_fetch`. It then
   calls `MarkArtifactPublicationUserFetch`. Both orders relative to the paxd
   worker's PUT converge:
   - ON CONFLICT DO NOTHING plus the source comparison handles the overlap.
   - The worker's PUT never overwrites `origin`.
   - The mark only touches origin, audit fields, and `updated_at`.
   - paxd's worker always registers a user_fetch publication before it
     snapshots the file, so a fast snapshot failure (file deleted, now
     owner-only) reaches `/failed` only after the row exists. The worker's
     register usually wins the race against this handler's upsert.
8. Audit log line: `artifact fetch checked` and `artifact fetch requested`,
   with user_id, node_id, agent_id, session_id, path, publication_id, outcome,
   and denial_code. File content is never logged.

## Risks and gotchas

- The node-control hub allows one request per node at a time, serialized by a
  mutex. A slow paxd call can make a concurrent check or fetch wait and then
  return 504.
- If the ack is applied but the DB upsert fails, the handler returns 500.
  paxd's worker still registers the row, but with origin `agent` and no audit
  fields.
- Between the worker's PUT and the manager's mark, a poll can briefly see
  origin `agent`.
- Paths must start with `/`. Windows drive paths are rejected with 400.
- Postgres changes are covered by the schema text test and by code review. No
  Postgres integration test exercises the new columns.
- The paxd and console contracts are implemented as specified. paxd is being
  built in parallel, so verify end to end once both sides land.
