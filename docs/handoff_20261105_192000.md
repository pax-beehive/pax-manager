# Pax-owned MCP automatic approval

## Behavior and boundaries

Pax tools registered for a Manager conversation can run without an individual
manual approval, including the Secretary workspace lookup tools. This policy
also covers list_agents, ask, reply and publish_artifact; it is not limited to
read-only tools. Ordinary session approval mode remains manual unless it was
already explicitly configured otherwise.

The ACP middleware verifies the owning user, node, agent, current session,
active prompt and turn. It compares the exact per-session server name produced
by agentConversationMCPServerName and an explicit registry of Pax tool names.
OpenClaw receives no injected server through this path and is not treated as a
trusted match. Archived and E2EE sessions are excluded.

For an ID-only permission request, tool identity comes from the same active
turn's tool-call cache. Completed calls, mismatched turns and conflicting
identity fields do not qualify. With no explicit transport turn ID, an existing
active-turn cache match is required. CurrentCorrelation returns a defensive
copy so concurrent updates cannot alter a caller's snapshot.

Codex ACP labels MCP calls execute. Its dot-form title must agree with the
structured top-level rawInput.server and rawInput.tool; a shell call with an
MCP-looking title is insufficient. Unrecognized native permission options fall
back to the existing manual path instead of guessing a grant.

## Flow and modules

- acp_owned_mcp.go recognizes registered Pax identities and derives policy.
- acp_pipeline.go applies that policy before generic manual approval and reuses
  the existing create/decide/respond/record/history flow with allow_once.
- Approved records have approval_policy=pax_owned_mcp in their grant body.
- The original pending request is consumed, and only the approved response is
  published to live readers. Forwarding a pending request would still interrupt
  the manual Secretary reader, even after sending the native approval.
- Node/agent/session capability checks, job leases, owner-filtered PG reads and
  source validation remain in the existing MCP implementations.

No SQL migration, generated API change or paxd binary change is required.

## Actual adapter probes

The user authorized dedicated test conversations which called list_agents with
limit=1 and replied with the actual exposed names. Only their own tool metadata
was inspected; credentials and normal session bodies were not copied.

| Adapter | Observed native ACP title | Evidence |
| --- | --- | --- |
| DSCODE | mcp__pax-conversation-<suffix>__workspace_summaries | Earlier production permission and preceding tool_call; permission itself has only toolCallId |
| Hermes | mcp_pax_conversation_<suffix>_list_agents | Successful native tool_call/tool_call_update and reply in this test |
| Codex | mcp.pax-conversation-<suffix>.list_agents | Successful native call with kind=execute and rawInput server/tool/arguments |
| Claude Code Air | No tool invocation | Native prompt failed with Authentication required |

Codex exposes an underscore-normalized double-underscore name to the model,
while its ACP display title uses dots. Model-visible names alone are therefore
insufficient to determine the wire representation. A fallback Claude server
probe and OpenClaw probe were requested; they are not counted as successful
without a matching result. Gemini's single-underscore format was reviewed in
adapter source, not tested against an online Gemini agent.

## Rollout and remaining work

Build and deploy the Manager through the usual PR workflow. No data backfill is
required. After deployment, cancel any old native prompts waiting on revoked
capabilities through the normal owner-authorized cancellation path, then retry
only the intended source tasks using their current control revisions. Keep
processed checkpoints and prior summary versions.

This change prevents the known Pax-MCP approval interruption. It does not add a
general durable approval-wait lifecycle for arbitrary third-party tools, and it
does not fix disconnected model providers. Issue 067 stays partial; issue 069
tracks this approval defect and rollout.
