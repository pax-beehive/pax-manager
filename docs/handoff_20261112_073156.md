# Search access request lifecycle handoff

## Outcome and issue

Issue [082](../issues/082-workspace-access-request-lifecycle.md) is resolved in
source. Requests remain nonblocking. Agents can query an approval ID, keep doing
independent work, or cancel. No runtime wait/resume mechanism was added.

`timeout_seconds` defaults to 600 and accepts 0 through 86400. Zero disables only
the pending time deadline. Approved grants have a separate 24-hour fallback
lifetime; turn completion, failure or cancellation still fences all access.

## Interfaces and boundaries

- `workspace_request_access` / wire `request_access` returns the existing ID,
  turn and scope, plus status/deadline and a pending poll suggestion.
- `workspace_access_status` / `access_status` reads only the caller's node,
  agent and session request. It can report a finished turn as expired without
  reviving authorization. Status polling never renews or creates a request.
- `workspace_cancel_access` / `cancel_access` idempotently revokes pending or
  approved access, including the race where approval wins just before cancel.
- States are pending, approved, denied, expired and cancelled. Denial remains
  terminal after its original pending deadline. Explicit reapplication after
  expiry/cancellation can create a new ID, subject to the per-turn record cap.
- The Manager request fingerprint uses turn, normalized scope and timeout;
  absolute deadlines are excluded so retries cannot extend them.
- Node approval reads translate IDs to native aliases. Status re-reads through
  canonical session filters before accepting an approval ID.
- User decisions check the Manager-dispatched active turn. Memory and PostgreSQL
  stores reject cancelled/expired requests. PostgreSQL takes the approval row
  lock before reading its clock and deciding, preventing stale approval from
  extending a turn expiry or undoing a cancellation.
- Notification delivery excludes revoked requests. Console session/Home cards
  exclude revoked and expired workspace requests; the session panel removes
  controls at the nearest finite deadline. No timeout setting was added to the
  next-turn preauthorization editor.
- New tools join the exact session-bound owned-MCP execution allowlist. This
  trusts execution of the helper, not workspace data; data checks remain in
  Manager. Secretary's existing separate tools and capabilities are unchanged.

## Source and rollout

- Manager: work/access-requests-manager, main base 91a9dea.
- paxd: work/access-requests-paxd, PR https://github.com/pax-beehive/paxd/pull/116.
- Console: work/access-requests-console, PR https://github.com/pax-beehive/pax-console/pull/253.
- No database migration, IDL or generated transport change is needed. The existing
  workspace/tools envelope carries two additional operation names and JSON args.
- Upgrade Manager before paxd. Console filtering is compatible with existing
  fields. A new/reloaded MCP helper is required to expose the new tool names;
  running helper processes retain their compiled tool list.
- No production deployment, agent restart or credential change was performed.
  Existing user checkouts and their local changes were preserved.

## Validation

Manager commands use an installed compatible toolchain selected through gvm:

```sh
source "$HOME/.gvm/scripts/gvm"
gvm list
gvm use go1.26
export GOWORK=off GOCACHE=/tmp/pax-manager-go-cache
make fmt-check
make lint
go test -count=1 ./...
go test -race -count=1 ./internal/manager ./internal/manager/storage -run 'TestWorkspace(Request|Access|ApprovalStorage)|TestPostgresWorkspaceApproval|TestApprovalNotification|TestPaxConversationToolName|TestOwnedMCP'
go build -o /tmp/pax-manager-access-requests-build ./cmd/manager
```

paxd targeted cmd/paxd and internal/cloud tests and build passed. Console's six
approval-panel tests, 56 Home tests (one skipped), full TypeScript and changed
file lint/format checks passed.

Local PostgreSQL-specific tests were skipped: the Docker engine was unavailable
and no database container was created. Existing CI config provisions isolated
PostgreSQL via PAX_NOTIFICATIONS_TEST_DATABASE_URL and runs the shared Memory/PG
contract and locked-row expiry/cancel regressions. Confirm that CI passes before
merging; do not treat local skipped PG cases as database verification.
