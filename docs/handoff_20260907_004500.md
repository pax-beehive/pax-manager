# Session command catalog persistence

## Behavior

New plaintext ACP `available_commands_update` notifications replace the
session's durable command catalog. Existing journal/history rows are not
backfilled. An empty advertised array clears the catalog; absent, null,
malformed, or duplicate-name advertisements do not replace it.

The existing authorized session configuration GET returns an optional
`commands` object containing `available_commands` and `observed_at`. Until an
advertisement is received, this field is absent. Command objects are preserved
as JSON, including input specifications, `_meta`, and unknown extension fields.

## Boundaries and flow

- `session_commands.go` observes agent-to-user frames after session identity
  normalization in both existing ACP pipelines.
- `domain/session_commands.go` defines the snapshot and persistence contract.
- Memory and PostgreSQL stores update only `metadata.acp_commands` on the
  matching agent/session. Config and permission metadata remain independent.
- PostgreSQL already stores session metadata in JSONB. No schema migration or
  new table is required.
- `session_config.go` reads the snapshot from durable session metadata.
- The hand-maintained configuration OpenAPI description documents the field.
  No generated transport code, IDL, or generated mocks changed.

The Console change uses its existing configuration query and 10-second polling.
It displays slash completion, descriptions, and input hints. Selection only
fills the draft; prompt execution and running-turn queue behavior are unchanged.
The Console does not interpret `_meta.commandAction`. E2EE sessions do not
publish plaintext catalogs to Manager or use this completion path.

## Rollout and limitations

Deploy Manager before paxd and Console through the existing deployment workflow.
These workspace changes have not been deployed.
Local development remains `make run-memory` for Manager and `pnpm dev` for
Console, with the documented same-origin proxy configuration.

ACP has no standard active command-list query. Configuration force-refresh
still reapplies config values and does not explicitly request a command list.
Newly observed catalogs reach the UI on the next configuration fetch. Old
sessions acquire a catalog only if the agent sends another advertisement.
A PostgreSQL-backed end-to-end deployment was not exercised in this change.

## Resume audit and input coverage

The local paxd log records a successful cold resume at 2026-09-06 17:10:25
America/Los_Angeles for native session 01a07924-a2d7-70c3-9bb4-9ceacea8f104.
Transport journal row 484484, at 2026-09-07T00:10:25.300249Z, contains a fresh
available_commands_update with 38 commands for its Manager session
sess_9e47a0a05f268aac9e43236d33b3efda6d050f663b594810. No config_option_update
appears in the surrounding 00:10:20-00:10:30 UTC window. Thus old sessions can
acquire a commands snapshot on a later resume without any historical backfill.

The cold-resume result loss is now fixed. `resumeColdRoute` returns the original
agent result after successfully binding the route. Explicit unknown-route
resume replies preserve that result and the caller's request ID. Automatic
cold resume emits `_pax/session_resumed` before forwarding the pending session
operation when configOptions or legacy models are present. Its params contain
sessionId and the complete result. Internal paxd request IDs are not forwarded.
The normal reliable output boundary maps native to Manager session identity.

Manager observes this agent-to-user notification after ID normalization and
stores config/model state with source `session/resume`. The existing config
GET exposes it together with the independently persisted commands snapshot.
The Console ignores the notification as chat content and uses its existing
configuration query. No new database schema, HTTP route, or generated code is
needed. Empty resume results do not invent a config observation.

The Console follow-up covers the queued-message editor and reuses the shared
input for Home's new-session draft. Home's existing-session view and the
standalone Session page already share SessionWorkbench. A not-yet-created
session has no catalog; the first advertisement is available after session
initialization. E2EE diagnostics and inquiry/envelope forms are separate.

The queued-editor regression also verifies completion does not submit the main
draft. Edit/delete icon buttons now have explicit accessible labels.
