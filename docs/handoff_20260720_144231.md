# Handoff: Durable Session History and PostgreSQL Payload Safety

## Summary

This change makes long-running session history safer and cheaper to read, and
prevents ACP/reliable-transport payloads containing PostgreSQL-incompatible
text from failing persistence.

## API and storage changes

- Adds `GET /api/v1/user/{user_id}/sessions/{session_id}/history`, which
  resolves the owning agent from the authorized durable session instead of
  trusting a caller-selected agent ID.
- Adds keyset pagination through `before_id` and returns
  `pagination.next_before_id` plus `pagination.has_more`. Pages contain the
  latest matching messages in chronological response order.
- Keeps the existing agent-scoped history endpoint for compatibility and uses
  the same pagination behavior there.
- Loads message parts in one batched query and adds an index on
  `(agent_id, session_id, id DESC)` for the history access pattern.
- Normalizes invalid UTF-8, NUL characters, and lone JSON surrogate escapes
  before writing message parts, envelopes, session reports, and reliable
  transport journal frames to PostgreSQL. Sanitized transport frames carry
  metadata indicating that replacement occurred.

## Compatibility and rollout

- The new session-only history route is additive.
- Existing history clients that omit `before_id` continue receiving the latest
  page, now with pagination metadata.
- The schema change is an additive index created with `IF NOT EXISTS`.
- Sanitization replaces unsupported text with Unicode replacement characters;
  it does not mutate the caller-owned reliable frame.
