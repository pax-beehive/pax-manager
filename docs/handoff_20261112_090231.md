# Queued and Steered Turns With Attachments Handoff

## Summary

Queued turns (`POST .../turn/queue`) and steered turns (`POST .../turn/steer`,
which queue a prompt and stop the running turn) can now carry user
attachments, like a normal conversation send. Before this change a queued
turn held only text, so the console blocked queue and steer while files were
attached.

## Request Shape

Both endpoints accept the conversation request shape:

```json
{
  "input": "optional text",
  "content": [
    { "type": "text", "text": "more text" },
    { "type": "attachment", "attachment_id": "att_..." }
  ],
  "search_access": { "...": "..." }
}
```

- Text from `input` and text blocks is joined with blank lines.
- Attachment blocks are deduplicated. At most 20 are allowed
  (`domain.MaxQueuedTurnAttachments`).
- A prompt may be attachments only. A prompt with neither text nor files is
  rejected with 400.
- `PATCH .../turn/queue` still edits only the text and keeps the queued
  files. Attachment blocks on PATCH are rejected with 400.
- `GET` and `PATCH` responses include `attachments`: a list of
  `{attachment_id, filename, content_type, size_bytes}`, never null.
- Queue `POST` and steer responses echo the stored `attachments`. An older
  Manager silently ignores `content`, so the console uses the missing field to
  detect it and refuses to drop files.

## Flow

1. Queue or steer authorizes the files for the caller and localizes them on
   the agent node before storing the turn (`Service.queuedTurnAttachments`,
   bounded by one minute). A foreign or missing file returns 404, an
   unfinished upload returns 409, and a localization timeout returns 504.
   Nothing is queued on failure. For steer, the files are local before the
   running turn is cancelled.
2. The queue row stores a metadata snapshot for display.
3. When a snapshot shows the session idle and the turn is claimed,
   `Service.queuedTurnPrompt` authorizes the files again for the turn owner,
   re-localizes if the node lost them, and sends `resource_link` blocks after
   the text (the same as `resolveConversationPrompt`). If the files are
   unavailable at that point, the turn is marked `uncertain` and not sent as
   text alone.
4. `ClaimQueuedTurn` compares the stored attachments as well as the input, so
   a turn whose files changed after it was read cannot be claimed.

## Schema

`db/init.sql`, applied idempotently at startup:

- `session_turn_queue.attachments JSONB NOT NULL DEFAULT '[]'`. It is in
  `CREATE TABLE` for fresh databases and in `ADD COLUMN IF NOT EXISTS` for
  existing ones.
- The inline `session_turn_queue_input_check` (input 1 to 65536 bytes) is
  dropped and replaced with `session_turn_queue_prompt_check`: input at most
  65536 bytes, attachments is an array, and the prompt has text or files.
  Both changes use the existing `DO $$ ... pg_constraint` pattern.

Rolling deploys work in both directions. Old code never writes empty input
and ignores the new column; new rows default to `[]`. The generated DAL
(`make gorm-gen`) does not include this table, so nothing needs
regeneration.

## Verification

```bash
make fmt-check
make lint
GOWORK=off GOCACHE=/tmp/pax-manager-go-cache go test -count=1 -race ./internal/manager/ -run 'Attachment|ConversationTurnQueue|QueuedTurn|TurnSteer'
PAX_MANAGER_QUEUE_TEST_DATABASE_URL=postgresql://... go test -count=1 ./...
GOWORK=off GOCACHE=/tmp/pax-manager-go-cache go build -o /tmp/pax-manager-build-check ./cmd/manager
```

The Postgres queue tests ran against a local `postgres:17` container. The
schema was also applied to real PostgreSQL 17 in two ways:

- main's `init.sql`, then this branch's: the old constraint is dropped, the
  new one is added, and the column defaults to `[]`;
- this branch's `init.sql` twice on a fresh database, to confirm it is
  idempotent.

New tests:

- `conversation_turn_queue_attachments_test.go`: queue with files, edit
  keeps files, attachments-only prompt, rejection cases, steer with files
  (the first steer handler test), resource links on dispatch, and the
  unavailable-file case;
- `exerciseTurnQueueAttachments`: memory and Postgres stores.

## Risks

- Queue and steer requests now wait for localization when files are
  attached, as a normal send already does, for up to one minute.
- E2EE sessions still cannot queue, unchanged.
