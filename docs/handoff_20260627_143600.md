# Team Shared Agent Access Handoff

## Summary

This change connects `team_agents` to the user-facing agent access path. A user
can access an agent when either they own the agent or they are an active member
of an active team where that agent is actively shared.

The change keeps node ownership and node-authenticated behavior unchanged.
Shared access applies to user-facing agent, session, conversation, tunnel, and
mailbox-message paths that already authorize through agent or session lookups.

## Module Boundaries

- `internal/manager/storage` owns the shared-agent access predicate for both
  in-memory and Postgres stores.
- `internal/manager/userapi` keeps route validation and delegates visibility to
  storage. Node-scoped user paths now validate the agent's `node_id` instead of
  requiring direct node ownership.
- `internal/manager/conversation.go` and `internal/manager/acp_tunnel.go`
  continue to authorize through `store.GetAgent`, so shared agent access flows
  into conversation and ACP tunnel handling without separate route logic.

## Access Flow

Agent access is granted when:

1. `principal.User.UserID == agent.owner_user_id`, or
2. `team_agents` has an active row for the agent, the team is active, and the
   principal has an active `team_members` row in that team.

Covered storage methods:

- `ListAgents`
- `GetAgent`
- `ListNodeAgents`
- `CreateNodeAgentSession`
- `ListAgentSessions`
- `GetSession`
- `ListSessionMessages`
- `CreateMailboxMessage`

## Preserved Boundaries

- `GetNode` and node ownership remain owner-scoped.
- Node-authenticated paths remain tied to the authenticated node.
- Agent/node creation still requires direct node ownership.
- Team members get access to shared agents, not full access to the owner's node.

## Verification

Commands run:

```bash
GOCACHE=/tmp/pax-manager-go-cache go test -count=1 ./internal/manager/storage
GOCACHE=/tmp/pax-manager-go-cache go test -count=1 ./internal/manager/userapi
GOCACHE=/tmp/pax-manager-go-cache go test -count=1 ./internal/manager
```

## Known Follow-Ups

- Generated OpenAPI/Thrift descriptions still do not include the hand-written
  team API routes.
- Rich team-agent cards for frontend display may still need more denormalized
  agent/node status fields.
- Team-scoped audit events are not implemented in this change.
