# Owner summary result browser

Issue 061 is resolved by exposing existing persisted results to ordinary owners.
No source model, summary table, background job or enable-setting behavior changes.

## Boundaries and flow

- Thrift defines `ListSecretarySummaries` at
  `GET /api/v1/user/:user_id/secretary/summaries`.
- The Manager handler validates cursor/limit and delegates to `userapi`.
- `WorkspaceSearchService` resolves the authenticated owner, applies an
  eight-second deadline and requests `SummaryRecentBrowserStore` pages.
- Memory and PostgreSQL implementations select each summary's current revision,
  order by revision creation time and ID descending, and reuse existing complete
  source visibility validation before returning any title or preview.
- The recent-list cursor is version 2 and owner-bound. Existing developer
  endpoints keep their administrator checks and version-1 cursor behavior.
- Full bodies, claims, exact source snapshots and child summaries use the
  existing owner-scoped `search/read` endpoint. This feature adds no duplicate
  read path or Elasticsearch dependency.

## Generation and deployment

Run `PATH="$HOME/go/bin:$PATH" GOWORK=off make generate` after changing
`api/pax_manager.thrift`. Hertz transport files and Manager OpenAPI artifacts
are generated; do not edit them directly. The optional browser-store interface
does not alter existing mockery interfaces. No database migration is required.
Deploy Manager and the corresponding Console summary-results page together.

owner/cursor isolation, current source visibility, database failures and real

  -o /private/tmp/pax-manager-summary-reader-build ./cmd/manager

Targeted ordinary Go unit coverage is 100% for the new HTTP handler, service,

Eight summary browser/recent-list tests passed against a dedicated temporary
PostgreSQL 16 container, including all three real database scenarios. The
container and its volume were removed afterward. These checks use deterministic
fixtures and do not call a model or inspect production data.

## Limits

The list includes all current owned summary subjects, including manually
published or higher-level summaries. It does not invent session metadata from
subject IDs. Source links resolve actual message metadata with the existing read
API. Pages bound candidate count rather than guaranteeing a full page after
permission filtering; clients must allow loading a next cursor on an empty page.
Concurrent summary updates can move results ahead of a previously issued cursor.
