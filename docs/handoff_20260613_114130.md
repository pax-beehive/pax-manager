# Handoff 2026-06-13 11:41:30

## Change Summary

The user-facing API was tightened around a REST resource model:

- A user owns many agents.
- An agent owns many sessions.
- An agent is also the parent resource for user-created mailbox messages.
- Session-scoped message reads remain available for drill-down views.

This route list is superseded by `docs/handoff_20260613_115532.md`. The current
user-facing routes are nested under the `user -> agent -> session` hierarchy:

- `GET /api/user/agents`
- `GET /api/user/agents/{agentId}`
- `GET /api/user/agents/{agentId}/sessions`
- `GET /api/user/agents/{agentId}/sessions/{sessionId}`
- `GET /api/user/agents/{agentId}/messages`
- `POST /api/user/agents/{agentId}/messages`
- `GET /api/user/agents/{agentId}/sessions/{sessionId}/messages`
- `POST /api/user/agents/{agentId}/sessions/{sessionId}/messages`

Flat user endpoints such as `/api/user/sessions/{sessionId}`,
`/api/user/sessions/{sessionId}/messages`, `/api/user/message`, and
`/api/user/mailbox` are intentionally not exposed.

## Implementation Notes

- `api/pax_manager.thrift` now defines `GetAgentRequest`,
  `CreateAgentMessageRequest`, `ListAgentMessagesRequest`, and `AgentResponse`.
- Hertz router and model code were regenerated with `make generate`.
- The new generated handler stubs were wired to the injected service, matching the
  existing project pattern for generated Hertz handlers.
- `userapi.Store` and `domain.Store` now include `GetAgent`.
- Memory and Postgres stores implement tenant-aware `GetAgent`.
- The user API service exposes `GetAgent` and keeps tenant isolation in the store
  boundary.
- User-facing create-message tests and integration helpers now use
  `POST /api/user/agents/{agentId}/messages`.
- User-facing mailbox-list tests now use
  `GET /api/user/agents/{agentId}/messages`.

## Transport Edge Case

The local `net/http` test adapter does not always expose Hertz path params the
same way as the real Hertz server. The adapter now injects an internal
`routeAgentID` value parsed from the original `http.Request.URL.Path`. Runtime
Hertz requests still use the normal `ctx.Param("agentId")` path first.

For `POST /api/user/agents/{agentId}/messages`, the manager also merges missing
message fields from the JSON body because hz body binding can be sensitive to
mixed path and body annotations. The path agent ID remains authoritative.
