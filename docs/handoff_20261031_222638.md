# Administrator summary inspection

## Scope and status

Added read-only administrator endpoints for browsing current owned summaries and
reading full current or exact historical revisions. Console consumes them from
`/admin/summaries`. The backend implementation and local SQL/HTTP verification
are complete, including local Console browser verification. Production deployment
is not claimed by this handoff.

The current authenticated principal must have `IsAdmin`, but ownership remains
strictly limited to that user's records. The feature does not add cross-user
administration, generate summaries, change source access, or depend on ES.
No existing issue changed status in this feature.

## Module boundaries and flow

1. The two GET routes are declared in `api/pax_manager.thrift`. Handwritten
   transport functions in `internal/manager/summary_browser_handlers.go` parse
   pagination limits and duplicate-free queries, then delegate to the user API
   service.
2. `userapi/summary_browser.go` resolves the current principal, checks `IsAdmin`,
   and passes only that user's owner ID to storage. The existing workspace source
   service retains normal authentication and error behavior.
3. `domain/summary_browser.go` defines a separate `SummaryBrowserStore` interface
   and lean list DTOs. Existing summary-publication interfaces and mocks do not
   expand.
4. PostgreSQL lists at most `limit + 1` current summary refs in ID order within a
   repeatable-read transaction, then reuses `getSummaryTx` and its recursive
   current source-access checks before constructing each visible list item.
   Hidden candidates do not return a title or body preview. Pagination can return
   an empty page with a continuation cursor.
5. Detail reads reuse `SummaryStore.GetSummary`, preserving immutable revision
   structure and exact pinned message/child-summary references. Current source
   visibility still applies to historical revisions.
6. `db/summaries.sql` adds only an idempotent owner/summary/revision browse index.
   Existing tables, summary bodies, source snapshots, and processing checkpoints
   are unchanged.

See [developer_summaries.md](developer_summaries.md) for the exact endpoint/DTO
contract, limits, status codes, cursor behavior, and deployment requirements.

## Operational notes

Deploy the matching Manager and Console changes to expose the page. Manager
must include the complete `db/` directory for normal index initialization.
This browse path does not require a search query, index synchronization, or an
available Elasticsearch process. It reads only summaries that already exist;
an empty list does not itself schedule Secretary or diagnose its configuration.

The browser does not impose an independent summary identity or cursor length
limit, matching the existing unbounded identity publication contract. Existing
HTTP transport limits still apply. Regression tests cover 513-byte and 5,000-byte
identities, generated cursors longer than 2,048 bytes, and long detail routes.

Pagination uses summary identity ordering rather than update time or search
rank. There is no total count, session filter, or cross-user owner selector in
this MVP. The existing recursive summary dependency budget and source deletion
rules remain in force. PR creation and production delivery are separate from the
local verification recorded here.
