# Secretary bounded batches, compact input views, and exact-turn reads

## Behavior and module boundaries

Storage previously applied the 64-message cap to raw dirty events. The planner
now pages raw message state using a revision/message-ID cursor and filters
canonical roles/types before full source loads. It accumulates actual changed
visible text up to the existing 64-message or 128 KiB bound, or the removal
bound. The shared batch helper preserves version, owner, session, and byte
checks in PostgreSQL and MemoryStore.

Raw scanning is bounded to 1,024 changes per claim in pages of 128. The SQL
candidate flag is an optimization only; full canonical source visibility still
governs included messages. Previously processed messages that disappear or
become hidden generate removals. Skipped/unchanged events advance through
revision, but an unconsumed visible message stays outside the checkpoint.
Invisible-only windows advance state without model execution.

## Merge and rollout

PR 214 targets the recovery/list/progress branch from PR 213. To merge this set
in one release, merge PR 214 into that branch first, then merge PR 213 into main.
The independent cookie-preservation PR 215 can follow. There is no mandatory
two-deployment safety boundary: owner checks, settings/lease fencing, source
versions, and transactional publication remain enforced throughout.

The compact input policy is explicitly versioned in RunID. Deploying it retires
pre-compact execution identities even when message contents are unchanged.
Batch filling can also change the input set and execution identity. Pending old
completed outputs may therefore require new model calls after this release;
do not promise recovery of every previously generated result. This also applies
to other users who have kept Secretary enabled. Disabling/re-enabling Secretary
already changes SettingsRevision and RunID independently of this change.

Identical retries under the new policy, settings, and batch retain their RunID.
No live job updates, inference calls, database DDL, or deployment were performed
as part of preparing these PRs.

## Validation

Regression-first tests cover fragmented inputs, raw scan bounds, skipped-event
checkpoint progress, bounded removals, byte limits, and stable retry identity.
Real isolated PostgreSQL checks verify canonical-only coverage and publication,
and continuation after an invisible-only 1,024-event window. Standard backend
formatting, lint, ordinary tests and build results are recorded in the PR.
Batch planning needs no new route or generated artifact. The turn-read addition
below includes optional turn metadata in existing read responses.

## Exact-turn reads and compact default projection

The same PR adds optional turn_id and view to Secretary workspace_history,
using the already implemented turn-filtered history service. Read responses carry
real turn_id metadata; source hash and canonicalization version remain tied to
the complete visible message. Each message is still paginated at 16,384 Unicode
code points, with has_more/next_offset and its receipt; use workspace_read to
continue that full view. Scope checks exclude other sessions, other turns, tools,
reasoning, and ungrouped rows when an exact turn is requested. Historical refs
without turn metadata remain ungrouped, and the ES record projection is unchanged.

Issue 059 is implemented using the existing last-view meaning from the
prototype and read API: full user text and the last natural paragraph of each
assistant message. This is not a transport part or the final complete reply of a
turn. The user-facing progress update states this assumption explicitly.
workspace_history can expand a named turn; workspace_expand can expand a named
message. The runtime MCP schema update is in paxd PR 108.

Message hashes and snapshots still identify complete canonical visible text.
Coverage freezes all included message versions, while claim quotes must occur
in exposed prompt text or in an exact, verified source read. Completed responses
with own-delta expansion receipts reverify those reads before evidence binding.
The model text budget remains 128 KiB; a separate 8 MiB canonical-source budget
and a SQL serialized-load guard bound full source material before transfer.
InputPolicyVersion prevents reinterpreting a pre-compact execution as a new-view
execution. The implementation was transferred from reviewed commit 790d6d5;
its earlier 343 isolated HTTP/ACP/PostgreSQL checks passed without skips.
