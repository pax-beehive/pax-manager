# Turn-scoped search authorization handoff

## Outcome

Ordinary agents can search their own sessions by default during a turn prepared
by Manager. Each search declares an explicit agent/session scope, and wider
ranges require an approved query/agent/session scope. Users can preauthorize before sending a prompt;
explicit PAX auto approve approves expansion requests immediately. It does not
automatically expand the default own-agent range at turn start. Mid-turn expansion
requests are asynchronous and do not pause ACP execution. Authorization records
are retained; no per-search audit facility was added.

The full API, scope, lifetime, and rollout contract is in
[turn_search_access.md](turn_search_access.md).

## Boundaries and flow

- `domain/workspace_access.go` validates complete-query allowlists and session
  and agent scopes. `*` is an authorization sentinel, not an ES query wildcard.
- Ordinary search requires `scope.agent_ids` and `scope.session_ids`; `self`
  resolves to the calling agent. ES and PG both enforce agent attribution,
  including grouped queries and pagination. Wider scopes are rejected explicitly
  rather than silently narrowed. Responses include their actual scope.
- `workspace_access.go` resolves node/agent/session ownership, current turn,
  approval, and source scopes. It rechecks authorization before returning data.
- `conversation.go` prepares authorization before dispatch. Queue and steer
  preserve the explicit scope until their actual dispatch.
- `workspace_access_lifecycle.go` expires records on successful/failed prompt
  responses. Cancellation expires before sending cancel. Internal missing-route
  recovery keeps the business turn's authorization; an unrecoverable dispatch
  error expires it.
- `storage/workspace_access.go` expires only matching workspace approval records.
- `session_turn_queue.search_access` stores one-shot preauthorization as JSONB.
  The idempotent schema upgrade is included in `db/init.sql`.
- `nodepolicy/routes.json` is shared with the machine gateway allowlist.
- paxd exposes `workspace_search` and `workspace_request_access` to ordinary
  sessions and performs a fresh Manager call for every invocation.
- Console carries one-shot scopes through first prompts, ordinary sends, queue,
  edits, and steer. Its separate pending-approval panel never invokes ACP resume.

## Security choices

- Data access is separate from native approval to execute an owned MCP tool.
- Only explicit `pax:auto_approve` enables automatic data grants. Agent-created
  sessions with implicit automatic tool approval cannot obtain them that way.
- A collaborator's ability to run a shared agent does not authorize searches
  of the agent owner's workspace. Turn preparation checks the initiating owner;
  queue edits retain the actual editing user as their initiating identity.
- A node snapshot cannot register a trusted turn. Registration is established by
  the Manager prompt path and disappears on Manager restart.
- Turn-end fencing and record creation share a lock. Creation racing with expiry
  cannot leave a newly approved record valid after the turn ends.
- The current process-local turn registry requires routing to the Manager that
  owns the turn, like existing Secretary capabilities. Shared multi-instance
  authorization is not implemented.
- Ordinary grants expose search snippets only. Source read/expand/history tools
  remain unavailable until their own grant enforcement is implemented.
- Secretary's execution-scoped capability and tool set are unchanged.
- Encrypted sessions cannot use Manager-owned turn grants.

## Deployment

This change does not deploy services. Deploy both regional Managers
and the machine gateway allowlist before the updated paxd and Console. Existing
node credentials are not changed. A Manager restart invalidates ongoing ordinary
turn access; starting a new authenticated turn establishes fresh authorization.
