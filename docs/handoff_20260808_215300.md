# Session transport marker handoff

## Summary

Agent sessions now expose a durable `transport` field. Existing sessions default
to `manager`; creating or replaying an encrypted agent command marks the matching
session as `e2ee`. Console clients can therefore select the encrypted runtime per
session without inferring it from browser key availability.

## Module boundaries

- `db/init.sql` owns the `agent_sessions.transport` schema and upgrade backfill.
- `internal/manager/storage` marks sessions in the same transaction as encrypted
  command creation and provides equivalent in-memory behavior.
- `internal/manager/domain.AgentSession` exposes the marker in user-facing session
  responses.
- `api/pax_manager.thrift` remains the generated HTTP contract source of truth.

## Data flow

1. A session is created with `transport = 'manager'`.
2. The browser posts an opaque encrypted command for that session.
3. `CreateAgentCommand` inserts or validates the idempotent command and updates the
   matching session to `transport = 'e2ee'` before commit.
4. Session list and detail queries return the marker to the Console.
5. Schema startup backfills existing encrypted sessions from `agent_commands`,
   `agent_events`, or `e2ee_messages`.

The marker contains no key material, plaintext payload, or native session ID.
Updating it does not touch `agent_sessions.updated_at`, so migration and command
replay do not reorder the user's session list.

## Generated artifacts

The Thrift model and OpenAPI JSON were regenerated after adding field 32:

```text
internal/transport/http/model/paxmanager/api/pax_manager.go
internal/manager/openapi_generated.json
```

Regenerate all derived artifacts with:

```bash
make generate
```

This requires the `hz` and `thriftgo` executables on `PATH`.

## Verification


The full suite requires permission to bind local loopback ports for `httptest`.

## Operational notes

- Deploy the Manager schema change before relying on the Console marker.
- Old Manager instances do not select the new column and remain compatible with
  the table addition, but only updated instances mark new encrypted sessions.
- Queue, steer, attachment, and permission parity are Console/runtime follow-up
  work; they do not change the marker semantics.
