# Multiple search keywords with partial-match fill

## Final contract

ISSUE-054 splits the raw query on Unicode whitespace using strings.Fields.
strings.ToLower normalizes case, duplicates are removed and terms are sorted
for a deterministic query. At most 16 distinct nonempty terms are allowed;
existing raw-query, hit-count and scope limits remain. Punctuation is literal,
including quotes; no phrase, Boolean operator or proximity syntax is introduced.

A result can match any keyword in title or body of the same indexed object.
Distinct matched-term count is the primary rank, followed by the number of terms
with ASCII identifier-boundary matches, then descending creation time. All-term
hits therefore appear before partial hits, which fill remaining page slots even
when there are zero all-term hits. Single terms retain the existing literal
substring recall and boundary order; underscore remains an identifier character.
Non-ASCII boundary behavior remains the documented technical ASCII policy.

## One query and current-source checks

internal/manager/domain/search_terms.go is the shared parser used by query
validation/construction, cursor fingerprints, PG-source revalidation and snippet
selection. internal/manager/search/query.go constructs one ES query: owner,
deleted and optional kind/session filters stay mandatory; a separate mandatory
OR of literal title/body clauses requires at least one keyword. Each distinct
literal clause contributes N+1 points, and each optional bounded-literal clause
adds one point across either field. Since the total boundary bonus cannot
exceed N, one extra literal term always outweighs every possible boundary bonus.
No per-field or repeated-occurrence score inflation is possible.

The scalar score is `(N+1)*matched_terms + boundary_terms`. Sort remains score,
created_at, doc_id and PIT _shard_doc. The v3 fingerprint includes canonical
terms and owner/filters, invalidating older ranking cursors. Four typed sort
values are retained; score must be an integer between N+1 and N*(N+2). Equivalent
query whitespace, term order and case preserve the same canonical query and
pagination. The same latest PIT identifier is reused across pages.

internal/manager/userapi/workspace_search.go reloads each result from its current
source and verifies owner, deletion, scope filters and at least one current
literal term. A stale index cannot expose unrelated source content. A source
that still matches one term remains eligible as a partial match; the ES rank can
briefly reflect older indexed content until synchronization catches up. Snippets
prefer body if it contains any term, otherwise title, and use the earliest
present keyword with the existing 200-rune bound. A snippet need not contain all
keywords when they are far apart. Existing short-page behavior after source
revalidation remains possible.

## API, MCP and rollout

The request/response schema is unchanged. Active search contract, deployment,
acceptance and Secretary MCP docs describe the new semantics; the MCP search
tool description covers messages, session titles and summaries. Thrift's
OpenAPI description is authoritative and regenerated through make generate.
Historical handoffs retain their historical single-query/older ranking design.

Deploy Manager before the companion Console keyword hints/highlighting so both
components describe the same behavior. No PG schema/index, ES mapping or reindex,
worker, source identity, permission model or summary-generation change is made.
There are no search-time model calls or PG associations. This handoff records
local validation and does not claim deployment.
