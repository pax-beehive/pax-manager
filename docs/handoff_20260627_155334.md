# Handoff: Team P1 Management and Audit Log

## Summary

This change adds the first P1 team management surface on the existing
hand-written user API routes:

- team audit log listing
- pending team invite cancelation
- team member role updates between `member` and `operator`
- team archive
- richer team agent list payloads with owner email and embedded agent details

The storage implementations now record audit events for team creation, invite
creation/acceptance/decline/cancelation, member removal, member role updates,
agent add/remove, and team archive.

## Module Boundaries

- `internal/manager/domain`: team constants, request/response domain structs,
  and store interface contracts.
- `internal/manager/userapi`: request validation, principal resolution, and
  service-level response envelopes.
- `internal/manager/storage`: Postgres and memory store implementations.
- `internal/manager/team_handlers.go`: thin Hertz handlers for the hand-written
  team routes.
- `db/init.sql`: schema additions for invite cancelation and audit events.

Generated Hertz handlers were not changed. The current team routes are still
registered manually in `internal/manager/server.go`.

## API Surface

New routes:

```text
GET  /api/v1/user/:user_id/teams/:team_id/audit?limit=50
POST /api/v1/user/:user_id/teams/:team_id/archive
POST /api/v1/user/:user_id/teams/:team_id/invites/:invite_id/cancel
POST /api/v1/user/:user_id/teams/:team_id/members/:member_user_id/role
```

Role update request:

```json
{"role":"operator"}
```

Allowed role update targets are `member` and `operator`. Empty role is rejected
with HTTP 400. Team invite creation still defaults an empty role to `member`.

## Data Flow

For each mutating team operation, the service resolves the authenticated
principal, validates path/body inputs, and delegates to the store.

The store performs authorization and writes the business row plus its audit row
inside the same transaction or memory-store lock. Audit events use `taud`
identifiers and include target user, agent, or invite IDs when available.

`ListTeamAuditEvents` currently requires active team membership, returns events
newest first, and defaults limit to 50 with a max of 100.

`ListTeamAgents` now returns:

- `agent_owner_email`
- the existing team-agent fields
- embedded `agent` details when the agent row exists

## Schema

`team_invites` now includes:

```sql
canceled_at TIMESTAMPTZ
```

New table:

```sql
team_audit_events (
    event_id TEXT PRIMARY KEY,
    team_id TEXT NOT NULL,
    actor_user_id TEXT NOT NULL,
    action TEXT NOT NULL,
    target_user_id TEXT,
    target_agent_id TEXT,
    target_invite_id TEXT,
    metadata JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
)
```

The audit listing index is:

```sql
idx_team_audit_events_team_created ON team_audit_events(team_id, created_at DESC)
```

but failed while building the sibling `../paxd/Dockerfile.integration` image.
That Dockerfile runs `go mod download` without the private module token plumbing
used by pax-manager's main `Dockerfile`, so it cannot fetch
`github.com/pax-beehive/paxkit`. The isolated stack was stopped with
`make integration-down`.
