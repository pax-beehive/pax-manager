# Local Session Reporting Preference Handoff

## Summary

Agent daemon connections now expose a `report_local_sessions` preference. It
defaults to `false`. Users can explicitly enable it from the PAX Console
connection edit form without restarting the ACP runtime.

When disabled, paxd still reports sessions whose native IDs exist in its local
`acp_session_route` table. Those routes are created by manager-driven ACP
session creation, so Console-created sessions remain discoverable and continue
to receive reported-name updates. Sessions found only by scanning unrelated
local agent logs are not uploaded.

Paxd also forces route-only reporting when distinct remote identities share a
normalized Cloud API URL. This prevents a shared paxl installation from
fanning one account's local sessions out to another account on the same server.

## Module Boundaries and Data Flow

- PAX Console sends `report_local_sessions` through the user-scoped daemon
  agent connection update endpoint.
- `internal/manager/userapi` validates the update and forwards it as an
  `agent_connection.update` control command.
- paxd persists the preference on `agent_connection`; GORM migration adds the
  column with a default of `false`.
- The paxd session reporter reads the persisted preference on each reporting
  pass. It does not rely on the supervisor runtime spec and therefore does not
  require a runtime generation change or ACP restart.
- If reporting is disabled, the reporter intersects scanned native session IDs
  with `acp_session_route.native_session_id` before sending the cloud report.

## Operational Notes

- The setting takes effect on the next paxd session report pass, normally
  within 30 seconds.
- Disabling the setting does not delete sessions already stored in the cloud.
- ACP routes are persisted before manager-created native sessions are used, so
  those sessions remain in the allowed report set.
