# Secretary long-user previews and preparation failure handling

## Behavior

New jobs use `user-head-tail-assistant-last-v2`. User messages larger than
32 KiB receive a bounded beginning/end preview; ordinary user messages and
assistant last-paragraph views keep their established behavior. The agent can
inspect the matching reply and read original ranges only when needed.

This changes input visibility, not canonical messages, IDs, hashes, snapshots,
search indexing, summary entities or permissions. Selective processing can
complete a message without reading its omitted middle. Claims may only quote
actual supplied segments or separately verified reads.

## Boundaries and flow

- `domain/secretary_message_view.go` owns the shared preview budget, UTF-8-safe
  slicing, supported policies and exact segment quote checks.
- Storage budgets the same preview used by prompt generation and freezes the
  policy in `SecretaryJob.InputPolicyVersion`. New batch IDs include it.
- Node and legacy prompt builders label omissions; evidence binding respects
  the frozen policy. Empty/v1 frozen jobs keep their old full-user visibility.
- Existing read/expand tools expose authorized first/last/full views and bounded
  pagination. Head-tail is not added as a public read view.
- Deterministic preparation size errors clear the lease and block retry without
  advancing progress. Source changes and explicit retry retain existing wake
  semantics. Native unknown/terminal recovery remains separate.

There are no SQL migrations, generated artifacts, Paxd tool-schema changes or
historical backfill resets. Previously queued 314 KiB user input can be claimed
with the new preview after deployment; already blocked native attempts still
require their existing recovery checks.
