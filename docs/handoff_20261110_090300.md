# Secretary compact evidence and confirmed failure recovery

## Behavior

New summary versions store complete source-version references once in
`summary_sources`. Each evidence item in `claims_json` keeps its quote and view
and uses a revision-local integer `source_key`. Reads restore complete references
for the existing HTTP, Console and MCP contracts. Legacy full-reference claims
remain readable, historical versions are not rewritten, and ES projections are
unchanged. The whole publication budget remains 64 KiB. Request/publication
hashes retain the existing full-reference representation for idempotency.

Three real capacity-invalid outputs measured 71,410 / 69,773 / 77,470 serialized
bytes before compaction. A lossless reference-index experiment reduced them to
56,534 / 56,662 / 57,420 bytes. This measures JSON representation, not PostgreSQL
disk compression or model token savings. Summary text and evidence were retained.

Secretary node attempts now have durable prompt-request associations and
idempotent reliable-inbox failure records. Only an exactly correlated RPC error
or cancellation is a known failure. A scoped wake schedules recovery of the
original attempt. Store-side proof checks under the existing settings/job lock
order handle terminal arrival before or after timeout failure handling.
Known failures save no partial output or checkpoint; three actual attempts are
allowed, with 5-second and 10-second retry waits. Unconfirmed outcomes are not
automatically replayed. Pauses, active leases, ownership and settings/retry
generation fences remain authoritative.

Validation retries additionally receive fixed safe hints for capacity, unavailable
sources and unverified quotes, without exposing raw errors. Result checks can
return the optional `result_failed` outcome. The companion Console change is
[PR 243](https://github.com/pax-beehive/pax-console/pull/243), which explains that
outcome without claiming publication or sending a new model request itself.

## Module boundaries and flow

- Domain owns compact encoding and strict shared terminal identity matching.
- Secretary binds trusted sources and uses the compact publication budget.
- Storage writes compact claims and source rows atomically, expands both claim
  encodings on reads, and owns task locking, proof queries and retry state.
- Manager persists only minimal prepared dispatch identity, then projects known
  failure records from authenticated, sealed reliable-inbox envelopes. Prompt
  text and raw native errors are not copied into those records.
- User API preserves the safe result outcome; Console renders fixed text.

Terminal proof queries use deterministic message primary keys and the existing
internal-session mapping. They do not scan source history or the transport
journal. Current request identity fences older failures after an ACP route retry.
The reliable projection remains retryable if terminal persistence or wake fails.

No Thrift, generated router/model/mock, SQL schema, model configuration or MCP
approval-policy change is required. Normal conversations are excluded from the
Secretary-only terminal path.

## Deployment and compatibility

Deploy the new Manager reader and writer together. The new reader accepts old
and compact claims, but an older binary cannot resolve new compact claims.
Rollback must retain the new reader or use a separately reviewed conversion;
do not promise that restarting an old image can read newly written versions.

Existing blocked batches and unknown executions are not globally reset. Old
unknown executions without durable request/terminal correlation remain unknown.
Use the existing owner-authorized per-task check or confirmed restart after
establishing native termination. A timeout, cancellation send, idle snapshot or
transport ACK alone is insufficient proof. Do not fabricate successful markers.

This change addresses current node execution recovery. Runtimes without sealed
session/turn correlation remain conservative. Global status aggregation can still
emphasize a pending failure while other tasks progress; task cards remain the
specific execution view. Real-session summary quality is separate from protocol
validation.

across versions, malformed keys, revoked/archived sources, old immutable
snapshots, unchanged hashes and atomic Secretary publication/replay. Real
PostgreSQL directed contracts passed. New compact encoder/decoder coverage is
above 95%.

removal, reliable replay, current-request fencing, both timeout/terminal orders,
