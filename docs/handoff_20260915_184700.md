# Sent attachment image previews

## Change and flow

- Console renders sent PNG, JPEG, GIF, WebP, AVIF, and BMP attachments as lazy
  thumbnails. Clicking opens an accessible image dialog. Other files remain
  labels. Failed image loads preserve the filename and offer retry.
- Live messages retain the uploaded attachment ID. History can recover it from
  the direct `att_<48 hex digits>` directory in Paxd's localized resource URI.
  Unrecognized resources remain labels; browsers never load node-local paths.
- Console requests the existing same-origin proxy at
  `/api/pax/api/v1/user/{user_id}/attachments/{attachment_id}/content`.
- The new Manager GET route uses the existing user principal and attachment
  store authorization. It requires a completed upload and the configured object
  storage bucket, then redirects to a short-lived signed URL for that object's
  recorded generation. The redirect is private and not cacheable.
- Only supported raster image MIME types receive inline content disposition.
  Other types receive attachment disposition. Filenames use MIME encoding.
- This follows the existing manually registered attachment endpoint family.
  No generated artifacts, database migrations, or Paxd changes are required.

## Deployment

Deploy Manager before or together with Console. An older Manager does not expose
the preview endpoint, so images show the filename and retry fallback until it is
updated. Standard local development uses `make run-memory` or `make run`; the
Console proxy must target that Manager with valid user authentication. No
deployment was performed for this change.

No existing issue records changed. Earlier local Console archive-list and prompt
attachment changes remain separate from this preview addition.
