# Hosting candidate against the deployed Manager base

## Scope

This candidate starts at the observed deployed Manager
revision `0a96512256029fbb4277f724694ab37a30578079`, on branch
`deploy/hosting-live-base-20261114`. Its worktree is
`work/hosting-live-manager-20261114` in the shared workspace.

It transplants only the hosting feature from `work/free-starter-manager` and
the small build/router prerequisites needed by that feature. The original
worktree is unchanged. It does not include the 80 intervening commits,
WorkOS/native-auth changes, Secretary/search features, or module upgrades.
`go.mod` and `go.sum` are unchanged from the deployed base.

The new `internal/manager/hosting` package owns accounts, leases, monthly
user/platform limits, model policies, moderation audit, reservations and
settlement. Manager handlers authenticate existing user/admin principals or
the separate host/gateway service capabilities, then delegate. Generation
stays in the independent gateway; the old Manager generation path returns410.

## Wiring and generated artifacts

- Hosting configuration is added to the existing config loader and validation.
- The base storage implementations expose the independent hosting transaction
  interface. Memory uses its own mutex; PostgreSQL stores one serialized
  `hosting_state` JSONB document with transactional row locking.
- `db/hosting.sql` is additive. `EnsureSchema` retains the base `db/init.sql`
  and additionally applies the hosting DDL, without adding later unrelated
  schema files.
- The IDL adds ten methods across eight paths and the hosting DTOs. The existing
  generated-handler bridge receives those ten methods.
- The existing Hertz customization template is included and the update command
  selects it. Newly generated handlers delegate to `HandleGenerated` rather
  than returning placeholder responses.
- The old browser Worker allowlist gains exactly `/api/v1/starter` and
  `/api/v1/starter/wake`. The accounting service route is not exposed through
  that browser proxy. No later native Worker architecture is copied.

Regenerate with `make generate`. The candidate uses the original pinned Hertz,
mockery, and OpenAPI generation workflow. A semantic comparison of generated
OpenAPI JSON found all 58 old paths and all old schemas unchanged; eight paths
are added. Independent read-only review also found no removed or changed
existing generated struct definitions or authentication implementation.

## Deployment limits

No image was published, no production service or schema was changed, and no
secret values were read or copied into this candidate. Gateway keys stay in
the operator-private configuration, not this repository.

Before activation, select this exact candidate release, verify a backup of the
actual Manager database, commission the additive schema against an isolated
copy, and verify authenticated HTTPS accounting ingress. Existing cloud
configuration and the operator's real model registry must be supplied.
Keep the monthly platform cap0 until the actual shared budget is chosen.

Deploying this Manager alone does not deploy the browser Worker, Console,
sandbox host, or the separate Lambda images. Existing production auth defaults
and original database data must be preserved throughout commissioning.
