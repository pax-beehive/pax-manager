# Session history calibration handoff

## Change and boundaries

Issue 029 is resolved in code. The Manager exposes a read-only durable head on
single-session detail and turn-filtered summary pages. Storage owns SQL and
in-memory filtering; userapi owns authorization, shaping, and page-size bounds;
handlers only bind query parameters. canonicalSessionStore forwards the optional
SessionHistorySyncStore capabilities. No table, migration, or paxd change.

GET /api/v1/user/{user}/nodes/{node}/agents/{agent}/sessions/{session} returns
latest_message_id, latest_message_seq, latest_turn_id. GET
/api/v1/user/{user}/sessions/{session}/history?view=summary&turn_id={turn}&limit=100
supports before_seq and after_seq. Read all older pages for a complete turn.
Unlike general summary history, filtered pages do not expand turn context.

Console retains locally owned conversation SSE; running sessions without it use
events. Visible metadata polls run every five seconds. Idle unknown message IDs
trigger after_seq catch-up from the second newest known row. Completion triggers
whole-turn reads; all pages must succeed and include turn_done before replacing
live output. Completed turns are assumed immutable. Failed reads retain the last
view and retry on metadata polling. Focus does not refetch all old pages.

## Deployment

Deploy Manager first, then Console through the existing deployment workflow.
Old Managers ignore turn_id; new Console rejects mixed-turn responses rather
than publishing an incomplete calibration. No data migration is needed.
For local execution use make run-memory or the existing development environment.
No deployment, service restart, or Docker integration stack was run for this task.

HTTP 202 acknowledges acceptance before detached target projection completes.

relationship. Production delivery behavior is unchanged.
