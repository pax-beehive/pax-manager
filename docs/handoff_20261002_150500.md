# Browser regional routing handoff

This change connects KEV-75 bootstrap to the browser portion of KEV-76/77.
Worker-owned signup precedes Console /me, and verified browser traffic follows
D1's immutable assignment using an identity-bound one-hour route cookie.

Boundaries: Worker routing.ts signs/verifies the route purpose and key ID;
browser-proxy.ts handles fixed origins, streaming, no-store and header filtering;
index.ts orchestrates bootstrap, recovery, probes and routing. Console's
features/region owns runtime configuration, bootstrap, probes and the gate.
The existing TanStack Query cache owns bootstrap results; no auth token is
exposed to React. The tunnel URL selects the same-origin edge only after bootstrap.

Validation: Worker 45 tests including real workerd RSA/D1/SSE/WebSocket flow;
100% statements/functions/lines and 98.75% branches. Console lint, typecheck,
production build, 795 full-suite tests plus follow-up route/tunnel tests passed.
Node 24.19 requires NODE_OPTIONS=--no-experimental-webstorage for existing jsdom
localStorage tests. New Console config handler coverage is 100%. No Go or
IDL-generated source changed. The real runtime test found and fixed the old
provisioning redirect:error setting and a conflicting cache override. Content
download redirects retain the existing Manager-signed HTTPS storage flow without
following redirects or forwarding user credentials to the storage origin.

Production activation requires installing matching per-region Manager secrets,
read-only regional auth mode, a final direct-to-D1 reconciliation, active browser
Worker routes, and the Console runtime feature flag. No local identity exports
are authorized or needed. Preserve existing container configurations and stopped
rollback containers; use at least a 240-second Manager startup health window.
Never re-enable implicit regional signup as a rollback after activation.

KEV-75 remains pending live activation verification. KEV-76/77 remain partial:
machine credentials, installer selection and paxd integration are separate work.
Operational receipts belong under work/browser-region and the home_dev runbook.
