# Session Archive Handoff

## Summary

This change adds reversible session archival. Active session lists exclude
archived sessions by default, while the owner-level paginated session endpoint
accepts `include_archived=true` to include them. The existing session PATCH
sets `archived` to `true` or `false` and returns `archived_at` when applicable.

## Module Boundaries

- `internal/manager/domain` owns `ArchivedAt`, `IncludeArchived`, and the
  optional archive update field.
- `internal/manager/userapi` validates archive updates and maps the list query.
- `internal/manager/storage` persists and filters archive state in memory and
  PostgreSQL.
- `api/pax_manager.thrift` is the transport and OpenAPI source of truth.

## Request and Data Flow

1. `PATCH /api/v1/user/{user_id}/nodes/{node_id}/agents/{agent_id}/sessions/{session_id}`
   accepts `{ "archived": true }` or `{ "archived": false }`.
2. User API authorization resolves the node, agent, and session before storage
   updates `agent_sessions.archived_at`.
3. `GET /api/v1/user/{user_id}/sessions` adds
   `agent_sessions.archived_at IS NULL` unless `include_archived=true`.
4. Agent-scoped session collection reads continue to return active sessions
   only. Direct session reads still resolve archived sessions, which allows
   restoration.

## Risks and Assumptions

- Archiving does not stop or cancel a running agent turn. It only changes list
  visibility.
- Archived sessions remain directly readable by authorized users and can be
  restored through the same PATCH endpoint.
- The inclusive filter returns both active and archived sessions; it is not an
  archived-only view.
