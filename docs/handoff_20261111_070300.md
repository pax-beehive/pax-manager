# Secretary fixture cloning and parallel acceptance

## Problem

Main CI run [42973018519](https://github.com/pax-beehive/pax-manager/actions/runs/42973018519)
for e6ae940 reached the storage package's 300-second Secretary acceptance limit.
It passed 223 top-level storage tests before the timeout. The last case had
only run for 0.541 seconds and was executing fixture schema DDL. Core
integration (126 seconds), search acceptance (205 seconds), and Secretary
acceptance (306 seconds including setup and cleanup) were serial steps in one
job, producing an approximately 11-minute failed run.

The existing tmpfs mitigation reduced disk I/O but retained the cost of
rebuilding four complete production SQL schemas for every PostgreSQL case.
The longest completed top-level test covered 18 scenarios across Memory and
PostgreSQL; its PostgreSQL leaves accumulated 23.35 seconds on that CI run.

## Fixture lifecycle

`tools/verify_secretary.sh` explicitly enables
`PAX_MANAGER_SECRETARY_TEST_TEMPLATE_DATABASE=pax_secretary_fixture_template`
only for its disposable PostgreSQL 16 container. The storage test fixture
builds init.sql, summaries.sql, search.sql and secretary.sql once in that empty
template. It closes the template pool before cloning a separate database per
case. Each clone receives fresh seed inserts, preserving timestamp, sequence
and trigger behavior. Cleanup closes each case pool before dropping its own
database; removing the isolated container removes the template.

The opt-in requires database-creation privileges provided by the disposable
container's test user. Ordinary local schema fixtures retain their previous
privilege requirements. Template names are restricted to a dedicated prefix,
validated, and quoted as SQL identifiers. A pre-existing template is not reused
or overwritten. Failed initialization attempts clean up their created database.

The cases retain real pooled connections, transactions and commits. Several
tests mutate DDL, drop columns and tables, install failure triggers, or observe
concurrent connections. Shared tables with TRUNCATE or an outer rollback would
change these semantics. A separate database per case preserves these checks.

The 300-second limit, complete Secretary selection, required-name checks,
no-skips gate, 4 GiB tmpfs and PostgreSQL durability defaults are retained.
New BDD cases verify structural and data isolation, fresh seed timestamps,
an empty template, cleanup and invalid template names. Successful acceptance
output reports each package's elapsed time.

## CI and release boundaries

Core integration, search acceptance and Secretary acceptance have separate
runner jobs. Search needs no MinIO images. Each suite retains its existing test
command and cleanup. The existing `integration tests` job and check name remain
as an always-run aggregate requiring all three results to equal success.
Failed, cancelled, skipped or missing results fail the gate. Image and Worker
publication retain their existing checks, integration and region dependencies.
Feature diagnostics include database, service and cleanup logs.

No application, API, production SQL or generated code changes are included.
Issue 078 remains partial pending CI verification. Existing issues 074-077 are
outside this test infrastructure change.

Before this fix, at the user's explicit request, the existing main-only Publish
image workflow was dispatched for e6ae940. Run
[42976041659](https://github.com/pax-beehive/pax-manager/actions/runs/42976041659)
successfully published, verified and registered this linux/amd64 artifact:


This workflow builds and registers an image; the user owns the deployment.

## Verification

The exact 18-scenario terminal-proof selection passed before and after on the
same runner with normal PostgreSQL durability settings. Package time, including
fresh template initialization, changed from 19.243 seconds to 5.049 seconds
(73.8% less time). The named test changed from 18.27 seconds to 4.35 seconds.
These are local timings rather than a GitHub runner guarantee.

Workflow validation passed actionlint v1.7.7, YAML dependency assertions and
the actual aggregate Bash script over all 125 combinations of success,
failure, cancelled, skipped and empty results. Only all-success passed.

The exact `GOWORK=off GOCACHE=/tmp/pax-manager-go-cache make secretary-acceptance`
passed 1355 named checks with zero skips. Storage completed in 40.388 seconds,
Manager in 9.568 seconds, userapi in 1.193 seconds and the worker in 0.433 seconds.
The script successfully removed its disposable PostgreSQL container. These
local full-suite results are not a same-runner comparison with the failed CI.

The new isolation and cleanup checks also passed against the default schema
fixture with template mode disabled (4.461 seconds, zero skips).
