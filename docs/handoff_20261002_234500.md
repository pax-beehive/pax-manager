# Node routing hints and recovery

## Change and trust boundaries

KEV-76/78 no longer require signed machine routing tickets. Node Keys continue
to authenticate machines. D1 remains authoritative for immutable user-to-region
assignments, and each regional Manager remains authoritative for Node Key
ownership and resource permissions. The browser signed-cookie protocol is
unchanged. Local issue 034 remains partial.

The new NodeAuth-protected GET `/api/v1/node/identity` returns the actual node
ID, owner user ID and configured Manager region. It does not read the supplied
user-ID hint, create accounts, or update business state. NodeAuth also adds
`X-Pax-User-ID` to authenticated HTTP responses.

`workers/region-directory/src/machine.ts` provides an opt-in machine origin.
The untrusted hint only orders read-only identity probes against fixed US/HK
origins. An accepted key's actual owner must match D1 before the original
business request is forwarded once. A failed mutation is never replayed in
another region. Missing, corrupt or other-user hints do not cause authentication
failure when a valid key can be recovered. An unrelated unavailable origin does
not prevent recovery at the actual healthy origin.

Paths and methods come from `internal/manager/nodepolicy/routes.json`. Only
header Node Keys are accepted; anonymous pairing, registration-token onboarding,
legacy agent-only keys, user APIs and internal APIs are excluded. Request bodies,
SSE and WebSocket upgrades are streamed. Identity corrections are returned on
HTTP responses and WebSocket handshakes. Each request currently incurs read-only
identity discovery and D1 lookup; no server-side identity cache is implemented.

The companion paxd branch `feat/kev-78-user-routing` stores only the corrected
user ID in `~/.paxd/cache/node-routing`. The cache is scoped to origin and key,
uses atomic mode-0600 writes and accepts only successful 2xx/101 responses.
Missing/unwritable files do not block requests; failures preserve existing hints.
No new secrets were generated or persisted by this change.

IDL source is `api/pax_manager.thrift`. Regenerated artifacts include the Hertz
model/router/handler and Manager OpenAPI JSON/Go output. The generated placeholder
handler remains generated; the Manager registry bridges the actual route to
`internal/manager/node_identity.go`.

## Deployment boundary

No production machine route is activated by this commit. All machine variables
are unset in the checked-in active browser config. Existing regional machine
origins and initial pairing behavior remain unchanged. No D1 migration is needed.

Before activation:

1. Deploy the Manager identity endpoint to both regions with their existing
   `PAX_REGION` values and auth settings.
2. Verify two fixed non-looping HTTPS machine origins with the reviewed Access
   path policy. Do not point an upstream at the intercepted public machine host.
3. Complete unified pre-pairing and installer integration in KEV-77/78/79.
4. Publish the companion paxd and verify old/new US/HK devices and failures.
5. Add machine routes while retaining all active browser routes and variables;
   supply `MACHINE_ROUTING_ENABLED`, `MACHINE_PUBLIC_ORIGIN`, `US_MACHINE_URL`
   and `HK_MACHINE_URL`. See the Worker README for the contract and examples.

Do not deploy the initial disabled `wrangler.production.jsonc` over the active
browser Worker. Rollback must preserve D1 assignments and active browser routing.
Manager/paxd support can deploy independently while machine routing remains off.
KEV-76/78 remain in progress; a code merge does not complete production rollout.
