# Permission request recovery

## Problem and changes

Manual permission requests were made durable by the initiating conversation SSE
reader. If that reader disconnected, history and observers could receive a raw
request without a manager approval ID. Console correctly disabled its buttons,
but the agent remained blocked waiting for a response.

The agent ACP pipeline now persists manual approvals before broadcasting them.
This runs in the existing approval middleware; there is no additional middleware
or temporary conversation runner for creating the record.
The conversation reader reuses that record instead of creating another one.
Runtime projection preserves the manager approval ID separately from the native
JSON-RPC request ID. Auto-approval still uses its existing pipeline path.
Pipeline creation does not search or rewrite old permission history: subsequent
normal history projection receives the decorated frame. A regression test covers
native request ID reuse so earlier approval records remain unchanged.

The companion Console change serializes decision POSTs but stops treating the
entire resumed SSE lifetime as a lock on later approvals. The paxd change sends
cancelled permission outcomes after session/cancel for pending requests in the
same session and process epoch. It still requires a terminal prompt response
before admitting another turn.

## Boundaries and rollout

- Manager: ACP pipeline, conversation streaming, and runtime projection.
- Console: permission card enablement and regression tests.
- paxd: ACP router permission cancellation and regression tests.
- No API schema, generated code, or database migration changes.
- Deploy the Manager, Console, and paxd changes for the complete behavior.
- Deployment is separate; no approval-fix release has been made.
- No production session was inspected or reset; the user did not provide a
  session ID during the investigation.
- Issue 018 is resolved for the current ACP conversation/observer flow, not the
  legacy mailbox protocol. It does not
  backfill approvals for requests that arrived before the fix. E2EE manual
  permission UI support remains outside this Manager approval flow.
