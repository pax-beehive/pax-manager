# Owner-scoped Starter activation

Manager can attach the existing Node in a trusted sandbox to its owner's
Starter. The owner can then select a Pi Agent already registered on that Node.
The same host claims a lease and applies the lease's budgeted Gateway credential
to the selected Agent. The legacy Starter provisioning queue remains available.

## Control flow

1. The host authenticates using its existing host bearer and the Node's existing
   key. Manager derives the owner from the Node key and records the Node and host
   affinity in the owner's Starter. Enrollment returns the owner and environment
   IDs for the worker to use in its claim. The owner sees `data.enrolled_node`
   and `data.starter.node_id` in Starter status. `data.user_budget_available`
   uses the same user budget check as wake, including explicitly zero-priced
   models. Enrollment does not allocate compute or issue a model credential.
2. A signed-in owner posts `{node_id,agent_id}` to `/api/v1/starter/wake`.
   Manager checks the registered Pi Agent and exact enrolled Node and checks the
   owner grant and platform pool before queueing the selected pair. An active
   wake for the same pair is idempotent. A different pair conflicts until the
   current lease is released or expires.
3. The host posts `{host_id,capacity,owner_user_id,environment_id}` to
   `/api/v1/hosting/jobs/claim`. A claim matches the owner, environment and
   pinned host in one hosting-state transaction. Scoped claims only find
   enrolled jobs. Legacy unscoped claims skip those jobs. An enrolled job
   contains the selected Node and Agent IDs and existing lease and model
   credentials. It has no registration token.
4. The host reports the selected Node and Agent under the existing lease.
   The ready transition requires both IDs to match the claim. The owner sees
   readiness and quota in `/api/v1/starter`. The Gateway validates the active
   lease and available budgets on model requests.

The HTTP boundary authenticates users and worker/Node keys and connects to the
Node directory in `internal/manager/hosting_handlers.go`. The hosting package
owns Starter state, scope, execution leases and quota. The current PostgreSQL
hosting-state document stores the enrollment marker and selected pair. No new
schema migration is required. The host key remains the trusted backend key and
the stable host ID is its affinity label. The same owner can enroll a replacement
Node after deleting the original from the Node directory and ending the previous
execution lease. Manager checks the old pin again before replacing it and keeps
the Starter's quota and usage records. A request that changes hosts while keeping
the existing Node requires an operator-controlled migration.

## Local verification and rollout

```sh
source /Users/gengcongkai/.gvm/scripts/gvm
gvm list
gvm use go1.26
export GOWORK=off GOCACHE=/tmp/pax-manager-go-cache
make hz-update
go generate ./internal/manager
make fmt-check
make lint
go test -count=1 ./...
go build -o /tmp/pax-manager-owner-claim-build-check ./cmd/manager
git diff --check
```

Hertz bindings and OpenAPI outputs were regenerated from `api/pax_manager.thrift`.
The aggregate `make generate` target also runs Mockery. This checkout's sandbox
could not reach the Go proxy for its module-deprecation metadata. Store
interfaces stayed the same, so no mock output was needed for this change.

Formatting, lint with and without the integration tag, focused enrolled-Node
tests and the Manager binary build passed. The full Go suite passed with
loopback sockets enabled for mock HTTP servers. No live model requests were made.

For manual local checks, set the documented hosting environment values and use
`GOWORK=off make run-memory`. Publish after review with the repository's
[Manager image release workflow](../.github/workflows/publish-image.yml). The hosting origin
must forward both credential headers for the exact enrollment POST. The browser
origin must route the existing signed-in Starter status and wake paths to the same
regional Manager. Deploy Manager and ingress before enabling a worker or Console
that calls the enrollment protocol. See [Hosted Starter](hosted-starter.md) for
the configuration and API contract.
