# Handoff: runtime configuration center and feature gates

Branch: `feat/runtime-config`. Contract: `output/config-center/config-center-design.md`
sections 1-6, 8, 9. Operator and API reference: `docs/runtime_config.md`.

## Summary

- New package `internal/manager/runtimeconfig`: registry (source of truth),
  resolution (db, env, default), lock-free snapshot store with a 15 second
  revision poller, admin operations (set, reset, revert, audit, test), and the
  search connection tester. Credentials are environment-only by decision: no
  API key is registered, stored, listed, or overridable.
- Storage: `db/migrations/20261113_runtime_config.sql` (applied by
  `EnsureSchema`), `storage.PostgresRuntimeConfig`, `storage.MemoryRuntimeConfig`.
- Manager wiring: admin routes `/api/v1/admin/config*`, `GET
  /api/v1/user/self/features`, `featureGate` middleware (`feature_gate.go`),
  `config` field in `/api/v1/health`, cross-region allowlist in
  `auth/browser_identity.go`.
- Consumers now read the snapshot per use: search (`search_runtime.go`,
  fingerprinted client), voice (`voice_handlers.go`, fingerprinted provider),
  journal cleanup (`Disabled` checked per tick).
- Background jobs respect gates: Secretary worker `OwnerAllowed`, notification
  worker `UserAllowed`.

## Module boundaries

- `runtimeconfig` depends on `domain`, `search`, `logging`; it never
  imports `storage` outside tests.
- Repository interface: `domain.RuntimeConfigRepository`. Stores expose it with
  `RuntimeConfig()`; `newRuntimeConfigStore` type-asserts the base store.
- The environment layer is the already-loaded `config.Config`
  (`runtimeConfigEnv`), so behavior without overrides matches `config.Load`.

## Data flow

- Read: handler -> `s.runtimeConfig.Snapshot()` (atomic pointer) -> typed getter.
- Refresh: poller -> `RuntimeConfigRevision` -> on change `LoadRuntimeConfig`
  (repeatable read) -> `resolve` (bad rows skipped individually) -> swap.
- Write: admin handler -> `Store.Set/Reset/Revert` -> one transaction (revision
  row lock, version check, upsert/delete, audit) -> immediate local refresh.

## Risks and gotchas

- Rollout: gates default to admin, so Secretary, Notifications,
  Collaboration, and Knowledge capsules disappear for ordinary users when this
  ships. Move gates to beta or ga in the admin UI as needed.
- Credentials stay in each instance's environment. Moving them to a managed
  store (for example AWS Secrets Manager) is a separate future change.
- Switching search to a new cluster or index does not re-run the backfill.
- `feature.browser_control` and `feature.android_control` are reported to
  Console but not enforced server-side yet.
- `openStore` still requires the main database at startup; only the config
  load is non-blocking.
