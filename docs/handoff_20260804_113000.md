# Durable Conversation Turn Lifecycle Handoff

## Summary

Conversation runs now have an opaque business `turn_id` that is allocated before
prompt submission and remains stable across streaming events, permission pauses,
permission continuations, and durable message history. Transport request IDs and
reliable queue sequence numbers are not exposed as business identifiers.

## Module Boundaries

- `internal/manager/conversation.go` owns conversation request sequencing and the
  public SSE lifecycle.
- `internal/manager/acp_pipeline.go` and `acp_tunnel.go` propagate the active
  business turn through ACP frames, runtime projection, and automatic approvals.
- `internal/manager/acp_history.go` persists turn-scoped ACP history.
- `internal/manager/conversation_turn_queue.go` preallocates a distinct turn ID
  for each queued follow-up.
- The observer envelope is unchanged. Existing observer ACP and `turn_done`
  events reuse the business turn already held by runtime state.

## Lifecycle and Data Flow

### Normal turn

1. Allocate `turn_*` before submitting the prompt.
2. Emit `turn_started` before visible output.
3. Attach the same ID to turn-scoped ACP events and durable history.
4. Flush buffered history text before completion.
5. Upsert a durable `message_type=turn_done`, `status=complete` marker whose
   `raw_json.turn_status` is `complete`.
6. Emit SSE `turn_done` only after the marker is query-visible.
7. Emit request-scoped `done` without a turn ID when the HTTP stream ends.

### Permission flow

- A manual permission pause emits `approval_required` and `interrupted`, but no
  `turn_done`. The request-scoped `done` only closes that HTTP stream.
- Resume reuses the same active business turn ID and emits `turn_started` with
  `status=resumed`.
- Automatic permission responses update runtime state and durable history with
  the same business turn ID.

### Queued follow-ups

Each queued follow-up receives a distinct preallocated business turn ID and an
independent `turn_started`/`turn_done` lifecycle.

## Public Contract

- `turn_started`, turn-scoped `acp`, `approval_required`, `interrupted`, `error`,
  and `turn_done` carry the opaque business `turn_id`.
- `turn_done` is the only business completion event.
- Whole-request `done` remains stream scoped and does not carry `turn_id`.
- Observer replay and `after_seq` behavior are out of scope for this change.

## Risks and Follow-up

- A pre-upgrade paused session without `ActiveTurnID` receives a new business ID
  on resume; old untagged history is not backfilled.
- Observer replay remains out of scope and the observer envelope is unchanged.
- Queued-turn storage remains process-local.

No issue state or schema-generated artifact was changed.
