# Secretary coverage progress

## Result

Secretary settings now expose session coverage progress: total sessions, current
complete coverage, partial coverage and sessions awaiting coverage. A paginated
session list reports covered and remaining turns where reliable persisted turn
IDs exist; otherwise it reports logical messages. This builds on the automatic
worker described in [handoff_20261031_093837.md](handoff_20261031_093837.md).

Progress means successfully published summaries cover the current canonical
source versions. Model input delivery is not completion. A changed older message
or late part can make an existing session pending again, even while Secretary is
disabled. The feature does not call a model, modify source content, start the
stopped local prototype, or require ES for progress reads.

## Contract and implementation

GET `/api/v1/user/self/secretary/progress?limit=20&cursor=...` returns:

- `as_of`: the observation time of a repeatable-read snapshot.
- `counts`: aggregate session and message/known-turn coverage for the complete
  current owner-visible universe, independent of the page size.
- `sessions`: up to 100 source sessions, with identity, title, coverage counts,
  classification and optional last successful completion time.
- `next_cursor`: an opaque owner-bound continuation for the stable source order.

The default page size is 20. Unknown/duplicate query parameters, invalid limits
and malformed/foreign cursors fail with 400. Authentication supplies the owner;
neither a route user ID nor a cursor changes authorization. An unavailable
progress capability fails with 503 instead of reporting zero work.

`domain/secretary_progress.go` defines the narrow optional progress store and
DTOs. `storage/secretary_progress*.go` implements matching PostgreSQL/memory
reads and aggregation. PostgreSQL streams one owner-scoped bulk source query
under repeatable read, reusing canonical message visibility and text assembly.
Completion requires matching full-body hash, canonicalization version and current
owner against the publication checkpoint. No schema or trigger changes are
needed; disabled-time edits remain visible without relying on queue dirtiness.

Empty/textless sessions, hidden tool/reasoning content, ciphertext, replaced
source messages, internal runner sessions, archived sessions and deleted or
currently inaccessible sources do not inflate the denominator. Visible source
sessions are included before the user first enables the feature. Message parts
do not add messages. Turns group actual nonempty `messages.turn_id` values within
each source session, and complete only when all visible members complete.
Unknown turn IDs remain `ungrouped_messages`; they are never inferred from
message pairs or sequence numbers. The counts describe persisted coverage as of
the read, rather than native ACP termination or a promise that no more messages
will arrive.

`userapi/secretary_progress.go` resolves authenticated ownership and validates
the query. `secretary_progress_handlers.go` parses strict query input and binds
the response. The endpoint source is `api/pax_manager.thrift`; `make generate`
updated Hertz models/routes/handler and OpenAPI. Generated files were not
manually edited.

Console uses a separate owner-keyed infinite TanStack Query in
`src/features/api/secretary-progress.ts`. The overview shows authoritative global
totals; bounded rows appear below the settings controls with direct session
links. Refresh restarts pagination and does not reset an unsaved agent/switch
draft. Refresh replaces pages instead of treating them as an append-only source
history. Progress polls every 30 seconds while active, independently of the
existing settings/status polling. The complete source scan is an intentional
small-deployment MVP; its cost scales with visible text. Measured growth can
justify a cached projection behind the same store contract.
