# Session-grouped search

Issue 062 is resolved by opt-in grouped browser search. The detailed API,
permission model, paging limits and operational migration are documented in
`docs/search_session_groups.md`.

## Flow and ownership

- `api/pax_manager.thrift` adds optional `group_by` and `group_key` inputs to
  the existing search route. Run `PATH="$HOME/go/bin:$PATH" GOWORK=off make
  generate` to regenerate transport and OpenAPI artifacts.
- `domain` defines canonical owner/agent/session group keys and optional grouping
  source/backend interfaces. Existing raw search and Secretary MCP defaults stay
  unchanged.
- `storage` resolves deterministic Secretary primary source sessions and current
  owner-scoped session metadata. Coverage may span sessions and never defines
  group identity. The indexing projection gets the same primary association.
- `search` adds a keyword mapping and includes group keys on new index writes.
  Grouped searches use collapse, bounded identity-only inner hits and independent
  PIT/offset cursors. Exact-group raw expansion also excludes ES source bodies.
- `userapi` re-reads current source content and permissions from PG, rejects
  stale/rebound keys and supplies canonical session titles. Initial previews
  resolve session metadata once per group. Bounded refill keeps pagination moving
  after inaccessible candidates are removed.
- The migration is explicit, paged and resumable. It queues normal search work,
  preserves leases and pending priority, increments external index revisions and
  performs no model calls or Secretary work. Deployment does not run it.

## Verification

Unit tests cover canonical identity isolation, owner/source metadata, standalone
summaries, stale/rebound hits, canonical snippets/titles, refill, expansion,
migration readiness, backend errors and cursor/window bounds. Actual Hertz tests
verify grouped body decoding, populated results, `groups:[]` for no results,
unchanged raw results and rejection of incompatible modes. Python tests verify
bounded migration calls and literal checkpoint argument handling.

The real ES suite verifies 22 sessions with title/message/summary documents,
20+2 unique grouped pages, bounded identity-only previews, raw expansion, tenant
isolation and legacy migration readiness, alongside all existing literal/ranking
and raw pagination regressions. Real PostgreSQL tests verify explicit primary
association despite related-session coverage, standalone project summaries,
custom/untitled names, archival/ownership and paged migration lease/revision/
priority behavior. Only isolated test schemas and the root-owned test stack are
used. Final executed checks and coverage are recorded at handoff completion.

## Operational limits

The grouped result window is 10,000. `matches_has_more` represents possible
indexed candidates, not an authorized count. Four indexed candidates per group
are inspected; all-stale preview windows may temporarily suppress groups.
An eight-second deadline and bounded refill can produce short pages with a
continuation. Raw search remains available while the explicit projection
migration drains. Deploy backend support and complete the migration before
expecting the Console grouped experience to be ready.
