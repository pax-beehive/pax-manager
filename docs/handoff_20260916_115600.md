# Summary history text regression

Issue 024 corrects two regressions in the combined summary/observer release.
The previous prompt-size test asserted the body appeared only once in JSON,
without testing whether the consumer could display it. The new API regression
asserts canonical prompt text parts and assistant text on the first page of a
turn containing 150 tools, as well as on its older page.

Storage first computes the existing transport-row page and its cursors, then
includes non-tool records for only those turns, within the authorized session
and at or below the page head. Supplementary context must not change cursors.
The response can exceed the base row limit; full tool payloads stay omitted.
This keeps the UI conversational while preserving lazy tool history paging.
Non-tool text size is still unbounded, as in the existing contract.

The summary service reads prompt text parts; duplicate raw payload parts remain
suppressed. Console has a raw-prompt text fallback for existing summary payloads
and deduplicates overlapping pages before sorting by session_seq. User text and
assistant replies remain visible; work groups are supplementary timeline items.

Validation uses gvm Go 1.26 and Node 24. Commands: go test -count=1 ./..., go build
./cmd/manager, make fmt-check, make lint, full Vitest, TypeScript, and targeted
ESLint. Manager full tests and build passed; Console has 520 passing tests,
2 skipped, and passing TypeScript/targeted ESLint. Existing Manager formatting and
lint baseline failures remain unrelated. No generated artifacts or schema
changes are required. No deployment, restart, or production data repair was
performed. Deploy both Manager and Console to obtain the full correction.
