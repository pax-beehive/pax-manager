# Device subscriptions and queued Web Push tests

## Result and boundaries

Issue 042 remains partial. Delivery 3 implements the device opt-in and actual
test-send path on `codex/web-push-notifications` in the notification Manager and
Console worktrees. Deliveries 1-2 were merged as Manager PR 185 and Console PR 197
and deployed by the user. This change has not been deployed by the agent.

Console adds Settings > Notifications (`/settings/notifications`) for the current
browser/Android TWA. Enable explicitly requests permission, waits for the root
worker to activate, subscribes with the public application key, and uploads the
standard subscription to the authenticated owner endpoint. Disable revokes the
owned receiver and unsubscribes locally. A failed remote disable leaves a local
opt-out marker, so reconciliation does not silently enable it again.

The test button queues a real delivery with HTTP 202. A Manager worker signs and
encrypts Web Push with VAPID, sends it, and persists provider acceptance or a
bounded retry/failure. The administrator dashboard now reads actual latest task
metadata. Pending tasks with zero attempts are displayed as not attempted.

Automatic turn completion is not connected: public configuration explicitly
reports `turn_completion_enabled: false`, and the settings page explains that
automatic turn alerts are unavailable. Delivery 4 still needs an atomic durable
completion boundary and a reviewed E2EE terminal signal. Do not describe this
change as the complete turn-notification feature.

## Modules and request flow

- `notifications/worker.go`: optional Outbox/Sender interfaces, bounded drain,
  owner/revision/key rechecks and generic five-minute test payloads.
- `notifications/webpush.go`: webpush-go encryption/signing, fixed provider host
  policy, checked DNS/IP dialing, no proxy/redirects, bounded requests/response
  reads, canonical status and Retry-After handling. No provider body is saved.
- `storage/notification_outbox*.go`: PostgreSQL and memory queues. The additive
  `notification_deliveries` schema is in `db/init.sql`. SQL claims use row locks
  with SKIP LOCKED and expiring lease tokens. Claims count uncertain attempts;
  expired leases are reclaimable, and stale result tokens cannot overwrite a
  new lease. A late 404/410 invalidates and erases keys only for its sent revision.
- The existing subscription metadata read now joins latest attempts in its
  repeatable-read snapshot. Receiver endpoints/keys stay private.
- `notification_worker.go` starts/stops the worker in the Manager Run lifecycle.
  No private key means sending stays unavailable; malformed configured keys or
  contact fail startup with a sanitized configuration error.
- `userapi/notification_http.go` queues owned test tasks with one test per user
  per 30 seconds. Private keys never appear in public configuration.
- Console `features/notifications` serializes browser changes and repairs
  opt-in registrations on foreground login/focus without re-prompting. It honors
  remote revocation, replaces expired/invalidated subscriptions, and prevents a
  changed account response from being saved under the previous owner.
- localStorage contains only owner/receiver/key IDs and the opt-in marker.
  `logout-cleanup.ts` bounds cleanup to three seconds before the existing native
  WorkOS logout form. Auth cookies continue to belong to the gateway.
- `public/push-sw.js` handles push/click/subscription-change only. It has no fetch
  handler or authenticated cache. Payload text is generic. Navigation permits
  only same-origin session routes and notification settings.

The new generated API is:

```text
POST /api/v1/user/self/notifications/receivers/{receiver_id}/test
```

It returns queued metadata, never a device-display receipt. The existing config
adds `test_enabled` and `turn_completion_enabled`. Existing regional gateways
already proxy these owner routes; this phase changes no gateway routing code.

## Configuration and deployment

Generate one stable key pair for the environment, outside the repository:

```sh
GOWORK=off go run ./cmd/webpush-keygen \
  -out /private/tmp/pax-web-push.json \
  -subscriber mailto:ops@example.com \
  -key-id webpush-v1
```

Replace the example contact with an operated address or HTTPS contact URL. The
command writes a private JSON file with mode 0600, refuses to overwrite it, and
prints only its path. Import the values into the existing deployment's secret
configuration; do not commit the JSON file or put private values in Next.js.

| Runtime variable | JSON field / purpose |
|---|---|
| `PAX_WEB_PUSH_PUBLIC_KEY` | `public_key`; returned to the browser |
| `PAX_WEB_PUSH_PRIVATE_KEY` | `private_key`; Manager secret only |
| `PAX_WEB_PUSH_KEY_ID` | `key_id`; stable alongside the pair |
| `PAX_WEB_PUSH_SUBSCRIBER` | `subscriber`; VAPID contact |
| `PAX_WEB_PUSH_ALLOWED_HOSTS` | Optional provider host policy override |

The default allowed hosts are `fcm.googleapis.com`, subdomains of
`push.services.mozilla.com`, `web.push.apple.com`, and subdomains of
`notify.windows.com`. Even configured names cannot dial private, loopback,
link-local or reserved destinations. Use the same environment pair consistently
across its regional Managers. Never regenerate keys during startup.

Deploy Managers first, with schema and secrets, then Console. Public-key-only
installations retain registry reads but the device UI cannot enable sending
until `test_enabled` becomes true. No standalone notification deployment or
additional regional Worker deployment is introduced here.

After deployment, use an installed Android TWA or Chrome on the intended origin:
enable in Settings, verify a receiver appears in the administrator dashboard,
send a test, close the app page, and check the system notification and click
route. Also check denied permission, disable, sign-out and account switch.
Provider `accepted` does not prove OS display. Real-device acceptance is pending.
