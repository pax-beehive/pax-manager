# Literal search ranking

## Scope and request flow

ISSUE-052 changes only Elasticsearch query construction and pagination in
internal/manager/search/query.go. The existing user API and MCP tools continue
to validate inputs, supply the authenticated owner, and revalidate source
visibility. No Thrift, generated artifacts, PG schema, worker, index mappings or
source documents change.

The mandatory title-or-body wildcard filter retains case-insensitive literal
continuous-substring matching. User wildcard characters remain escaped. A
single optional constant_score clause adds one point if title or body contains
the escaped literal with ASCII identifier boundaries. Matching both fields or
matching repeatedly cannot add more points. Sort order is score descending,
created_at descending, doc_id ascending, then the PIT _shard_doc tie breaker.

Identifier continuation means A-Z, a-z, 0-9 or underscore. For port, PORT,
port:9879 and (port) receive the bonus; transport, viewport, port_name and
port123 remain recalled in the lower tier. A Chinese or U+00E9 prefix is a
boundary under this ASCII rule. This is an explicit technical identifier policy,
not Chinese segmentation or Unicode linguistic word matching. CJK literal
substring recall remains unchanged.

The regexp escapes Lucene standard and optional reserved operators and sets
flags NONE. If the escaped expression exceeds a conservative 1,000-byte budget,
the optional bonus is omitted; the existing wildcard recall query still runs.
Elasticsearch's original wildcard automaton complexity limits continue to apply.
No source scans, scripts, analyzers or model calls are introduced.

## Pagination and rollout

A ranking-version tag participates in the owner/query/filter fingerprint.
Old cursors are rejected; callers start a fresh search after rollout. The new
cursor validates four sort values: binary numeric score, integer creation time,
nonempty document ID and nonnegative integer PIT shard-document value. Backend
sort values are validated before a next cursor is returned. The same PIT, query
and sort are retained across pages, using the latest returned PIT identifier.

Deploy Manager normally. Existing wildcard indices and indexed history work
immediately with the new query; no reindex or database migration is needed.
This change has been validated locally and does not claim production rollout.

run failed because the new escaping helper did not exist. Tests now cover the
single binary bonus, filters, all regexp operators, omitted long-query bonus,
old cursor rejection, typed sort values, changed owner/query/filter rejection,
and closing the PIT on invalid backend sort values.

fixture. They verify port boundary examples, recency within each tier, stable ID
ties, owner isolation, PIT pagination after new documents are refreshed, literal

index mappings. The previous literal CJK and external-version/tombstone suite
also passes. The fixture is shared with independent browser navigation QA;
