# Secretary stored-claim recovery and local reporting audit

## Problem and fix

Issue 057 concerns a wire-schema contradiction: baseline claims exposed internal
IDs and rich evidence, whereas generated output rejected those fields. Production
inspection found 70 schema failures and confirmed copied input fields in two
completed replies. Automatic retries were checking the same completed response,
not allocating another model session each time.

BuildPrompt now projects baseline claims into the concise generated schema,
while currentPromptState retains the full stored baseline for ownership, head,
reset, and size validation. The decoder accepts only the previously exposed
typed compatibility fields. bindRollingEvidence first resolves evidence from
trusted delta/read/baseline data, then compares any supplied rich version, view,
and receipt against that result. Claim IDs are checked against the baseline
and regenerated. No source/version/quote validation is waived.

The executor can therefore recover a valid old completed response under the
same RunID without another session/new or model prompt. It can still reject
genuine evidence errors, expired receipts, or invalid references. There is no
automatic retry-generation rotation or new inference policy.

This recovery requires the same settings revision, batch, and retry generation.
Every settings save increments the revision and fences old work. In particular,
disabling and later re-enabling produces new RunIDs even for unchanged source
messages. Existing summaries and pending source work remain, but this patch
does not automatically reuse completed output from the previous setting. Keep
that fence intact rather than attributing model-free recovery to re-enabling.

## Module boundaries and deployment

Only Secretary prompt/output binding changes; no schema, index, generated HTTP
artifact, or public API changes. Use the usual Manager release flow. No live
jobs, settings, or messages were changed during the investigation.

The independent paxd PR 108 excludes known internal sessions before native
transcript reads and metadata uploads, using durable native-to-Manager bindings.
That fix requires updating paxd on the agent host; deploying Console/Manager
alone does not activate it. Native logs and the execution event stream remain
available for recovery and diagnostics.

Separate batching work investigates filling canonical messages rather than
stopping after 64 raw events. Production's 284 prompts contained a median of
six canonical messages. This standalone recovery patch can retain the old batch
shape to reuse valid completed replies when settings remain unchanged. The
combined release described in handoff_20261102_075100.md also versions compact
inputs and fills batches, so pending old executions may run again. Runs already
fenced by a settings change use new RunIDs regardless. The combined release is
safe to merge together; model-call reuse is not guaranteed across policies.

## Verification

TDD reproduces both input projection and completed-output decoding failures.
Secretary ordinary-test coverage is 94.4 percent; new functions are 100 percent.
A Manager completed-turn recovery test fails if BeforePrompt is called and
checks the saved response can form a valid publication. Negative tests cover
unknown fields/IDs, changed or removed evidence, contradictory aliases, and
hash/canonicalization/view/receipt mismatches. Full Manager checks are recorded
in the PR, along with the existing session list and progress validation.
