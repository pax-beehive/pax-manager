# Atomic Gateway admission and finish

## Scope and boundaries

Issue 094 is resolved in Manager. The current service-authenticated
`POST /api/v1/hosting/gateway/accounting` endpoint gains two actions. No new
owner-facing route, cancellation proxy, environment variable, or infrastructure
resource is introduced. The independent Gateway must deploy its matching client
before using the new actions; Manager can deploy first because existing actions
remain compatible.

`internal/manager/hosting_accounting.go` owns transport decoding, bounded numeric
usage evidence, and moderation metadata validation. Business rules live in
`internal/manager/hosting/admission.go` and `finish.go`. Both use the existing
`Store.WithHostingState` transaction. PostgreSQL serializes the durable JSON
document with a row lock; the in-memory store uses the same transactional
callback and persists only successful changes. The reservation fields need no
SQL migration.

## Request flow

Prepare accepts `token`, one-use `request_id`, public `model`, conservative
`input_tokens`, `max_output_tokens`, and `protocol` (`chat`, `responses`, or
`messages`). An output cap of zero uses the authoritative policy cap; a smaller
positive cap is accepted. An explicit `reasoning_effort` is allowed only for
Chat with provider `openrouter` and exact upstream model `openai/gpt-6.1-sol`,
`openai/gpt-6.2-astra`, or `anthropic/claude-opus-5.5`. Supported efforts are
`low`, `medium`, `high`, `xhigh`, and `max`; public aliases do not grant capability.
The omission preserves provider defaults. Unsupported or malformed effort is
HTTP 400 `invalid_reasoning_effort`; other request bounds are HTTP 400
`invalid_model_request`.
Disabled authoritative models are rejected with HTTP 403 `model_disabled`
before holding either budget, preserving the existing Gateway behavior.

In one short transaction, Prepare validates the current lease, selects Manager's
policy, rejects replay, applies request rate limits, and holds both user and
platform budgets. The hold prices the conservative input bound and effective
output cap separately. The reply returns `reservation_id`, the fixed `policy`,
effective `max_output_tokens`, and reserved `tokens`. No model call runs inside
the transaction. Registry-less configurations receive a policy constructed from
Manager's trusted legacy configuration, with required moderation.

Finish accepts `reservation_id`, optional `moderation` and `usage`, `known`,
`started`, and `outcome`. Outcomes are `completed`, `cancelled`, `failed`,
`blocked`, `unavailable`, and `invalid`. A started request requires an allowed
or policy-skipped moderation decision. A blocked outcome requires a blocked
decision. An unstarted cancellation or local rejection may have no moderation.
The first valid finish records the outcome and audit, releases the hold, and
settles the actual usage or conservatively charges the hold when usage is
unknown. Duplicate finish never charges or changes the first result again.

Finish never rechecks the current lease, enabled model, user or pool balance,
or hosting-enabled state. The service credential remains mandatory. Provider
usage may exceed the reserved amount; that overrun is recorded honestly and
future admission observes the resulting balance. No prompt, output text, or
credential is accepted as accounting evidence. Raw usage retains only bounded
numeric usage fields.

## Failure and accounting behavior

`Reservation.AtomicAdmission` prevents legacy actions from altering the new
reservations. After three minutes without finish, reconciliation changes an
atomic hold to a conservative charge with `ReconciliationRequired=true`, rather
than interpreting `GenerationStarted=false` as evidence of no upstream call.
The first late finish can correct that provisional charge. The recorded quota
and pool periods prevent a correction for a prior month from charging or
refunding the new month's quota or pool.

A finish with `started=true, known=false` is final for idempotency, remains
conservative, and explicitly requires later reconciliation. A duplicate finish
cannot silently replace it with fabricated zero usage. This change does not add
an operator reconciliation action. Admin request views expose atomic admission,
protocol, outcome, usage-known, and reconciliation-required metadata. Existing
views may ignore the added fields.
