# Node-Control Paxd Restart Command

## Summary

Pax-manager now exposes an authenticated user API that forwards a durable
`paxd.restart` command over the existing node-control tunnel. The API follows
the same dispatch and acknowledgement contract as the existing desired-slots
and agent-connection commands: it waits for the node command ACK and returns
HTTP 202 with the command and dispatch statuses.

The companion paxd change accepts the command from an authenticated remote,
persists it for idempotency, confirms that its ACK was written, drains active
ACP work within a bounded grace period, and exits so the service supervisor can
restart it.

## API

```http
POST /api/v1/user/:user_id/nodes/:node_id/daemon/restart
Content-Type: application/json

{
  "command_id": "cmd_restart_01",
  "mode": "immediate",
  "shutdown_grace_seconds": 12,
  "reason": "operator requested"
}
```

`command_id` is required and provides the same idempotency and status-query key
as other node daemon commands. `mode` defaults to `immediate`; other modes are
rejected in this release. The optional grace period must be between 1 and 60
seconds, and the optional reason is limited to 512 bytes.

An acknowledged request returns HTTP 202. Callers can query the durable paxd
record through the existing endpoint:

```http
GET /api/v1/user/:user_id/nodes/:node_id/daemon/commands/:command_id
```

## Request Flow

1. Pax-manager resolves the authenticated principal and verifies node ownership.
2. It resolves the connected node-control tunnel and current remote ID.
3. It sends a normal command frame containing `type: paxd.restart`.
4. Paxd persists and prepares the command, then writes a `received` ACK.
5. Pax-manager returns HTTP 202 with `dispatch_status: acknowledged`.
6. Only after ACK delivery does paxd begin bounded graceful shutdown and exit.
7. The external service supervisor restarts paxd with a new boot ID.

If ACK delivery fails, paxd stays running. A persisted command from a previous
boot is not replayed as another restart, which prevents restart loops.

## Generated Artifacts

The Thrift IDL is the source of truth. The Hertz model/router files were
regenerated with `hz update` using thriftgo 0.4.5, and the manager OpenAPI files
were regenerated with `go generate ./internal/manager`. The new generated
handler is connected to the manager's existing `HandleGenerated` bridge in the
same way as the desired-slots endpoint.

## Deployment Notes

Deploy the pax-manager and paxd changes together. Pax-manager can safely be
deployed first, but restart requests will be rejected by an older paxd because
it does not recognize `paxd.restart`.

This release intentionally supports restart only. It does not download or
install a new binary, and it does not implement a `when_idle` policy. The 202
response proves durable command acceptance and ACK delivery, not that the new
paxd process has already connected; operators can observe the node reconnect
and its new boot heartbeat for that final confirmation.
