# Team Memex Manifest Publish Handoff

## Summary

This change turns the dry-run team memex harness into a validated manifest
publish loop. The default executor still returns a no-op manifest, so the
public run endpoint remains safe before DeepSeek is wired in. Tests can now
inject a fake executor that searches and reads the memex workspace, returns a
manifest, and lets manager validate and publish create, update, archive, and
no-op operations.

## Module Boundaries

- `internal/manager/domain` owns the manifest, manifest operation, and storage
  operation shapes.
- `internal/manager/userapi` owns the executor seam, lexical workspace tools,
  manifest validation, run status mapping, and response DTOs.
- `internal/manager/storage` owns the atomic publish transaction for PostgreSQL
  and the copy-on-write publish path for the memory store.
- `internal/manager/userapi/mocks` is regenerated because the team memex store
  interface now includes reserved-path lookup and publish methods.

## Run Flow

1. Owner or operator calls
   `POST /api/v1/user/:user_id/teams/:team_id/memex/runs`.
2. The service lists active documents and internal reserved paths.
3. The service builds `index.md`, default constraints, and a workspace tool
   facade.
4. The executor returns a JSON-like manifest with operations.
5. The validator checks operation count, allowed operation type, path rules,
   `index.md` read-only status, active-document requirements, doc body size,
   tags JSON validity, and reserved path collisions.
6. Validation failure stores a `validation_failed` run with a typed validation
   report and does not publish any document changes.
7. Validation success calls `PublishTeamMemexRun`, which persists the run and
   applies all document operations in one storage transaction.

## Workspace Tools

The executor receives a narrow workspace interface:

```text
ListIndex()
SearchDocs(query)
ReadDoc(path)
```

Search is lexical and uses active documents only. Search results intentionally
omit `body_md`; full document bodies are returned only through `ReadDoc`, which
tracks per-run document read count and character limits from the persisted
constraints.

## Manifest Contract

Supported operations:

```text
create_doc
update_doc
archive_doc
no_op
```

Rules enforced before publish:

- `index.md` cannot be modified.
- `create_doc` cannot use any path that active or archived documents already
  reserve.
- `update_doc` and `archive_doc` can target active documents only.
- hard delete is not supported.
- duplicate operations for the same path are rejected.
- created and updated docs require title, summary, and body.
- output doc body size is limited by `max_output_doc_chars_each`.
