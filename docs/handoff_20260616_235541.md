# Handoff: Node-Scoped Message Tenant Boundary

## Summary

This change tightens the user-facing v1 node path:

```text
user -> node -> agent -> session -> message
```

Node-scoped handlers now validate that the requested node owns the requested
agent, and that the requested session belongs to that agent and, when present,
that node. Message creation also validates the same relationship in storage and
writes mailbox rows using the agent's canonical node ID instead of trusting the
request path.

## Module Boundaries

- `internal/manager/node_idl_handlers.go` remains transport binding. It now
  delegates node-scoped reads to node-aware `userapi` methods.
- `internal/manager/userapi/service.go` owns user-facing relationship checks for
  node, agent, session, and mailbox flows.
- `internal/manager/storage/postgres_store.go` and
  `internal/manager/storage/memory_store.go` provide a second persistence-layer
  guard for mailbox message creation.
- `integration/node_scoped_boundaries_integration_test.go` covers
  cross-tenant, cross-node, cross-agent, and cross-session boundaries against
  the Docker-backed manager and Postgres stack.
- `integration/paxd_container_integration_test.go` covers the Postgres-backed
  v1 node message path.

## Request Flow

For `/api/v1/user/:user_id/nodes/:node_id/agents/:agent_id/...`:

1. The handler treats route params as authoritative for node, agent, session,
   and message IDs.
2. The handler passes both `node_id` and `agent_id` into `userapi`.
3. `userapi` loads the visible node and visible agent for the principal.
4. `userapi` returns not found when `agent.node_id != node_id`.
5. Session-specific requests additionally load the visible session and require
   `session.agent_id == agent_id`.
6. If `session.node_id` is non-empty, it must equal the route `node_id`.

The empty `session.node_id` case is intentionally allowed for legacy session
rows that predate node-scoped sessions. Those rows remain constrained by the
session's agent, and the agent is still constrained to the route node.

## Persistence Flow

`CreateMailboxMessage` now:

1. Loads the target agent by `agent_id`, and by `node_id` when a node-scoped
   request provided one.
2. Verifies the principal can access the agent owner.
3. Verifies the target session exists for the same agent when `session_id` is
   present.
4. Rejects node-scoped requests when the session has a non-empty node ID that
   does not match the agent node.
5. Inserts `mailbox.node_id` from the agent's stored node ID.

This avoids cross-node mailbox pollution from a forged route `node_id`.

## Compatibility

Existing legacy session rows with empty `node_id` continue to work through
node-scoped session APIs when their agent belongs to the route node. Legacy
agent-only APIs are unchanged. Existing mailbox rows are not rewritten.

Node-scoped APIs will not expose sessions whose stored `node_id` conflicts with
the route node. That is intentional for tenant isolation.

## Verification

Commands run:

```bash
GOCACHE=/tmp/pax-manager-go-cache make fmt-check
GOCACHE=/tmp/pax-manager-go-cache make lint
GOCACHE=/tmp/pax-manager-go-cache go test -count=1 ./...
GOCACHE=/tmp/pax-manager-go-cache make integration-test
make integration-down
GOCACHE=/tmp/pax-manager-go-cache go build -o /tmp/pax-manager-build-check ./cmd/manager
```

The Docker-backed integration suite includes:

- cross tenant: another user cannot list or create messages under the owner's
  node/agent/session path.
- cross node: a body-provided correct node ID cannot override a wrong route
  node ID.
- cross agent: a body-provided correct agent ID cannot override a wrong route
  agent ID.
- cross session: a body-provided correct session ID cannot override a wrong
  route session ID.

`go build` exited successfully but printed a Go module stat cache warning
because the sandbox could not write under the user module cache.

## Risks

- Existing corrupt data with a non-empty session `node_id` that conflicts with
  the agent node is now hidden from node-scoped APIs.
- Existing legacy mailbox rows with empty `node_id` are not returned by
  node-scoped mailbox listing unless they are session-specific and reached
  through the session message path.
