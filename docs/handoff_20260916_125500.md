# Preserve text segments inside business turns

Issue 025 fixes tagged text keys that ignored historyGroupID. Turn identity is
an execution scope, not a message identity. Consecutive chunks share a group;
tool and terminal events end that group. The key now includes turn and group,
or the individual transport sequence if the group is unavailable. The normal
acp_tunnel dispatch already supplies historyGroupID. No schema changes apply.

Text rows set raw_json.text_layout to segment. The marker lets Console preserve
new row boundaries while supporting old whole-turn aggregates. It is not a
revision or a session discovery mechanism. Observer snapshots and history use
the same normalizer. Deploy Console first, then Manager, to recognize the new
layout before segmented rows are emitted. No deployment was performed here.

No historical backfill is attempted. Restoring exact boundaries in old merged
rows would require original frame evidence; concatenated text alone is not
sufficient. A turn spanning the rollout can contain both kinds of row; Console
preserves its stored order when segmented rows are present.

Verification uses gvm Go 1.26, full Go tests/build, fmt-check and lint; Console
uses Node 24, full Vitest, TypeScript and targeted ESLint. Existing repository
format/lint baseline failures are documented separately. The regression uses
the actual projection and batched persistence path, not hand-built row IDs.
Full Manager tests and build passed. Console: 521 tests passed, 2 skipped;
TypeScript and targeted ESLint passed. No generated code changes or regeneration
are required.
