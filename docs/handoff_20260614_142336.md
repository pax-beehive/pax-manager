# Handoff 20260614 142336

## Summary

This handoff covers the node-model API update and the local issue status
cleanup that followed it. The active domain model is now:

```text
user -> node -> agent -> session -> message
```

The new v1 API is node-scoped for both user-facing and paxd-facing flows. The
legacy agent and user routes remain for compatibility, but new work should use
the v1 node routes.

## API Shape

Primary node-facing routes:

- `POST /api/v1/node/register`
- `POST /api/v1/node/status`
- `GET /api/v1/node/mailbox`
- `GET /api/v1/node/agents/:agent_id/mailbox`
- `GET /api/v1/node/agents/:agent_id/sessions/:session_id/mailbox`
- `POST /api/v1/node/messages/offset`
- `POST /api/v1/node/messages/:message_id/result`
- `POST /api/v1/node/messages/:message_id/delivered`
- `POST /api/v1/node/messages/outbound`

Primary user-facing routes:

- `GET /api/v1/user/:user_id/me`
- `GET /api/v1/user/:user_id/nodes`
- `GET /api/v1/user/:user_id/nodes/:node_id`
- `GET /api/v1/user/:user_id/nodes/:node_id/agents`
- `POST /api/v1/user/:user_id/nodes/:node_id/agents`
- `GET /api/v1/user/:user_id/nodes/:node_id/agents/:agent_id/sessions`
- `POST /api/v1/user/:user_id/nodes/:node_id/agents/:agent_id/sessions`
- `GET /api/v1/user/:user_id/nodes/:node_id/agents/:agent_id/sessions/:session_id/messages`
- `POST /api/v1/user/:user_id/nodes/:node_id/agents/:agent_id/sessions/:session_id/messages`
- `GET /api/v1/user/:user_id/api-keys`
- `POST /api/v1/user/:user_id/api-keys`
- `DELETE /api/v1/user/:user_id/api-keys/:key_id`
- `GET /api/v1/user/:user_id/node-registration-tokens`
- `POST /api/v1/user/:user_id/node-registration-tokens`
- `DELETE /api/v1/user/:user_id/node-registration-tokens/:token_id`

All success responses use HTTP 200. Request problems use 4xx. Internal bugs or
data inconsistency use 500.

## Module Boundaries

- `api/pax_manager.thrift` is the API contract source of truth.
- `internal/manager/domain` owns domain models and store interfaces.
- `internal/manager/paxd` owns paxd-facing node behavior.
- `internal/manager/userapi` owns user-facing behavior.
- `internal/manager/storage` owns PostgreSQL and in-memory persistence.
- `internal/manager/auth` owns Cloudflare Access and key-based identity.
- `internal/manager/node_idl_handlers.go` contains thin v1 handlers that bind
  transport data and delegate to services.
- `internal/manager/openapi_generated.go` and
  `internal/manager/openapi_generated.json` are generated from the IDL by
  `cmd/openapi-gen`.

The Hertz scaffold is still present for the legacy generated route surface.
The v1 node routes are wired through the lightweight generated route file above,
not through `hz update`.

## Data Model

`db/init.sql` now includes the `nodes` table and node-aware foreign keys for
agents, sessions, mailbox messages, registration tokens, and message offsets.

Important storage behavior:

- Node registration authenticates with `X-Pax-Key`.
- User API requests authenticate with Cloudflare Access by default.
- Local test flows can disable Cloudflare Access through the existing
  development flag.
- Mailbox rows are scoped by user, node, agent, and session.
- Pulling mailbox messages marks pending messages delivered.
- Token usage now stores input, output, total, cache read, cache write,
  reasoning, estimated cost, and actual cost.

## Issue Status Changes

Resolved:

- ISSUE-001: v1 node API has outbound agent-to-user message reporting.
- ISSUE-002: v1 user API has explicit node-scoped session creation and
  first-message support.
- ISSUE-003: v1 node API has delivered status reporting and pull-time delivery
  marking.
- ISSUE-006: v1 user API has `GET /api/v1/user/:user_id/me`.
- ISSUE-008: token usage now matches the wider paxd reporting shape.

Partial:

- ISSUE-005: store-level user API key authentication updates `last_used_at`,
  but user-facing HTTP routes still use Cloudflare Access. A public user API
  key middleware has not been enabled.

Still open:

- ISSUE-004: legacy paxd HTTP register still expects an unwrapped response.
- ISSUE-007: legacy paxd HTTP mailbox fallback still expects an unwrapped array.

Those two issues should stay open until paxd migrates to the v1 node API or the
legacy HTTP fallback is intentionally changed.
