# Canonical session metadata lookup

## Scope and contract

ISSUE-053 adds GET /api/v1/user/:user_id/sessions/:session_id. The authenticated
self path works without knowing the session's node or agent. The response is the
existing AgentSession inside the normal data envelope, including agent_id,
node_id and existing history-head synchronization fields. Node/agent-scoped
session routes retain their current behavior.

The handwritten adapter delegates to userapi.Service.GetUserSession. Principal
resolution runs before storage access. The service then uses the existing
Store.GetSession direct lookup with its owner or explicit team access check.
Unrelated users and missing sessions receive the existing not-found response;
an explicit path cannot bypass the normal identity resolver. If a legacy
session has no node ID, GetAgent resolves it under the same principal. Finally,
fillSessionHistoryHead reads one latest-message metadata record through the
existing optional SessionHistorySyncStore capability.

No session list is fetched and no history window, message body or parts are
hydrated for this endpoint. There is no dependency on Elasticsearch or workspace
search/read, and no storage SQL/interface, database schema, index, worker or
permission model change. Offline agents remain resolvable through persisted
metadata. Archived-session behavior follows the existing direct session read.
