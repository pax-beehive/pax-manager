# Released Paxd Concurrent Session Rollout

## Summary

Structured ACP conversations now enable per-session concurrent turns for every
owner when the node reports a ready ACP pool. The previous owner-admin or
development-build rollout check was removed.

## Request Flow

`ACPTunnelAgent.concurrentTurnsReady` reads the agent runtime metadata persisted
from the node status snapshot. Concurrent turn admission is enabled only when:

- the runtime connection ID is present;
- the ACP pool capability report names the same connection;
- the report generation is positive; and
- the report initialization phase is `ready`.

Missing, stale, mismatched, or non-ready reports still fall back to agent-wide
structured admission. Legacy raw user tunnels remain single-claim.

## Authorization Audit

The removed admin check was a feature rollout gate, not an authorization
boundary. The remaining backend admin check allows an admin to mint a node
registration token for another user. It remains unchanged because it crosses
user ownership boundaries. Other forbidden responses enforce node, agent,
tenant, token, or artifact-uploader identity and also remain unchanged.

## Generated Artifacts

No generated artifacts changed. `make generate` is not required.

## Deployment Notes

Deploying pax-manager is sufficient. Existing connected agents keep their live
tunnel state until reconnect; reconnecting the agent tunnel guarantees the new
admission policy is used. No paxd upgrade or database migration is required.
