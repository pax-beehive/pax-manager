# Pax Manager observability

The first candidate was built from `5ee17dc`, the live revision at initial
preflight. Production was independently upgraded to `7390f51` during staging.
This worktree is based on `7390f51`. The original checkout remains on its own
revision and has an existing user change.

## Metric flow

- Manager starts a separate TLS listener when `PAX_METRICS_ADDR` is set.
  Configure `PAX_METRICS_PEER_IP`, `PAX_METRICS_TOKEN_FILE`,
  `PAX_METRICS_CERT_FILE`, and `PAX_METRICS_KEY_FILE` with it. The listener
  checks the TCP peer address and Bearer token before exposing metrics.
- Hertz records completed requests, status, and handler duration in memory.
  Route labels are registered templates. Unmatched requests use a shared
  label. SSE and WebSocket connections are excluded from the latency histogram.
- The internal `/metrics` listener does not use generated API routes. No
  generated artifacts or database schema changes are required.
- In production, publish container port `9109` only on `192.168.0.101`.
  Prometheus on `192.168.0.100` authenticates over HTTPS. Compose on
  `home_server` uses a dedicated bridge because its default Docker pools are
  exhausted. Grafana listens on `127.0.0.1:3030` and Butler uses `3000`.
- Agent first response, turn duration, and device connection metrics are
  follow-up signals. This phase measures HTTP requests and process health.

## Deployment and verification

See [the monitoring Compose instructions](../deploy/observability/README.md).
The running project is under `~/pax_workspace/pax-observability` on
`home_server`. Credentials are under `~/.config/pax-observability`. The Manager
server certificate, private key, and token are in the protected
`~/pax_workspace/.secrets/pax-metrics` directory on `home_dev`. Only mount
the three files the listener needs, never the signing key. Renew the server
certificate before its one-year expiry and recreate the Manager container.

- Go 1.26 with `GOWORK=off` passed `make fmt-check` and
  `go test -count=1 ./...`. The Linux amd64 image
  `pax-manager-manager:7390f51-metrics-466f563924e6` is staged on `home_dev`.
- `promtool check config` passed on `home_server`. Grafana health, dashboard
  provisioning, and a real Prometheus query via Grafana passed on port 3030.
- Isolated Manager candidates at both revisions used in-memory storage.
  Health returned HTTP 200, tokenless scrapes returned HTTP 401, and
  authenticated scrapes returned the API counters over the LAN. Both
  candidates were stopped after verification. The production container was
  not switched because automatic approval requires explicit authorization for
  the interruption.
- On explicit production rollout approval, use the operations runbook on
  `home_dev` to preserve the previous Manager container, networks, mount
  configuration, and authentication. Use the staged image recorded at
  `~/pax_workspace/.deployment-candidates/observability-20261120-7390f51/image-tag`.
  Verify origin and public API health as well as a production Prometheus scrape.
  Update the remote runbook and carry the metrics port, mounts, and environment
  into the next Manager release. Recheck the serving image revision immediately
  before the switch.
